# 个人信息与资料空间

## 一、资料空间与读取边界

```text
<root>/
├── README.md
├── 个人全景档案.md
├── 待确认信息.md
├── 访谈进度.md
├── 资料索引.md
├── 迭代日志.md
├── 原始访谈/<year>/<session-id>/<turn-id>.md
├── 历史版本/
├── .backups/
├── .trash/
└── .hello-state
```

`个人全景档案.md` 是唯一权威综合资料。`待确认信息.md` 不是权威背景。普通任务默认只读取 `README.md` 与 `个人全景档案.md`；继续访谈时再读取 `访谈进度.md`；核验来源时才定位读取相关原始轮次、资料索引或历史版本，禁止默认加载整个访谈历史。

一个正式访谈轮次对应一个不可变原始文件。不要把多年访谈继续追加到单个巨型 Markdown。需要会话级或年度视图时，把它视为可重新生成的派生索引，不作为事实源。

## 二、状态模型

`.hello-state` 只存控制状态，不存个人内容。schema 2 的字段见存储协议，其中：

- `profile_version` 只跟踪经用户确认的权威档案更新。
- `progress_version` 跟踪访谈轮次与进度更新。
- `last_session_id + last_turn_id` 提供轮次幂等。
- `last_interview_at` 记录最近一次正式访谈轮次写入时间；`status` 缺少进度文件元数据时可用它恢复显示。
- `review_stage` 只能通过显式 `configure` 改变。
- 新空间的 `capture_mode` 默认为 `prompt`。

schema 1 可以继续读取，下一次受控写入迁移；不得为升级而修改真实资料内容。

## 三、信息类型

| 类型 | 定义 | 处理 |
|---|---|---|
| 用户事实陈述 | 用户确认发生过或当前成立的事情 | 记录来源和确认时间；不等于外部核验 |
| 外部证据事实 | 有用户授权材料支持的事实 | 记录证据位置，不复制不必要的敏感原件 |
| 原始记忆与叙述 | 用户对经历的回忆 | 保留语境，不强行改写为客观事实 |
| 用户自我理解 | 用户对能力、性格、动机和经历的解释 | 标明为本人判断 |
| AI 假设 | AI 提出的模式、矛盾或可能性 | 单列，确认前不得升级 |
| 未知或冲突 | 缺失、模糊或版本不一致 | 并列保留，不擅自选择 |

重要信息尽量区分事件时间、状态有效期、讲述或确认时间、整理写入时间。旧状态被替代时说明失效时间和去向，不静默抹除历史。

## 四、权威档案

主档案必须能独立说明用途、隐私边界、时间边界、可信度和使用限制，并保留以下章节：当前起点；人生时间线与关键经历；能力、经验与证据；知识、认知与学习方式；健康、精力与可持续边界；经济、资源与风险承受能力；关系、支持网络与现实责任；习惯、行动与决策方式；价值观、世界观与人生愿景；当前目标与未来设想；AI 协作偏好；未知、冲突与 AI 假设；主要来源。

如果只能提供一个文件，提供主档案。不要把体积较大的访谈进度或原始记录当成默认上下文。

## 五、候选、进度与日志

候选至少包含唯一编号、暂存时间、类型、来源、摘要和待确认状态。审核结果只能是已归档、继续追问、推迟、合并、忽略或撤回。

候选类型还应区分“长期个人背景”和“当前任务参数”。市场扫描字段、研究顺序、项目验收条件等任务参数默认不进入个人背景候选；只有用户确认其跨任务长期有效时，才按稳定偏好或约束处理。

`访谈进度.md` 只保存恢复访谈所需的最小状态：进度版本、已覆盖主题、待补充主题、暂不收集主题和下一问题。不复制整段问答、完整事实清单或权威档案内容。

权威更新类型固定为新增、状态变化、事实纠正、解释变化、假设验证、撤回隐藏。每次更新日志记录版本、时间、触发原因、来源、更新类型、位置、摘要、确认状态和工具标识，不重复保存敏感原文。

除主结构外的专题快照（例如经济快照）只有在存在明确任务、独立维护者和读取场景时才建立；否则把相关信息保留在主档案对应章节，避免多个权威副本。
