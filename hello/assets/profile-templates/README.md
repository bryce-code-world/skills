# 个人资料空间

> 本目录保存本地私密个人资料。未经本人明确同意，不得上传、公开或向无关任务披露。

## 资料包职责

最终资料空间是一个分层目录，而不是把一个人的全部内容塞进单一文件。当前存在两种不能混用的布局：

- **兼容 schema 2**：根级 `个人全景档案.md` 仍是唯一的权威综合档案；其中的速览层是优先读取区，正文是同一权威档案的备查区，不是另一个聚合副本。
- **目标包（正式运行布局）**：`个人全景档案.md` 降级为由 `权威/` 条目生成的聚合索引、固定速览和主题导航；`权威/` 保存带稳定 ID 的声明、事件、决策和未知/冲突。旧 schema 2 仅作为一次性迁移输入，不是目标包的日常运行模式。
- 两种布局都把 `原始访谈/` 作为不可变来源、`待确认信息.md` 作为尚未确认的候选；目标包另有可重建的 `派生/` 自传、AI 背景包和克隆底座。
- 目标包由 `主题覆盖矩阵.md` 保存主题注册表与覆盖状态；兼容 schema 2 暂以 `访谈进度.md` 的基线/长期分组承载覆盖进度。两种布局都使用 `.hello-state` 和 `迭代日志.md` 保存版本与审计状态。

当前兼容模板仍包含旧版单文件正文，供一次性迁移读取。新建目标包和 v21 迁移使用 [个人资料包架构契约](../../references/profile-architecture.md) 规定的目录，不能把目标包的聚合 owner 语义倒推到旧来源。

## 默认读取顺序

1. [个人全景档案](./个人全景档案.md) 的“速览层”（当前处境、核心约束、主要能力模式、下一步待确认）和主题导航。
2. 目标包按任务读取相关 `权威/声明`、`权威/事件`、`权威/决策`；兼容 schema 2 包只有在确需详细依据时才读取同一权威文件的正文备查层。
3. 只有继续访谈时才读取[访谈进度](./访谈进度.md)和未处理候选数量。
4. 只有核验来源或理解变化过程时，再读取[资料索引](./资料索引.md)、[迭代日志](./迭代日志.md)、`原始访谈/`、`历史版本/` 和相关派生视图。

[待确认信息](./待确认信息.md)不是权威个人背景，只在候选审核闸门中逐条读取。

## 布局判定与当前适配器边界

`target-package/` 是 Skill 内的设计样板，不是资料空间根目录。样板中的 `target-draft` 文字只用于说明目标布局，**不是运行时 marker**；样板不提供根级 `.hello-state` 或 manifest。真实目标实例必须由目标协议创建并由三套适配器按 marker 分支处理；不能依靠目录是否存在来推断布局，也不能把目标包交给旧版单文件 `apply`。

## 存量档案迁移（需用户确认）

对已有 v21《个人全景档案》只做一次性旁路迁移：先复制到隔离临时目录，按正文内容提取速览、主题声明、事件、决策和下一步待确认，逐条保留原章节来源标注；不改写、不删除、不合并原正文。向用户展示映射、速览草稿和差异，取得明确确认后，由目标协议写入新版目录并生成历史快照和迭代日志；旧正文此后只作为不可变来源和回退依据。未确认或抽不出可靠结论时保持来源不变。

## 使用边界

- 兼容 schema 2 中，根级 `个人全景档案.md` 是唯一权威综合文件；目标包中，它才是由 `权威/` 条目生成的唯一导航入口，详细事实的唯一 owner 在稳定 ID 条目中。同一结论不能有多个事实副本。
- 事实、本人理解、AI 假设、未知和冲突必须分开，并带来源、时间、敏感级别和允许用途。
- 只使用当前任务必要的个人信息。
- 资料发生变化时记录来源、时间、版本、替代关系和确认状态。
- 产出物会离开本地时，先执行 `context-contract.md` 的最小上下文协议，不整篇搬运权威资料。
