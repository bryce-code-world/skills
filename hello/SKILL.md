# 你好

让 AI 逐步认识用户，也帮助用户借助 AI 更准确地认识自己。维护一个分层、可追溯、可移植的个人资料包，不生成固定人格结论。

当前 `hello` 0.6.x 的正式运行只面向 schema 3 目录化资料包；Python、PowerShell、POSIX Shell 三套适配器按 [target-protocol.md](references/target-protocol.md) 保持同一语义。schema 1/2 仅作为一次性迁移输入和历史快照，不再作为日常双读或写入分支。迁移草稿中的条目仍须用户逐条确认，不能因切换布局而自动成为已确认事实。跨普通会话的自动发现仍依赖宿主逐轮 Hook；没有 Hook 时，只在本 Skill 被调用的会话内处理。

## 触发边界（供宿主规则直接引用）

命中场景：用户在普通会话中出现任何与本人有关的表达，宿主先把它作为 `Signal` 进行候选判定；其中稳定偏好、现实变化、经历、能力证据、自我认识、价值观、目标、关系或约束，且对未来多个会话有价值或会实质改变已有个人背景的，进入 `Candidate` 流程。已有个人资料空间且当前任务需要个人背景时，也视为命中。命中后分两支：普通会话信号先保持当前任务节奏，在自然停顿处按“会话发现”形成候选；需要个人背景的任务先判断产出物去向，远端、非私密或公开任务先执行 [context-contract.md](references/context-contract.md)，再运行 `status`、完成知情披露和“生成上下文”分支，最后按最小范围读取并产出任务。检测面与落盘面分离：一次性情绪、临时偏好、任务参数或用户拒绝的信号可以被识别和解释，但不得因此自动写入收件箱或权威层。未命中场景：普通问候、主要描述第三方且对本人无可识别的长期影响/关系责任，或与未来协作无明显关系的生活碎片。若第三方信息反映用户本人的角色、责任、边界、价值取舍或现实变化，仍按 Signal 处理，并只保留理解本人所需的最小关系摘要。未命中时静默退出，不读取个人资料、不启动访谈、不暂存候选。

没有宿主逐轮 Hook 时，不把“安装后自动发现”理解为后台扫描或隐式读取其他会话；应在可观察范围内诚实报告能力边界。

资料架构、`Signal → Candidate → Claim` 生命周期、目标目录和前人模型映射见 [profile-architecture.md](references/profile-architecture.md)。《个人全景档案》在正式目标包中是聚合索引、固定速览和导航入口，详细权威内容按声明、事件和决策拆分；旧单文件只在一次性迁移输入/历史快照中保留。

## 守住边界

按以下优先级执行：

1. 用户对自己的资料、存储位置和使用方式拥有最终决定权。
2. 区分事实陈述、原始记忆、本人理解、外部证据、AI 假设和未知冲突。
3. 区分过去、现在、未来和确认时间。
4. 只使用当前任务必要的个人信息，不主动暴露无关敏感背景。
5. 不进行心理诊断，不把单次表达固化为人格，不逼问敏感经历。
6. 不记录密码、验证码、私钥、完整证件号、支付凭据或精确家庭住址。
7. 未经逐条确认，不把普通会话的候选信息写入《个人全景档案》。
8. 不把个人资料发送给外部服务；确有必要时逐次说明范围并取得同意。

读取或处理高敏感、第三方、撤回和外部处理问题时，先读取 [privacy-rules.md](references/privacy-rules.md)。

需要选择资料层、稳定 ID、候选状态、覆盖状态、迁移路径或派生视图时，先读取 [profile-architecture.md](references/profile-architecture.md)，不要把聚合索引、派生文档或候选收件箱当成互相独立的事实源。

## 维护版本与依赖

每次触发时读取 [dependencies.md](references/dependencies.md)，按其中的 24 小时规则执行非阻塞更新检查。

更新检查失败或发现新版本时继续当前任务，只在交付时报告。更新 Skill 仍需用户确认，任何更新都不能移动、覆盖或删除个人资料。

## 识别工作模式

每次只选择一种主要档案操作模式：

| 模式 | 适用情况 |
|---|---|
| 建立基线 | 用户首次建立个人背景 |
| 继续访谈 | 从上次中断主题继续 |
| 增量回访 | 一个月、季度或重大事件后的变化回顾 |
| 审核候选 | 集中处理按采集策略进入待确认区的信息 |
| 修正与撤回 | 纠正、失效、隐藏或删除旧信息 |
| 生成上下文 | 为新 AI 或具体任务生成最小必要背景 |

普通会话还可以触发“会话发现”辅助模式。先完成当前任务，再暂存候选；不要强行切换成正式访谈。

## 解析个人资料目录

个人资料不保存在 Skill 目录。

**资料读取总闸门（强制）**：在解析根目录内容、读取任何个人资料文件或运行会读取资料的命令前，先判断当前任务的产出物去向。若产出物会离开本地（提交远端、写入非私密目录或对外发布），必须先读取并执行 [context-contract.md](references/context-contract.md)，列出最小读取范围、抽象化方式和敏感排除；协议完成前不得读取整篇《个人全景档案》或整套 `权威/`。为核对主体，目标包允许宿主注入或读取只含身份/布局/版本的 metadata-only manifest；这不算个人资料内容读取。若宿主不能提供 metadata-only 状态，应先暂停或转入用户明确授权的本地受控分支。本地私密任务也只能在授权档位内按需读取。

按以下顺序解析根目录：

1. 用户本次明确指定的目录。
2. 只读探针在没有显式目录时才可使用环境变量 `HELLO_HOME`。
3. 都没有时，说明尚未配置并询问用户；不要自行选择目录。

任何会改变资料空间的命令（包括 `init`、`configure`、`record-disclosure`、`stage`、`apply`、`record-turn`、`withdraw`、`recover`、`migrate-apply`、`rebuild-index`、`switch-layout` 和 `rollback-layout`）都必须显式带 `--root <已授权目录>`；不能让它们回退到 `HELLO_HOME`。显式的空字符串或全空白 root 也必须失败关闭，不能解析为当前目录或空白命名目录。这样可防止审查探针、包装器或丢失参数时误写另一份资料。测试和审查命令必须始终传入隔离临时根。

路径不存在时，先展示准确路径和将创建的结构，获得确认后再初始化。只读取用户授权的现有资料，不扫描其他目录。若根级 `.hello-state` 或 manifest 明确标记 `layout=target-draft|target`，必须先读 [target-protocol.md](references/target-protocol.md)：`target-draft` 只能运行只读校验、迁移计划或经确认的迁移应用；`target` 根只能由目标协议的入口处理，不得把它交给只懂 schema 2 的旧适配器。目标样板中的 `target-draft` 文字仍只是说明，不是运行时 marker，不能靠目录存在推断布局。

读取或修改资料前，读取 [information-model.md](references/information-model.md)。正式运行只使用新版目录化资料包；旧 schema 仅在一次性迁移读取时适用。

运行 `status` 或其他会读取资料的命令前，再次核对上述产出物去向和授权档位；远端分支必须已经完成 `context-contract.md` 的范围确认。

在本地私密分支（远端、非私密或公开产出已先完成上方读取总闸门）中，隐式发现已经分类为 `Candidate`/需要持久化，或继续访谈前，先运行只读 `status`，以实际状态为准识别当前采集策略、维护阶段、待确认数量、最后轮次和下一问题。已有空间即使不是新空间，也必须向用户说明当前有效的 `capture_mode`；不得把“新空间默认 prompt”误当成已有空间的配置。

这是进入 `Candidate`/持久化流程和继续访谈的强制前置检查，不得省略：读取 `status` 后向用户披露输出中的 `capture_mode`、当前采集策略，以及 `last_capture_disclosed_at` 所记录的上次知情审计时间；用户确认理解后调用 `record-disclosure --capture-mode <当前模式> --confirmed --root <已授权目录>`，再决定是否形成候选或读取更多个人资料。仅停留在会话内的纯 `Signal` 不进入此门禁，也不得借此读取个人资料。记录为空、是否过期由宿主按会话、设备、策略版本、用户记忆和约定时限判定；当前适配器只保存审计时间，不自行假定 TTL。并发披露或策略变更发生冲突时停写、重新读取 `status`，不得让旧回执覆盖新策略。不确定时暂停暂存并改回 `prompt` 或 `explicit`。该命令只记录已展示的策略，不改变策略或资料版本。

这是宿主层的知情门禁。当前三套适配器的 `stage` 除 `--confirmed` 外，在非 `explicit` 模式还会校验 `last_capture_disclosed_at` 是合法 ISO 8601 UTC 时间，且 `last_capture_disclosed_mode` 与当前 `capture_mode` 匹配；`explicit` 模式不要求披露回执。适配器仍无法验证用户实际看到策略或披露是否已过期，未完成宿主披露时不得调用 `stage`，不能把脚本成功当成知情证明。远端任务若没有 metadata-only 状态来源，也不能把兼容 `status` 的受控全量校验当作已满足最小读取协议。

## 执行首次访谈

读取 [interview-method.md](references/interview-method.md)，然后：

1. 确认建档目的、根目录、资料授权范围、敏感边界和撤回方式。
2. **固定候选消化闸门**：先展示未处理候选并询问处置，逐条让用户接受、修正、合并、追问、推迟或拒绝；用户可以明确选择“本次跳过”，但候选仍保持 pending、不得当作事实，且下次入口要再次提示。明确跳过后可继续本轮正式访谈。
3. 询问用户如何把人生划分为若干章节，先建立时间骨架。
4. 一次只问一个核心问题，根据回答追问事件、条件、选择、结果和理解变化；需要时分别形成 `Event` 或 `Decision`。
5. 每个主题结束后分别汇总已确认事实、本人理解、未知冲突和 AI 假设，并更新新版 `主题覆盖矩阵.md`；旧 `访谈进度.md` 只作为迁移来源或兼容快照保留。
6. 正式资料一律先用目标协议校验布局和来源，再通过目标实体/索引事务更新；不得把旧单文件 `diff`/`apply` 当作日常写入。`migrate-apply`/`rebuild-index` 只负责一次性迁移提升与索引，不把草稿条目自动确认。
7. 每轮回答整理完后，在目标包中保存不可变原始轮次、schema 3 恢复游标、候选处置和索引变更；目标协议校验失败或发现未完成事务时先停止并恢复，不得声称已落盘。
8. 高敏感内容由用户决定保存结构化问答、影响摘要或不落盘。
9. 基线达到完成标准并经用户确认后，用一次 `configure --review-stage first-review --next-review-at <一个月后> --confirmed --root <已授权目录>` 显式完成基线；普通 `apply` 不改变维护阶段。

目标包草稿边界（强制）：在用户确认切换前，待确认的声明、事件、决策和聚合索引草稿只能保留在当前会话、系统临时目录，或用户确认的隔离旁路根；不得写入 canonical root 或覆盖旧历史快照。用户确认后也必须先通过目标协议的版本护栏；切换只改变活动布局，不把 `draft` 条目静默升级为 `confirmed`。迁移失败可回退到旧快照，临时草稿在拒绝后清理并核验。旁路迁移目录在切换后只作审计证据，不是第二个访谈入口。

访谈要设置轻量预算：连续同一主题达到约 6—8 轮，或用户表现出疲惫、重复回答、开始设计具体项目方案时，先做阶段总结并询问继续、暂停、转任务文档或暂不收集。不要用“还有一个问题”无限延长基线。项目方法、行业扫描和具体执行参数默认留在当前任务；只有稳定、跨任务仍有价值的个人约束或偏好，经用户确认后才进入个人档案候选。

`status` 返回的 `baseline_required_remaining` 是新版主题矩阵中的基线必答项；数组非空时 `baseline_closure_blocked` 必须为 `true`，`long_term_backlog` 中的可长期补充项不阻塞基线收口。`baseline_split_unknown=true` 时表示矩阵无法判定，`legacy-unclassified` 占位项会强制阻塞。基线完成后先让用户确认，再显式 `configure --review-stage first-review --next-review-at <时间> --confirmed --root <已授权目录>`。

用户疲惫、不适或要求暂停时，保存已确认进度后结束，不为完成主题清单继续追问。

## 处理会话发现

只有信息主体是用户、对未来多个会话仍有价值，并且相对已有资料存在新增、变化、纠正、新证据或新解释时，才形成候选。主要描述第三方且不反映用户本人的长期影响、角色、责任、边界或价值取舍时不形成候选；若反映这些本人信息，仍先作为 `Signal`，并最小化第三方细节。先把会话中的信号视为 `Signal`，分类后才进入 `Candidate`；用户确认后才成为权威 `Claim`、`Event` 或 `Decision`。

新资料空间默认采用“提示确认”。只有用户已明确选择“自动暂存”时，才把该选择作为对 `stage` 的持续授权。执行顺序是：

1. 先完成当前主要任务。
2. **强制前置检查**：先读取 `status`，并向用户披露当前 `capture_mode`、当前采集策略和 `last_capture_disclosed_at` 所表示的上次知情审计时间；用户确认理解后调用 `record-disclosure --capture-mode <当前模式> --confirmed --root <已授权目录>`，披露完成前不得暂存。披露是否过期由宿主按会话、设备、策略版本、用户记忆和约定时限判定，策略变更或并发冲突时必须重新读取并停写。`prompt` 模式先简短询问是否暂存；历史 `auto-stage` 模式必须建议改为 `prompt`，但不静默改写既有设置：用户明确选择改为 `prompt` 后才运行 `configure --capture-mode prompt --confirmed --root <资料根目录>`；用户明确选择继续 `auto-stage` 且完成本次披露时，才按既有持续授权暂存；用户未选择、表示不记得或拒绝继续时，保持原设置但暂停新的隐式暂存；`explicit` 模式只响应明确保存指令。
3. 获得本次或持续授权后，将候选摘要、来源、时间和类型写入 `待确认信息.md`。
4. 为候选保留来源会话、主题、敏感级别、有效时间、用途范围和处置状态。暂存不代表确认。
5. 不在当前会话展开正式访谈，除非信息缺失会导致严重失真或属于需要立即处理的重大事件。
6. 在每周、每月或用户指定的审核周期集中处理；下一次正式访谈入口仍先消化未处理候选。

`auto-stage` 只授权合格候选进入待确认区，不授权更新权威档案、读取其他目录或外部处理资料。历史 `auto-stage` 不因“新空间默认 prompt”而自动转换；用户不记得或没有明确选择继续时，先暂停暂存并允许改回 `prompt` 或 `explicit`。

临时情绪、随口偏好和任务专用参数不暂存。普通“hello”或“你好”问候不触发本 Skill。

用户可以把采集策略改为“自动暂存”“提示确认”或“仅显式”。任何策略都不授权更新权威档案。

修改采集策略、下次回访时间或维护阶段时，使用 `configure`，不手工编辑 `.hello-state`。

完成 `status` 披露并得到用户理解确认后，使用 `record-disclosure --capture-mode <当前模式> --confirmed --root <已授权目录>` 记录本次知情时间；它不改变采集策略、资料版本或访谈进度。

正式访谈跨自然日、跨设备、超过 50 轮或用户明确结束时，会话终止；适配器只可检查其能看到的轮次/日期，跨设备和显式结束依赖宿主传入。自然日目前按 UTC 日期判定，用户本地时区边界尚待验证。`record-turn` 保存当前轮次后若返回 `new_session_required`，立即提示用户开启新会话，下一轮不得复用原 `session-id`。

## 审核与更新

审核候选或执行增量回访时：

1. 读取当前版本、最近确认时间、访谈进度和待确认信息。
2. 逐条判断重复性、长期价值、敏感性和信息缺口，先处理收件箱候选。
3. 信息不足时一次只追问一个关键细节。
4. 把变化分类为新增、状态变化、事实纠正、解释变化、假设验证或撤回隐藏，并决定它属于声明、事件还是决策。
5. 先运行 `target-validate` 和目标协议的来源/版本检查；确认后用目标事务更新实体和聚合索引，不能把旧 `diff`/`apply` 当作目标实体写入。
6. 展示差异、来源、变更类型和影响，等待用户确认。
7. 使用目标协议的预期版本和迁移 ID，写后运行 freshness/双读校验，仍保留每条条目的确认状态，不能把草稿当成已确认事实。
8. 将每条候选标记为已归档、继续追问、推迟、合并、忽略或撤回；不要批量自动转正。

旧 schema 的 `diff`/`apply` 只在一次性迁移输入中使用；正式资料的迁移、索引、切换和回退必须走三套适配器共同实现的 [target-protocol.md](references/target-protocol.md)。目标实体确认/撤回按该协议的冻结范围执行，未提供的动作必须明确失败，不得回退写旧单文件。

提问默认先开放后澄清：让用户先用自己的语言定义问题；只有用户表示不清楚、无法展开或要求比较时，才提供少量选项。选项必须标明是 AI 提供的探索框架，不得把用户选择 AI 选项当作用户原始概念。涉及具体项目、研究流程或商业方案时，先判断是否应转入任务文档，避免把任务参数伪装成长期个人特征。

重大健康、工作、家庭、关系或经济事件可以随时触发专项回访，不等待固定周期。

## 执行确定性存储操作

读取 [profile-store-contract.md](references/profile-store-contract.md)，按当前系统选择：

- Windows：优先使用 `scripts/profile_store.ps1`，支持 Windows PowerShell 5.1 及以上。
- Linux、macOS：优先使用 `scripts/profile_store.sh`，使用 POSIX `sh` 和系统基础工具。
- 原生适配器不可用时：尝试 Python 3.8 及以上的 `scripts/profile_store.py`。
- 都不可用时：按存储协议使用 Agent 的安全文件工具；没有安全工具时停止持久化。

所有修改命令都要求 `--confirmed`。该参数只防误调用，不能替代用户确认。更新权威档案必须使用 `--expected-version`；记录访谈轮次必须使用 `--expected-progress-version`、稳定的 `session-id` 和 `turn-id`。版本冲突时重新读取，未完成事务时先运行 `recover`。候选临时文件和成功事务的恢复副本在成功 `stage`、`apply` 或 `record-turn` 后清理；失败时保留到确认恢复完成。适配器输出必须是 UTF-8 JSON，不能依赖 Windows 默认代码页。

基本调用：

```text
Windows:
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/profile_store.ps1 resolve-root --root <path>

Linux / macOS:
sh scripts/profile_store.sh resolve-root --root <path>
```

## 生成协作上下文

生成上下文时先执行上述读取总闸门：先判断产出物去向；远端、非私密或公开产出物必须在读取任何个人资料前按 [context-contract.md](references/context-contract.md) 列出读取范围、抽象化和敏感排除，完成 `status` 披露及 `record-disclosure` 后再按清单读取；不得直接读取整篇《个人全景档案》或整套 `权威/`。

协议完成后，新 AI 的默认读取顺序是资料空间中的 `README.md`、`个人全景档案.md` 的速览层和主题导航。目标目录中需要详细依据时，再按导航读取相关 `权威/声明`、`权威/事件`、`权威/决策`；只有继续访谈时才额外读取 `访谈进度.md`；只有核验来源或理解变化过程时，才定位读取相关原始轮次、资料索引和历史版本。当前兼容目录仍可把同一权威文件的旧单文件正文作为备查层，但不应默认整篇加载。所有具体任务生成上下文都只选与任务相关的事实、资源、约束、目标和协作偏好；不修改权威资料，不附带无关敏感信息。抽不出可靠结论时标为未知/待确认并请求是否扩大范围。

## 验收

交付前检查：

1. 是否正确选择模式并保持当前主要任务。
2. 是否区分信息类型、时间和确认状态。
3. 是否只读取和写入授权目录。
4. 是否把隐式发现限制在待确认区。
5. 是否在权威更新前展示差异并获得确认。
6. 是否使用预期版本、快照、日志和写后校验。
7. 是否允许用户跳过、纠正、撤回和删除。
8. 是否避免诊断、固定标签、诱导问题和无关敏感披露。
9. 是否在长主题达到检查点时主动收束、暂停或转为任务文档。
10. 是否按实际 `status` 告知已有空间的采集策略，并确认任务参数没有被写成长期个人背景。
