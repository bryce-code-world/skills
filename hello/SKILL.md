# 你好

让 AI 逐步认识用户，也帮助用户借助 AI 更准确地认识自己。维护可修正的长期协作背景，不生成固定人格结论。

## 守住边界

按以下优先级执行：

1. 用户对自己的资料、存储位置和使用方式拥有最终决定权。
2. 区分事实陈述、原始记忆、本人理解、外部证据、AI 假设和未知冲突。
3. 区分过去、现在、未来和确认时间。
4. 只使用当前任务必要的个人信息，不主动暴露无关敏感背景。
5. 不进行心理诊断，不把单次表达固化为人格，不逼问敏感经历。
6. 不记录密码、验证码、私钥、完整证件号、支付凭据或精确家庭住址。
7. 未经逐条确认，不把普通会话的候选信息写入《个人全景档案》。
8. 不把个人资料发送给外部服务；确有必要时逐次说明范围并取得同意。

读取或处理高敏感、第三方、撤回和外部处理问题时，先读取 [privacy-rules.md](references/privacy-rules.md)。

## 维护版本与依赖

每次触发时读取 [dependencies.md](references/dependencies.md)，按其中的 24 小时规则执行非阻塞更新检查。

更新检查失败或发现新版本时继续当前任务，只在交付时报告。更新 Skill 仍需用户确认，任何更新都不能移动、覆盖或删除个人资料。

## 识别工作模式

每次只选择一种主要档案操作模式：

| 模式 | 适用情况 |
|---|---|
| 建立基线 | 用户首次建立个人背景 |
| 继续访谈 | 从上次中断主题继续 |
| 增量回访 | 一个月、季度或重大事件后的变化回顾 |
| 审核候选 | 集中处理自动暂存的信息 |
| 修正与撤回 | 纠正、失效、隐藏或删除旧信息 |
| 生成上下文 | 为新 AI 或具体任务生成最小必要背景 |

普通会话还可以触发“会话发现”辅助模式。先完成当前任务，再暂存候选；不要强行切换成正式访谈。

## 解析个人资料目录

个人资料不保存在 Skill 目录。

按以下顺序解析根目录：

1. 用户本次明确指定的目录。
2. 环境变量 `HELLO_HOME`。
3. 都没有时，说明尚未配置并询问用户；不要自行选择目录。

路径不存在时，先展示准确路径和将创建的结构，获得确认后再初始化。只读取用户授权的现有资料，不扫描其他目录。

读取或修改资料前，读取 [information-model.md](references/information-model.md)。

## 执行首次访谈

读取 [interview-method.md](references/interview-method.md)，然后：

1. 确认建档目的、根目录、资料授权范围、敏感边界和撤回方式。
2. 询问用户如何把人生划分为若干章节，先建立时间骨架。
3. 一次只问一个核心问题，根据回答追问事件、条件、选择、结果和理解变化。
4. 每个主题结束后分别汇总已确认事实、本人理解、未知冲突和 AI 假设。
5. 用户确认后才生成《个人全景档案》的候选差异并应用。
6. 每轮回答整理完后，先生成该轮记录和新的完整《访谈进度》，用 `record-turn` 原子写入；落盘成功后再问下一题。
7. 高敏感内容由用户决定保存结构化问答、影响摘要或不落盘。
8. 基线达到完成标准并经用户确认后，用一次 `configure --review-stage first-review --next-review-at <一个月后>` 显式完成基线；普通 `apply` 不改变维护阶段。

用户疲惫、不适或要求暂停时，保存已确认进度后结束，不为完成主题清单继续追问。

## 处理会话发现

只有信息主体是用户、对未来多个会话仍有价值，并且相对已有资料存在新增、变化、纠正、新证据或新解释时，才形成候选。

新资料空间默认采用“提示确认”。只有用户已明确选择“自动暂存”时，才把该选择作为对 `stage` 的持续授权。执行顺序是：

1. 先完成当前主要任务。
2. `prompt` 模式先简短询问是否暂存；`auto-stage` 模式直接暂存；`explicit` 模式只响应明确保存指令。
3. 获得本次或持续授权后，将候选摘要、来源、时间和类型写入 `待确认信息.md`。
4. 不在当前会话展开访谈，除非信息缺失会导致严重失真或属于需要立即处理的重大事件。
5. 在每周、每月或用户指定的审核周期集中处理。

临时情绪、随口偏好和任务专用参数不暂存。普通“hello”或“你好”问候不触发本 Skill。

用户可以把采集策略改为“自动暂存”“提示确认”或“仅显式”。任何策略都不授权更新权威档案。

修改采集策略、下次回访时间或维护阶段时，使用 `configure`，不手工编辑 `.hello-state`。

## 审核与更新

审核候选或执行增量回访时：

1. 读取当前版本、最近确认时间、访谈进度和待确认信息。
2. 逐条判断重复性、长期价值、敏感性和信息缺口。
3. 信息不足时一次只追问一个关键细节。
4. 把变化分类为新增、状态变化、事实纠正、解释变化、假设验证或撤回隐藏。
5. 生成完整候选档案并先运行 `diff`。
6. 展示差异、来源、变更类型和影响，等待用户确认。
7. 确认后使用当前预期版本运行 `apply`，再校验结果。
8. 将每条候选标记为已归档、继续追问、推迟、合并、忽略或撤回；不要批量自动转正。

重大健康、工作、家庭、关系或经济事件可以随时触发专项回访，不等待固定周期。

## 执行确定性存储操作

读取 [profile-store-contract.md](references/profile-store-contract.md)，按当前系统选择：

- Windows：优先使用 `scripts/profile_store.ps1`，支持 Windows PowerShell 5.1 及以上。
- Linux、macOS：优先使用 `scripts/profile_store.sh`，使用 POSIX `sh` 和系统基础工具。
- 原生适配器不可用时：尝试 Python 3.8 及以上的 `scripts/profile_store.py`。
- 都不可用时：按存储协议使用 Agent 的安全文件工具；没有安全工具时停止持久化。

所有修改命令都要求 `--confirmed`。该参数只防误调用，不能替代用户确认。更新权威档案必须使用 `--expected-version`；记录访谈轮次必须使用 `--expected-progress-version`、稳定的 `session-id` 和 `turn-id`。版本冲突时重新读取，未完成事务时先运行 `recover`。候选临时文件在成功 `stage`、`apply` 或 `record-turn` 后清理；失败时保留到确认恢复完成。

基本调用：

```text
Windows:
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/profile_store.ps1 resolve-root --root <path>

Linux / macOS:
sh scripts/profile_store.sh resolve-root --root <path>
```

## 生成协作上下文

新 AI 的默认读取顺序是资料空间中的 `README.md` 和 `个人全景档案.md`。只有继续访谈时才额外读取 `访谈进度.md`；只有核验来源或理解变化过程时，才读取原始访谈、资料索引和历史版本。

为具体任务生成上下文时，只选与任务相关的事实、资源、约束、目标和协作偏好；不修改权威资料，不附带无关敏感信息。

## 验收

交付前检查：

1. 是否正确选择模式并保持当前主要任务。
2. 是否区分信息类型、时间和确认状态。
3. 是否只读取和写入授权目录。
4. 是否把隐式发现限制在待确认区。
5. 是否在权威更新前展示差异并获得确认。
6. 是否使用预期版本、快照、日志和写后校验。
7. 是否允许用户跳过、纠正、撤回和删除。
8. 是否避免诊断、固定标签、诱导问题和无关敏感披露。

## 行为验收

发布后在全新会话中使用 [behavior-cases.md](references/behavior-cases.md) 验证触发、非触发、权限边界和失败处理。案例只定义预期，不授权读取或修改个人资料。
