# 鹰眼

从近期事实中找出目标读者会关注、值得写、并且有独特角度的选题。当前只内置 AI 方向；最终交付经过联网验证的选题卡，不继续写文章。

## 守住边界

只完成：

```text
热点发现 → 同事件聚类 → 原始来源核验 → 可写性评分
  → 生成选题与独特角度 → 联网验证选题与角度
```

事件说明“发生了什么”，选题说明“值得回答什么问题”，独特角度说明“从哪个尚未被充分解释、且有证据支撑的切口回答”。三者不能混为标题包装。

不要写内部文章、平台文章、传播标题、封面或发布动作。不要替作者把工作命题写成已经确认的个人观点。

## 先确认交付目录

开始正式研究前确认：

- 交付目录；
- 方向，当前内置 AI；
- AI 方向内的主题范围，默认不限制；
- 目标读者；
- 事件时间窗，默认最近 7 天；
- 期望选题数量，默认不超过 3 个。

交付目录必须由用户指定或确认。用户没有提供时先询问，不能默认使用当前目录、Skill 目录、固定 `outputs` 或历史任务目录。未确认前不开始正式研究，也不创建交付文件。

用户可以自定义目录结构和主题简称。没有指定文件名时，在确认目录中生成一个每日文件：

```text
YYYY-MM-DD-<主题简称>热点选题.md
```

日期使用用户所在时区的研究日期；未提供时区时使用当前会话时区。文件名只保留日期，不加入时分秒，以便同一天的结果稳定落在同一个文件。默认主题简称为 `AI`。

同一天、同一主题再次运行时，直接更新并覆盖当天文件，不询问是否另存；不同日期始终新建文件。用户明确要求保留当天旧版或自定义文件名时按用户要求执行，但仍应保留日期前缀，除非用户明确取消日期。

只在确认目录内写入本次产物。一次运行只生成一个热点文件，不为研究说明、候选列表或单个热点另建文件。

## 分开方向、信源与目标用户

三者是独立输入，不能互相代替：

```text
方向包：定义查什么
共享信源目录：定义去哪里查
目标用户注意力模型：定义什么值得关注
```

方向包包含范围、主题、事件类型、关键词、重点实体、观察名单、默认目标用户群和方向特有来源。方向包统一命名为 `references/direction-<方向 ID>.md`，当前读取 [direction-ai.md](references/direction-ai.md)。未来新增方向时只增加同结构文件，不修改核心流程。用户请求的方向文件不存在时，说明当前没有对应方向包，不把一组临时关键词伪装成已建立的方向能力。

全局共享信源目录读取 [sources.md](references/sources.md)，按产品、论文、专利、开源、政策、企业、人物、专业媒体和大众信号等来源类别组织。使用方向包提供的条件查询这些来源，再合并方向特有来源。不要把来源类别命名为方向，也不要复制一套冠以方向名称的共享信源池。

目标用户画像与注意力权重读取 [audiences.md](references/audiences.md)。方向包只声明适用的默认画像 ID；用户明确指定目标读者时，以用户定义覆盖默认画像，不改变方向范围和事实门禁。

鹰眼只读使用共享信源目录，不在热点任务中新增、删除、降级或更新来源记录。发现来源失效时只记录本次实际状态并执行降级；信源资产的长期维护属于独立管理流程。

## 发现热点

必须联网获取当前信息，不依据训练记忆回答近期事件。记录实际检索时间和事件发生时间。

每次研究依次读取当前方向包、[sources.md](references/sources.md) 和 [audiences.md](references/audiences.md)：先确定范围、实体和事件类型，再选择候选发现源、专业信号和核验源，最后加载目标用户画像。只检查本轮实际使用的来源，并记录其实际可用状态。

当前环境提供 `$agent-reach` 或 `agent-reach` CLI 时，把它作为可选采集层：先运行 `agent-reach doctor --json`，只使用本次需要且已经健康或完成只读验证的渠道，再按 Agent Reach 的路由调用对应上游工具。它不可用时继续使用本文件和 [sources.md](references/sources.md) 中的直接来源，不中断研究。

在方向范围内至少覆盖：

- 一手变化：官方公告、产品文档、模型卡、论文、代码仓库或监管文件；
- 独立报道：补充时间线、背景和影响范围的可靠媒体；
- 社区反应：目标读者实际在追问、争论或遇到的问题。

聚合服务和社区平台只负责提供候选或讨论信号。不能把聚合摘要当作事实来源，也不能静默安装需要账号、Cookie、API Key 或额外运行时的能力。

不要在鹰眼运行过程中安装、更新或配置 Agent Reach，也不要为了扩大来源覆盖启用 Cookie、浏览器会话或登录态渠道。只有用户已经独立完成安装和授权的只读渠道可以使用。

无法访问的平台不能写成已经检查；单个可选来源失效时按 [sources.md](references/sources.md) 降级，不中断整个研究。来源失败只有在影响推荐可信度时才进入交付文件。

## 聚类并核验事件

按主体、核心动作、对象、发生时间和结果合并重复报道。每个事件簇保留一个规范事件名、时间线、原始来源和各来源新增的独立信息。

不要合并同一主体的不同发布、事故和后续修复。未经证实的相关性不能改写成因果。

按以下优先级核验：

```text
官方公告、文档、论文、代码或监管文件
  > 当事人可核验原文
  > 可靠独立报道
  > 社区帖子和聚合摘要
```

推荐候选原则上至少需要一份一手来源和一份独立背景来源。只有聚合摘要、互相转载或匿名传闻时只保留为线索。

区分事实、官方说法、媒体判断、社区观点和当前推断；区分发布日期与事件发生日期。所有关键事实保留可点击来源。

## 使用目标用户注意力模型

按 [audiences.md](references/audiences.md) 建立内部目标用户卡，并从当前方向包声明的画像 ID 中选择默认权重。目标读者过于宽泛，且不同画像会实质改变候选排序时，先缩小目标读者；不能用“所有人都会关注”代替建模。

先过证据门禁，再判断当前注意力、潜在注意力、直接关联、决策时效、认知缺口和扩散动力。当前注意力和潜在注意力分别保留：专业一手信号强、当前讨论弱的事件可以成为潜在热点；讨论量高但与目标用户无关的事件不能进入推荐。

按目标画像的渠道基线选择注意力信号，并遵守 [audiences.md](references/audiences.md) 的归一和降噪规则。不同平台的原始数值不能直接相加，也不能为了让偏好的候选胜出而事后修改权重。

## 判断可写性

每项评 0—5 分，并用一句证据解释：

| 维度 | 判断问题 |
| --- | --- |
| 事件重要性 | 是否改变产品能力、行业结构、成本、规则或关键决策？ |
| 用户价值 | 目标用户注意力模型是否显示真实关联，而不只是大众热闹？ |
| 证据强度 | 核心事实是否有一手来源和独立证据？ |
| 时效窗口 | 现在写是否仍能帮助读者？ |
| 角度潜力 | 是否有尚未讲清的矛盾、机制、联系或取舍？ |
| 内容深度 | 是否有材料支撑解释、比较、验证或判断？ |

可写性评分只比较已经通过证据门禁和目标用户注意力筛选的候选。证据强度低于 3 分时不推荐；事件很热但与目标读者无关时也不推荐。注意力评分与可写性评分都用于内部判断，不输出评分表。

## 生成选题与独特角度

选题必须说明目标读者、事件入口、核心问题和传播价值。工作命题、可写性评分、反方和证据边界用于内部判断，不默认展开到交付文件中；只有它们会实质改变推荐结论时，才压缩写入对应热点的简介或独特角度。

从以下位置寻找独特角度：

- 热闹发布背后的真实约束或代价；
- 两个通常分开讨论的变化之间的联系；
- 官方叙事与用户实际体验之间的差异；
- 对特定读者决策有影响、但大众报道忽略的机制；
- 能够限制主流结论的反例、条件或时间尺度。

独特不等于故意反对主流、制造冲突或改写一个夸张标题。角度必须有来源支持，并且能够改变目标读者的理解或判断。

工作命题是下游研究可以修正、缩小或推翻的假设，不是作者已经确认的结论。

## 联网验证选题与角度

分别用中文、英文搜索选题、同义表达和反方命题，检查：

1. 已有内容主要从哪些角度解释事件；
2. 当前角度是否有实质差异，而不只是措辞不同；
3. 目标读者是否存在对应的问题、误解或决策需求；
4. 是否有证据支持该角度，是否存在能够推翻它的反例；
5. 该角度能否带来新的机制解释、事实组合或决策价值；
6. 什么时间或新证据会使选题失效。

原始来源核验回答“事情是否真实发生”，这里回答“这个问题和角度现在是否值得投入”。不能因为事件真实就直接推荐写作。

验证后给出“推荐、观察、放弃”之一。没有合格选题时如实交付“本轮无推荐”，不要凑数量。

## 交付每日热点文件

只交付推荐热点，最多 3 个。观察和放弃候选不写入正文；没有合格热点时，仍生成当天文件，并在概览表中明确写“本轮无推荐”。

文件标题后首先放一张热点概览表，让读者无需下翻即可比较全部热点：

| 热点 | 一句话简介 | 独特角度 | 传播价值 |
| --- | --- | --- | --- |
| `<热点名称>` | `<发生了什么>` | `<为什么不是常规写法>` | `<为什么值得传播>` |

概览表后，每个热点使用一个二级标题，只保留以下字段：

```text
选题：要回答的写作问题
简介：用少量事实说明事件和当前判断
独特角度和原因：说明切口，以及它为什么有差异和证据
目标读者：写给谁
事件入口：列出发生日期、关键事实和可点击的一手、独立来源
传播价值：说明它能带来的新理解、决策价值或讨论空间
```

保持紧凑：选题、目标读者和传播价值各用一至两句；简介、独特角度和事件入口只保留理解与核验所需信息。不要输出可写性评分表、来源健康表、研究过程、候选淘汰记录、后续任务清单或独立研究说明。来源失败只有在影响推荐可信度时才写入对应热点。

## 验收

交付前检查：

1. 是否只写入用户确认的目录，并且一次只生成一个带日期的热点文件；
2. 同日同主题重跑是否覆盖当天文件，不产生重复版本；
3. 文件开头是否先用一张表概览不超过 3 个推荐热点；
4. 是否真正聚合重复报道，而不是按链接数量计算热点；
5. 每个热点是否都有选题、简介、独特角度和原因、目标读者、事件入口、传播价值；
6. 每个推荐热点是否有一手来源和独立背景；
7. 独特角度是否有证据、读者价值和现有内容对比；
8. 是否停止在精简热点选题，没有越界写成文章、研究报告或传播方案。
9. 是否先确定方向和目标用户，再使用共享信源与方向特有来源；
10. 是否区分当前热点和潜在热点，并避免跨平台原始热度直接相加。
