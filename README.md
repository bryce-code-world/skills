# ⚡ Bryce Skills

为自己与 AI 协作构建的实用 Skill。

</div>

这些 Skill 先解决自己的真实问题，再整理成可复用的开放指令。

仓库遵循通用的 `SKILL.md` 目录结构。

## Skill 清单

| Skill | 作用 |
|---|---|
| [你好（hello）](./hello/SKILL.md) | 通过持续访谈和会话暂存，建立并维护用户掌控的个人全景档案。 |
| [鹰眼（eagle-eye）](./eagle-eye/SKILL.md) | 面向目标读者发现、核验并交付值得写且具有独特角度的 AI 选题。 |
| [闪电（lightning）](./lightning/SKILL.md) | 在不丢失关键信息的前提下，把内部文档整理成自己易读、AI 易于行动的形式。 |
| [架构图（architecture）](./architecture/SKILL.md) | 把已确认的架构事实转译成可信、清晰、可离线打开的单文件 HTML 架构图。 |
| [可视化认知学习（visual-cognitive-learning）](./visual-cognitive-learning/SKILL.md) | 把已梳理清楚的主题文档转译成先逐步理解、再查看全貌的离线单文件 HTML。 |
| [声纹（writing-style）](./writing-style/SKILL.md) | 提炼和应用个人风格，正向建立作者—读者关系并清理机械 AI 痕迹。 |
| [广播（broadcast）](./broadcast/SKILL.md) | 按传播效果链和关系契约分别设计标题、封面、开头、正文和结尾，把完整内部底稿转写为四平台长图文。 |
| [分发（distribution）](./distribution/SKILL.md) | 把验收通过的平台稿保存为草稿或公开发布，核验最终状态并登记渠道对象和公开链接。 |

## 安装

在支持 `SKILL.md` 的 Agent 中安装：

```text
帮我安装这个 Skill：
https://github.com/bryce-code-world/skills/tree/main/lightning
```

也可以把 `lightning` 目录复制到本地 Skill 目录。

安装你好时，将链接或目录名替换为 `hello`。

安装鹰眼时，将链接或目录名替换为 `eagle-eye`。

安装架构图时，将链接或目录名替换为 `architecture`。

安装可视化认知学习时，将链接或目录名替换为 `visual-cognitive-learning`。

安装声纹时，将链接或目录名替换为 `writing-style`。

安装广播时，将链接或目录名替换为 `broadcast`。

安装分发时，将链接或目录名替换为 `distribution`。

八个 Skill 独立安装。业务 Skill 不在运行过程中自动安装缺失能力；需要新增或更新 Skill 时，使用源码仓库、插件或用户显式安装流程。

架构图只对其 `dependencies.md` 声明的白名单依赖执行按需自动安装，不再询问。未知来源、来源变化、版本无法核验和依赖更新不自动执行。

广播、声纹和分发不在运行时执行 24 小时更新检查。

发布 Skill 更新时，必须同步提升对应 `references/release.json` 的语义版本。

## 你好

适用于：

- 通过分阶段访谈建立个人背景基线。
- 在普通会话中自动暂存具有长期价值的个人经历和现实变化。
- 定期审核候选信息，更新可追溯的《个人全景档案》。
- 为新的 AI 或具体任务生成最小必要个人背景。

候选信息默认只进入待确认区。未经逐条审核确认，不会写入权威档案。

使用示例：

```text
使用 $hello 通过持续访谈建立我的个人全景档案。
```

## 鹰眼

适用于：

- 从近期 AI 热点中筛选目标读者值得关注的事件；
- 先加载 AI 方向条件，再查询论文、专利、开源、政策、企业、人物和大众信号等共享信源；
- 聚合同一事件并回到原始来源核验；
- 区分当前热点与尚未扩散的潜在热点；
- 使用目标用户注意力模型，而不是统一的大众热度分；
- 比较候选事件的可写性；
- 为选题找到有证据、对读者有价值的独特角度；
- 联网检查现有内容、反方证据和选题有效期。
- 当前环境已经安装 Agent Reach 时，把健康渠道作为可选采集层。

鹰眼当前内置 AI 方向，只读使用共享信源目录，不负责长期维护信源资产。它停止在经过验证的选题，不继续写内部文章或公开平台文章。没有用户确认的交付目录时不会开始正式研究或创建文件。每次把不超过 3 个热点汇总为一个带日期的文件，同日同主题重跑时覆盖当天文件。

使用示例：

```text
使用 $eagle-eye 面向 AI 开发者，从最近 7 天的 AI 热点中找出不超过 3 个值得写且有独特角度的选题，并汇总到我确认目录中的当天文件。
```

## 闪电

适用于：

- 内部文档的创建、修改、整理和审查。
- 分析报告、设计方案、审查报告和任务说明。
- 零散材料和知识库内容的结构化整理。
- 为自己和 AI 准备可快速理解的任务上下文。

不适用于公众号、新闻、博客、论文、营销文案和文学创作。

核心原则：

> 在不丢失关键信息的前提下，把内容整理成最容易理解的形式。

使用示例：

```text
使用 $lightning 整理这份内部文档。
```

## 架构图

适用于：

- 企业产品蓝图、平台能力蓝图和业务—技术一体化架构图。
- 分层系统、微服务、AI 平台和数据平台架构。
- 带左右横切能力、外部依赖、数据平面或基础设施层的复杂蓝图。
- 确实需要逐层探索、架构演化或路径聚焦的交互式架构模型。

输入应包含已经确认的组件、分组、关系和边界。架构图先建立内部绘图规格，再按场景复用静态布局、可视化认知学习或前端视觉能力，并统一补齐离线图标、稳定画布、精确连线和浏览器验收。

输出只有一个可通过 `file://` 直接打开的 HTML 文件。参考图只提供视觉方向，不会被当作架构事实来源。

使用示例：

```text
使用 $architecture 把这份企业 AI 平台设计转成可信、清晰、可离线打开的单文件 HTML 架构图。
```

## 可视化认知学习

适用于：

- 把 SOP、业务流程、状态机和方案形成过程转成可逐步理解的学习模型。
- 展示复杂事物从简单起点演化到当前形态的过程。
- 让公式参数、因果传播、物理机制和层级关系变得可观察、可操控。
- 从局部问题开始引导理解，完成后再查看全局关系。

输入应是已经梳理清楚的主题文档。输出是可直接离线打开的单文件 HTML；交互只在有助于理解关系时使用，不补造来源没有说明的事实或机制。

使用示例：

```text
使用 $visual-cognitive-learning 把这份软件开发 SOP 转成可逐步理解、完成后能查看全局流程的离线单文件 HTML。
```

## 声纹

适用于：

- 从对话或历史文章提炼本人及他人的表达风格。
- 管理多个命名个人档案和一个默认档案。
- 为文章选择主风格和场景语气。
- 建立可信的说话位置、读者关系、对话距离和口语边界。
- 应用风格、执行正向声音检查与去模板化，并检查跨平台一致性。

不会静默学习或修改档案，也不会冒充参照作者、虚构经历或为了风格改变事实。

使用示例：

```text
使用 $writing-style 从这些文章提炼我的个人风格，先展示候选档案，确认后再保存。
```

## 广播

适用于：

- 从一篇完整、结论收敛的内部底稿生成简洁广播任务总结；
- 写作前明确普通大众、主题半熟悉读者或专业读者，并区分能够识别的主题术语、已经理解的共同概念和必须先解释的概念；
- 面向普通大众时使用有共识的简单语言，先建立含义再引入必要术语；
- 写作前建立作者说话位置、读者关系、对话距离、情绪温度和口语边界，不用网络用语配额制造“人味”；
- 把标题、封面、开头、正文和结尾作为五个独立工程，成稿后由独立读者执行五道门禁和陌生场景迁移题；
- 生成公众号标准文章、知乎独立文章、CSDN 技术文章或掘金技术文章；
- 四个平台直接读取内部底稿和任务总结，彼此不作为内容上游；
- 对 CSDN 和掘金执行开发者内容准入门禁，不把无关内容强行同步到技术社区；
- 在 CSDN 和掘金稿中保留必要、已脱敏且带环境和结果说明的代码块；
- 公众号默认无目录并保留真实作者关系，知乎强化推理，CSDN 强化技术闭环，掘金强化工程取舍；
- 使用克制编辑感的统一视觉骨架，并把真实草稿排版条件交给分发阶段核验；
- 为每个平台生成与标题互补的入口封面：标题负责进入理由，封面优先补充情绪、场景、对象证据或账号风格；
- 用户明确要求投递时，把验收通过的发布包交给 `$distribution`，不在广播中管理账号、浏览器和发布状态。

广播保护事实、观点、条件和不确定性，默认不连接账号、不投递草稿，也不公开发布。

概念视觉与平台封面按需使用 `canvas-design`；既定方向需要写实或复杂位图素材时再调用 `imagegen`。精确信息图优先使用当前环境已有的原生可编辑图形能力，不临时引入额外 Skill。

使用示例：

```text
使用 $broadcast 从这篇完整技术底稿推导认知缺口、作者—读者关系和目标效果，用真实同类样本校准标题、封面、开头、正文和结尾的分工，再生成公众号、知乎、CSDN 和掘金传播包。
```

## 分发

适用于：

- 检查目标平台、账号、稿件、素材和本次授权；
- 把验收通过的微信公众号、知乎、CSDN 或掘金文章预填或保存为草稿；
- 在用户明确授权后公开发布，并从草稿箱或公开页面核验结果；
- 区分已填充、草稿已保存、草稿已核验、已发布和发布已核验；
- 在文章发布包目录维护渠道对象和规范公开链接，供后续数据追踪；
- 按需加载目标渠道模块，新增平台时不复制核心授权与状态协议。

分发不改写文章，也不自动安装浏览器工具、MCP、插件和运行时。浏览器能力不可用时保留本地发布包并转人工处理。

使用示例：

```text
使用 $distribution 把这个验收通过的公众号发布包保存到指定公众号草稿箱，重新打开草稿核对标题、正文、封面和移动端排版，不要公开发布。
```
