# 场景路由

一次任务只选择一个主绘图路径。辅助能力不得各自生成一份互相冲突的架构。

## 一、先判断主要阅读任务

只选择一个主要任务：

- 同时看清系统整体、分层、边界和主要关系。
- 逐步理解架构如何演化、展开或沿路径运行。
- 在事实结构不变的前提下获得特定品牌或展示风格。

目标混在一起时，以用户最终要理解或决定的事情为准；次要内容下沉为说明，不并列争夺主图。

## 二、选择主路径

| 判断 | 主路径 | 处理 |
|---|---|---|
| 主要任务是同时看清整体结构 | 静态企业蓝图 | 读取隔离的 `markdown-viewer/architecture` 规则源 |
| 需要操作后才能理解演化、层级或路径 | 交互认知模型 | 使用 `visual-cognitive-learning` |
| 结构已确认，只需形成独特视觉方向 | 当前主路径 + `frontend-design` 辅助 | 只改变视觉语言，不改变架构事实 |

### 静态企业蓝图

适合：

- 企业产品、平台能力和业务—技术一体化蓝图。
- 分层系统、微服务、AI 平台和数据平台架构。
- 左右横切能力、顶部接入层、底部数据或基础设施层。
- 一张图内需要表达多个确定分组，但不需要读者操作。

只从上游规则源读取当前需要的布局、样式和连接器文件，不加载无关模板。

### 交互认知模型

只有能够明确回答以下两个问题时才使用：

1. 读者具体点击、推进、聚焦或切换什么？
2. 操作后会看到什么有助于理解的变化？

如果删除交互后理解效果不变，使用静态蓝图。

### 视觉定向

只有用户明确要求品牌化、特定展示语境或参考视觉时才调用 `frontend-design`。它可以决定配色、字体、节奏和视觉签名，不能增加节点、连接、边界或规划状态。

## 三、避免错误路由

- 普通流程图、时序图或快速关系图不强制进入企业蓝图。
- 简单三层系统使用最小分层结构，不增加侧栏、治理层和装饰模块。
- 参考图只有样式没有真实内容时，先完成架构图规格。
- 输入仍有关键冲突时，不通过交互或视觉润色掩盖事实缺口。
- 用户要求 Draw.io、Excalidraw、独立 SVG、PNG 或 Mermaid 为主产物时，说明当前 Skill 的单 HTML 边界并改用对应专项能力。
