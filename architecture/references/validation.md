# 架构图验收

最终产物同时通过事实、HTML、浏览器和视觉四层验收后才能声称完成。

## 一、事实验收

- 节点名称、职责、分组和时间状态能够回到来源。
- 每条确定连线都有明确依据，方向和类型没有被补造。
- 当前架构、目标架构、规划和推断没有混成同一事实层。
- 外部依赖、信任边界和横切能力位置准确。
- 参考图只影响视觉，没有替代真实架构内容。
- 未进入主图的冲突和未知已记录，不被静默删除。

## 二、HTML 验收

- 只有一个 `.html` 文件。
- 存在完整 `doctype`、`html`、`head` 和 `body`。
- CSS、JavaScript、SVG、数据和图标全部内嵌。
- 不存在外部脚本、样式表、字体、图片、iframe、模块导入和网络接口。
- 不包含密钥、Token、Cookie、绝对来源路径和无关原始材料。
- JavaScript 部分失败时，静态主体仍能表达主要结构。
- 控制台没有影响主体、连接器或查看路径的错误。

## 三、浏览器验收

使用当前可用的现代 Chromium 或 Edge：

1. 通过 `file://` 实际打开最终文件。
2. 检查主要目标桌面尺寸。
3. 检查至少一个较窄视口。
4. 截图保存为过程证据，不默认进入交付包。
5. 阻止网络请求后重新检查内容和图标。
6. 存在交互时，仅用键盘完成主要查看路径。
7. 存在动画时，检查 `prefers-reduced-motion` 下的等价表达。

浏览器不可用时只能说明事实和静态检查结果；不得声称浏览器与视觉验收通过。

## 四、视觉验收

- 第一屏能够说清架构对象、主要结构和视觉重点。
- 标题、侧栏、主层、图例和底部横向层完整可见。
- 没有文字截断、卡片重叠、容器溢出和不可控横向滚动。
- 连接线端点、箭头、方向、标签和避让正确。
- 连线不穿过节点、标题和关键说明。
- 长中文、英文缩写、双语标题和多行说明均可读。
- 色彩、图标、形状和线型语义一致，且不只靠颜色区分。
- 简单架构没有被强制套成复杂企业蓝图。

## 五、失败处理

| 情况 | 处理 |
|---|---|
| 事实不完整 | 完成确定部分；删除或标记未确认关系 |
| 内容过密 | 聚合节点、下沉说明、扩大画布或拆分视图 |
| 连线无法避让 | 减少次要关系、调整分区或改变主结构 |
| 依赖安装失败 | 执行 `dependencies.md` 中的场景降级 |
| 交互无助理解 | 改为静态 HTML 蓝图 |
| 浏览器不可用 | 明确未完成浏览器与视觉验收 |
| 参考图与事实冲突 | 保留事实，只借鉴视觉语言 |

修复后重新执行受影响层及其下游验收。只改颜色不能解决布局、连线或事实问题。
