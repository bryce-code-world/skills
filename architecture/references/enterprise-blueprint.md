# 企业蓝图规则

本文件补充静态企业架构图的共同薄弱点，不替代上游布局与样式规则。

## 一、画布与分区

1. 先确定主结构和内容规模，再确定逻辑画布尺寸。
2. 将桌面蓝图作为权威布局，保证分组和连线不因视口改变而错位。
3. 窄屏优先使用整体缩放、可控横向查看或简化总览，不把复杂蓝图强制重排成长页面。
4. 内容超出时增加高度、聚合节点或下沉说明，不持续缩小文字。
5. 根据真实结构组合以下区域，不要求全部出现：
   - 左侧业务、入口或产品形态。
   - 中间主架构和嵌套能力层。
   - 右侧治理、外部依赖或供应商。
   - 顶部接入、用户或渠道层。
   - 底部数据平面与基础设施层。
6. 横切能力使用贯穿侧栏或边界，不复制进每个业务层。

## 二、视觉层级

- 标题只说明架构对象和时间状态，不使用宣传口号。
- 层名、域名、组件名和补充说明形成稳定的四级层次。
- 主要底座、核心路径和信任边界应比次要技术清单更醒目。
- 同类节点使用一致的图标、形状和语义色；颜色不是唯一编码。
- 参考图提供密度、分区和视觉方向，不提供架构事实。
- 不使用含义不稳定的 Emoji 作为正式主图标。

## 三、离线图标

- 使用内联 SVG 或等价离线资源。
- 只内嵌当前图实际使用的图标，不打包完整图标库。
- 图标必须与可见文字名称同时存在。
- 不加载外部字体、在线图标接口、远程图片或 CDN。
- 使用第三方图标时保留来源与许可证核对记录，但不把研发记录塞进最终 HTML。

## 四、连接器

1. 先完成容器和节点布局，再绘制关系。
2. 主路径优先使用水平、垂直和直角转折。
3. 将连线置于节点下方或绕开节点，不穿过组件主体、标题或说明。
4. 简单局部关系使用固定锚点；跨层、跨区或需适应视口的关系依据元素边界计算 SVG 路径。
5. 页面加载和尺寸变化后重新计算动态连接器，保持离线且不改变架构状态。
6. 同步调用、异步事件、数据流和治理关系使用可区分的线型，并提供紧凑图例。
7. 连线过多时保留主路径，聚合或下沉次要关系，不生成意大利面图。

## 五、文本与密度

- 一张图只承担一个主要阅读任务。
- 组件卡保留正式名称和理解所需的一句信息。
- 长说明、实现细节和完整技术清单放到辅助说明，不塞入节点。
- 同一结论只出现一次；图例只解释视觉编码。
- 长中文、英文缩写和双语标题应通过换行与宽度解决，不通过极小字号解决。
- 如果内容仍无法清楚容纳，扩大画布或拆成主图与辅助图。

## 六、实现底线

- 最终只有一个完整 HTML 文件。
- CSS、JavaScript、SVG、数据和图标全部内嵌。
- 通过 `file://` 打开，不需要服务器或构建步骤。
- JavaScript 失败时节点、分组和核心说明仍然可见。
- 没有必要交互时不增加动画、筛选器、按钮或悬停隐藏信息。
