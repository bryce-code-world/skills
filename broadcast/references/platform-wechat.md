# 公众号标准文章

只负责结合已经通过底稿门禁的完整内部底稿和广播任务总结，直接转写微信公众号标准文章。不要生成小绿书、卡片或其他形态。

## 输入契约

开始前确认：

- 一篇明确的权威内部底稿已经通过底稿门禁；
- `00-广播任务总结.md` 已经生成且没有复述底稿；
- 内容任务、底稿材料画像、内容拓扑、阅读方式、知识单元角色、本平台输出形态和唯一主导原型已经确定；
- 主风格、本平台侧重点和本次特别要求可用；
- 目标是公众号标准文章。

底稿不完整时停止或转交 `$lightning`；任务总结缺失时先补任务总结。不得读取其他平台稿补造核心内容。

## 重构目标

公众号依赖订阅关系和移动端连续阅读。重构重点是让读者快速建立“这与我有什么关系”，然后沿一条主线自然读完。

公众号关系较强不代表必须使用经验复盘或认知变化。底稿没有真实经历时，按已经选定的问题解释、观点论证、方法分享或能力演化原型推进，不为对象感改选原型。

公众号可以采用精华版，但不能只剩观点摘要。必须保留核心结论、关键证据、最短完整推理链、主要边界和至少一个可迁移判断或应用方式；优先压缩支撑知识单元，延伸知识单元可以省略，核心知识单元不得均匀削薄。保留的每个核心部分仍需完成结论、机制、边界和实践影响中的必要环节。

可以调整：

- 从底稿已有的真实观察、经验分享、思考变化或读者共同经历中选择具体入口；
- 缩短段落，增加必要留白和转场；
- 用少量小标题帮助手机扫读；
- 将已有案例、解释、判断过程和结论调整到更自然的位置；
- 压缩过密的概念说明，但保留必要推理和边界；
- 在结尾回收开头或给出自然的判断与行动方向。

第一人称表达在四个平台中最强，可以呈现作者为什么这样理解、曾经哪里想错和如何做出取舍，但只能使用作者真实拥有的观察和判断。

不得新增底稿中不存在的事实、案例、经历、核心观点和第二主线。需要的机制或边界不在底稿时，缩小表达或停止并请求补充底稿。

## 入口传播组合

公众号入口同时面对订阅读者和转发链中的陌生读者。标题与封面先让目标读者确认“这与我有关”，再给出清楚、具体且正文能够兑现的阅读收益。设计前读取 [headline-engineering.md](headline-engineering.md) 和 [cover-engineering.md](cover-engineering.md)，进入全文时分别读取 [opening-engineering.md](opening-engineering.md)、[body-engineering.md](body-engineering.md) 和 [ending-engineering.md](ending-engineering.md)。

- 标题：优先组合可识别对象、未解决张力和读者损益，至少让目标读者看到一个现在值得点开的具体原因；主题准确但只有概念分类时不进入终稿；
- 封面：优先补充标题难以承担的情绪、场景、人物、对象证据或账号风格；大众抽象长文默认无字，不把正文压缩成卡片、阶梯、流程或结构图；
- 开头：立即承接标题和封面，进入读者处境、真实观察或核心矛盾，不先讲作者背景；
- 正文：沿一条内容主线兑现承诺，语言门槛与任务总结中的受众认知层级一致；面向普通大众时优先使用有共识的简单语言，作者关系服务理解，不替代事实和推理；
- 结尾：回收读者能够带走的判断或方法，只在内容自然支持时提出互动。

写正文前从真实样本中提炼机制，内部生成至少 12 个、覆盖不少于 4 种机制的标题，再保留 3 个强候选；封面生成至少 3 个机制不同的方向，再保留 2 个强候选。标题与封面联合完成入口冷读，成稿后再与开头联动校准。标题或封面吸引了正文不服务的读者，或者承诺强于正文，均判定失败。

## 阅读节奏

优先采用：

1. 标题兑现一个真实阅读收益。
2. 摘要补充对象和价值，不机械重复标题。
3. 开头在较短篇幅内增加入口之外的新信息，建立读者处境、问题或矛盾，并把未完成的问题交给正文。
4. 正文按内容需要建立张力与回报循环，每个核心部分都新增理解、判断或可用结果。
5. 每个段落只承担一个主要任务，长短段落自然交替。
6. 条件、例外和风险就近出现，不统一藏到文末。
7. 结尾交付可带走的判断、方法或下一步，不空泛升华。

默认不生成目录，也不写“本文将介绍”式导航。只有超长工具书、手册或明确依赖跳读的参考型文章可以例外使用轻量文本目录。

公众号还需要建立清楚的阅读注意力层级：

- 用 `**语义重点**` 标记真正需要读者停顿、记住或据此判断的短句或短语；
- 优先强调核心判断、关键转折、选择标准和本节必须带走的结论，不按术语或关键词机械加粗；
- 一个自然段通常不超过一个强调区，连续段落不重复强调同一意思；
- 不整段加粗，不把每节第一句自动加粗，也不通过批量暖色和高亮制造重点；
- 没有值得强调的内容可以不加粗，但全文不能只靠普通正文承担全部信息层级。

避免：

- 很长的作者背景；
- 把内部底稿机械切成大量小标题；
- 每段都写成口号或金句；
- 为追求“公众号味”加入焦虑、煽动和机械互动；
- 用“转发给所有人”替代真实转发理由。

## 作者关系与连续性

公众号可以从真实经验、思考变化或一次具体取舍进入，但必须沿同一件事往下走。认知变化型文章优先使用“原来怎样理解 → 哪个具体问题让原理解失效 → 如何重新判断 → 新判断怎样改变行动”的链路。不要先说有一次转变，随后离开这件事去做概念分类。

内部底稿的目录不能直接变成公众号章节。小标题只标记自然转折，不按术语类别切割正文。专业概念只有在当前问题需要时才出现，并回到传播主线；不得为了满足“具体锚点”而强行使用作者当前工作作为案例。

“我后来发现”“我很认同”“我现在会”后面必须有真实材料中的触发、动作、取舍或结果。没有真实经历支撑时直接解释，不用第一人称包装说明书。

完成平台稿语言终检后，以 [communication-effects.md](communication-effects.md) 的五道门禁执行独立冷读和陌生场景迁移题，并用 [reader-continuity.md](reader-continuity.md) 补充概念与主线证据。格式正确、段落较短或句式自然，均不能替代这次阅读。

## Markdown 产物

输出 `01-公众号文章.md`，使用带结构的 Markdown。标题结构必须遵守 [platform-markdown-contract.md](platform-markdown-contract.md)：front matter 的 `title` 是唯一发布标题，正文不再包含 H1，而是直接从导语开始。当前环境已有等价明确协议时可以映射为该协议：

```markdown
---
platform: wechat
title: "推荐标题"
summary: "文章摘要"
cover: "assets/wechat/cover.png"
source: "<权威内部底稿路径>"
references:
  - name: "外部资料名称"
    url: "https://example.com/source"
---

正文……

![准确的替代文字](assets/shared/example.png)

图注：这张图帮助读者理解的核心关系
```

如果当前发布入口使用其他元数据协议，在投递阶段映射字段，不把发布参数写进正文。Markdown 是内容真相源，不能依赖下游删除重复标题；正文小标题从 `##` 开始。HTML 和公众号富文本是下游渲染结果。

最终可见正文超过 3000 字时，在 front matter 后、导语前加入与原生长度检查器一致的长文阅读提示；投递时渲染为淡色背景、小号次级文字。完整规则读取 [platform-format-contract.md](platform-format-contract.md)。

正文格式可以使用：

- 标题层级；
- 自然段；
- 列表；
- 少量强调；
- 图片和图注。

读取 [platform-format-contract.md](platform-format-contract.md) 应用统一视觉骨架和公众号富文本基线。Markdown 是语义真相源；字体、字号、颜色和行距由投递时的富文本渲染实现，但平台默认导入样式不能直接视为成稿。

Markdown 列表继续表达语义关系。投递时若微信公众号原生列表导致字号或行高缩小，`distribution` 必须把它渲染为正文级编号或项目段落，不得通过删除列表关系修复样式。

## 公开正文硬限制

公众号成稿不得出现：

- 三个反引号或三个波浪线形成的围栏代码块，包括用来排版普通文字的 `text` 代码块；
- 以 `>` 开头的 Markdown 引用块；
- Markdown 表格、ASCII 图、空格对齐的多列文本和 `<pre>` 等不自动换行结构；
- 作为独立可见文本的长网址、长路径、长命令和连续标识符；
- Markdown 文字链接和可见网址；
- “参考资料”“参考文献”“资料来源”“来源列表”等文末章节；
- 脚注、尾注和编号链接列表。
- 正文一级标题，或在正文首行重复 front matter 的标题。
- 未通过“超长参考型文章”例外判断的目录、“本文将介绍”式导航和大面积蓝底标题块。

对照内容改为分点列表或手机宽度下可读的纵向信息图。需要保留原话或重点结论时写成自然段，必要时使用少量加粗。正文必须说明出处时，只把机构、报告或实验名称写成普通文本；完整地址写入 front matter 的 `references`，证据强度、素材授权和风险信息写入 `05-验收报告.md`。不在正文或文末重新展开来源列表。

## 视觉处理

- 复用直接来自底稿、且至少两个平台都需要的共享正文插图；
- 遵守 [platform-format-contract.md](platform-format-contract.md) 的克制编辑感：深灰正文、少量暖色编号或细线、充足留白，不使用蓝底标题块；
- 按 [orchestration.md](orchestration.md) 的视觉路由生成公众号封面和必要裁切版本：概念型、编辑型封面优先 `$canvas-design`，既定方向需要照片、复杂插画或纹理位图时使用 `$imagegen`；
- 调整插图位置和留白，不改变图片语义；
- 按 [platform-markdown-contract.md](platform-markdown-contract.md) 为信息图分别提供替代文字和 `图注：`；纯装饰图使用空替代文字且不生成图注；
- 图注只说明图片对当前论证的作用，不替代相邻正文，也不扩大图片或正文结论；
- 保证图片文字在手机宽度下可读；
- 保留封面的设计说明或可编辑源文件，以及最终 PNG；
- 实际查看目标尺寸和约 320 像素宽缩略结果，完成至少一次视觉批评和修正；
- 不用平台封面扩大正文观点强度。

## 移动端检查

- 直接扫描 Markdown 源文件；存在围栏代码块、引用块、Markdown 表格、ASCII 排版或 `<pre>` 时立即判定失败；
- 任何正文结构都必须在手机宽度内自动换行，不得依赖横向滚动；
- 外部网址从正文移入 front matter 的 `references`；长路径、长命令和连续标识符改为普通解释或纵向信息图；
- 段落是否过长或连续过密；
- 小标题是否帮助扫读而不是制造碎片；
- 核心判断、关键转折和选择标准是否形成少量、准确的加粗锚点；
- 列表在真实预览中是否与正文同字号、同一行高区间，没有被平台默认样式压缩；
- 是否默认无目录，首屏没有被导航框或大色块占满；
- 图片路径和顺序是否正确，信息图是否有紧邻且准确的图注，替代文字是否没有被当作可见图注；
- 封面和正文图片是否分别记录确认状态。
- 缩略封面是否仍能感知清楚的情绪、场景、对象或风格，并与标题共同形成进入理由，而不是像一页需要阅读的演示文稿。

无法查看真实手机端结果时，不标记“草稿排版已通过”；本地源稿可以完成，但把移动端复核留在草稿验收中。

## 交付与验收

交付：

```text
01-公众号文章.md
assets/wechat/
```

检查：

- 只看标题和封面时，目标读者是否能识别主题、相关性和真实阅读收益；
- 受众认知层级是否在写作前明确，入口、术语密度和解释深度是否与该层级一致；
- 目标读者是否能指出为什么愿意现在点开，而不是只评价标题准确或清楚；
- 最终标题是否有真实样本校准和机制不同的候选比较，是否避免把无数据样本说成十万加；
- 最终封面是否有真实样本校准、标题与封面的明确分工、非语言视觉命题和机制不同的候选比较，是否避免把头部账号普通封面说成十万加；
- 缩略状态下是否能感知清楚的情绪、场景、对象或风格，并与标题共同形成进入理由；除信息海报型外，是否避免卡片、箭头、流程和多标签；
- 标题、封面、摘要、开头和正文是否兑现同一入口承诺，结尾是否固化同一主要目标效果；
- 开头是否通过第一屏门，正文是否通过推进门，结尾是否通过最后一屏门；
- 开头是否迅速建立对象感和阅读理由；
- 正文是否准确转写底稿事实和边界，并让核心部分形成必要的深度闭环；
- 是否保留作者真实的观察、判断过程和取舍，而不是写成媒体稿或课程讲义；
- 第一人称是否有具体触发、动作、取舍或后果，而不是语气外壳；
- 是否围绕同一件事推进，概念是否在读者正需要时才出现；
- 标题和封面中的术语是否只用于点名读者可识别的主题，普通读者是否不依赖未解释的术语也能理解阅读收益和正文核心关系；
- 节奏是否适合手机连续阅读；
- 是否完全不存在围栏代码块、引用块、Markdown 表格、ASCII 排版和横向滚动结构；
- front matter 是否包含唯一发布标题，正文是否从导语开始且不存在 H1；
- 正文是否没有 Markdown 文字链接和可见网址，外部引用是否只保存在 front matter 的 `references`；
- 信息图是否使用非空替代文字和紧邻的 `图注：`，纯装饰图是否使用空替代文字且没有图注；
- 是否没有参考资料、参考文献、资料来源、脚注、尾注和编号链接列表；
- 是否默认无目录、没有大面积蓝底标题块，并符合公众号富文本基线；
- 是否存在可解释的重点层级，且没有机械加粗、整段高亮或列表缩小；
- 是否与其他已生成平台版本形成真实语境差异；
- 共享插图、封面和适配素材是否完整；
- 是否没有新增内部底稿之外的实质内容；
- 是否由独立读者完成五道门禁和正文未出现过的陌生场景迁移题，并在 `06-读者测试.md` 留下问题证据、判断过程、修改动作和复测结论；只有作者自检时不得标记为通过。
