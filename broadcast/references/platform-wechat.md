# 公众号平台规则

## 选择形态

公众号支持两种目标形态：

| 形态 | 主要阅读任务 | 典型产物 |
|---|---|---|
| 标准文章 | 完整理解、系统论证、长期沉淀 | 标题、摘要、正文、封面、文中配图 |
| 小绿书 / 图卡 | 快速浏览、收藏、转发 | 标题、发布短文、逐张图卡、封面 |

只指定“公众号”时：

- 内容依赖完整论证、上下文或证据链，推荐标准文章；
- 内容可以拆为单一判断、清单、步骤或对比，推荐小绿书；
- 两者都需要时，先完成标准文章，再从同一内容内核生成图卡，不从已压缩图卡反推长文。

## 标准文章

按以下顺序组织：

1. 标题兑现一个真实阅读收益。
2. 摘要补充对象和价值，不重复标题。
3. 开头在最短篇幅内回答“这与读者有什么关系”。
4. 正文按问题、判断、证据、方法或影响推进。
5. 条件、例外、风险和未知出现在相关结论附近。
6. 结尾收束为可带走的判断、方法或下一步。

避免：

- 先写很长的作者背景；
- 连续大段无小标题正文；
- 每段都用口号式金句；
- 为追求“公众号味”加入空泛升华；
- 用“转发给所有人”替代真实传播价值。

### 标准文章交付

```text
推荐标题：
备选标题：
摘要：
正文：
封面任务与文案：
文中视觉位置和任务：
来源与风险说明：
```

## 小绿书 / 图卡

把内容重组为卡片阅读路径，不机械截图长文。

推荐信息顺序：

1. 封面：对象 + 核心收益或判断。
2. 入口卡：问题为什么值得关心。
3. 主体卡：每张只完成一个理解任务。
4. 边界卡：条件、例外、风险或不确定性。
5. 收束卡：帮助读者复述、收藏或行动。

发布短文负责：

- 交代背景和对象；
- 串起图卡；
- 补充不适合放入卡片的来源或边界；
- 不逐字重复每张卡。

每张卡都记录来源项。卡片删除细节时，确认它只是重复或已由发布短文、附录承接。

### 小绿书交付

```text
推荐标题：
发布短文：
封面卡：
正文卡 1..N：
结尾卡：
每卡来源：
视觉系统建议：
```

## 平台验收

- 标准文章是否有完整论证而不是堆素材；
- 小绿书是否每张卡都有独立任务；
- 标题、摘要或发布短文是否兑现正文；
- 条件、例外和风险是否被卡片化压缩误删；
- 封面是否准确而非夸张；
- 当前编辑器的尺寸、数量和格式限制是否在实际投递前重新核对。
