# 公众号标准文章

只负责把已经通过门禁的大众基础长文重构为微信公众号标准文章。不要生成小绿书、卡片或其他形态。

## 输入契约

开始前确认：

- `01-大众基础长文.md` 已经通过基础门禁；
- 事实与观点账本、主风格和不可改变项可用；
- 共享正文插图已经生成，或明确记录为无需；
- 目标是公众号标准文章。

缺少完整基础长文时返回共同上游，不在本文件补写核心内容。

## 重构目标

公众号依赖订阅关系和移动端连续阅读。重构重点是让读者快速建立“这与我有什么关系”，然后沿一条主线自然读完。

可以调整：

- 把基础长文开头改成更有对象感的具体入口；
- 缩短段落，增加必要留白和转场；
- 用少量小标题帮助手机扫读；
- 将已有案例、解释和结论调整到更自然的位置；
- 压缩过密的概念说明，但保留必要推理和边界；
- 在结尾回收开头或给出自然的判断与行动方向。

不得新增基础长文中不存在的事实、案例、经历、核心观点和第二主线。需要实质补充时先修改基础长文并重新验收。

## 阅读节奏

优先采用：

1. 标题兑现一个真实阅读收益。
2. 摘要补充对象和价值，不机械重复标题。
3. 开头在较短篇幅内建立读者处境、问题或矛盾。
4. 正文按“问题 → 判断 → 解释或案例 → 影响”逐步推进。
5. 每个段落只承担一个主要任务，长短段落自然交替。
6. 条件、例外和风险就近出现，不统一藏到文末。
7. 结尾交付可带走的判断、方法或下一步，不空泛升华。

避免：

- 很长的作者背景；
- 把基础长文机械切成大量小标题；
- 每段都写成口号或金句；
- 为追求“公众号味”加入焦虑、煽动和机械互动；
- 用“转发给所有人”替代真实转发理由。

## Markdown 产物

输出 `02-公众号文章.md`，使用带结构的 Markdown。默认使用机器可读的元数据区，并保持正文独立可读；当前环境已有等价明确协议时可以映射为该协议：

```markdown
---
platform: wechat
title: "推荐标题"
summary: "文章摘要"
cover: "assets/wechat/cover.png"
source: "01-大众基础长文.md"
---

# 推荐标题

正文……

![准确的替代文字](assets/shared/example.png)

图注……
```

如果当前发布入口使用其他元数据协议，在投递阶段映射字段，不把发布参数写进正文。下游必须把元数据区解析为字段，不能渲染进文章；平台标题字段已经使用标题时，正文渲染应避免重复显示首个 H1。Markdown 是内容真相源，HTML 和公众号富文本是下游渲染结果。

正文格式可以使用：

- 标题层级；
- 自然段；
- 列表；
- 少量强调；
- 链接、图片和图注。

不要依赖 Markdown 表达精确字体、字号、颜色和行距。这些由渲染器或公众号编辑器处理。

## 公开正文硬限制

公众号成稿不得出现：

- 三个反引号或三个波浪线形成的围栏代码块，包括用来排版普通文字的 `text` 代码块；
- 以 `>` 开头的 Markdown 引用块；
- Markdown 表格、ASCII 图、空格对齐的多列文本和 `<pre>` 等不自动换行结构；
- 作为独立可见文本的长网址、长路径、长命令和连续标识符；
- “参考资料”“参考文献”“资料来源”“来源列表”等文末章节；
- 脚注、尾注和编号链接列表。

对照内容改为分点列表或手机宽度下可读的纵向信息图。需要保留原话或重点结论时写成自然段，必要时使用少量加粗。必须说明出处时，在相关句子中自然写明来源名称，并把链接附在简短名称上。完整来源、素材授权和风险信息只写入 `06-验收报告.md`。

## 视觉处理

- 复用基础长文中的共享正文插图；
- 按 [orchestration.md](orchestration.md) 的视觉路由生成公众号封面和必要的裁切版本：概念型、编辑型封面优先 `$canvas-design`，精确框架或文字型封面优先 `$frontend-design`；
- 调整插图位置和留白，不改变图片语义；
- 保证图片文字在手机宽度下可读；
- 保留封面的设计说明或可编辑源文件，以及最终 PNG；
- 实际查看渲染结果并完成至少一次视觉批评和修正；
- 不用平台封面扩大正文观点强度。

## 移动端检查

- 直接扫描 Markdown 源文件；存在围栏代码块、引用块、Markdown 表格、ASCII 排版或 `<pre>` 时立即判定失败；
- 任何正文结构都必须在手机宽度内自动换行，不得依赖横向滚动；
- 长网址、长路径、长命令和连续标识符必须改为简短链接文字、普通解释或纵向信息图；
- 段落是否过长或连续过密；
- 小标题是否帮助扫读而不是制造碎片；
- 图片路径、顺序和图注是否正确；
- 封面和正文图片是否分别记录确认状态。

无法查看真实手机端结果时，不标记为已经确认；把移动端复核留在草稿验收中。

## 交付与验收

交付：

```text
02-公众号文章.md
assets/wechat/
```

检查：

- 标题和摘要是否兑现正文；
- 开头是否迅速建立对象感和阅读理由；
- 正文是否保留基础长文的主线、事实和边界；
- 节奏是否适合手机连续阅读；
- 是否完全不存在围栏代码块、引用块、Markdown 表格、ASCII 排版和横向滚动结构；
- 是否没有参考资料、参考文献、资料来源、脚注、尾注和编号链接列表；
- 是否与其他已生成平台版本形成真实语境差异；
- 共享插图、封面和适配素材是否完整；
- 是否没有新增基础长文之外的实质内容。
