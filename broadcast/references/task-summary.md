# 广播任务总结

每次从完整内部底稿转写平台文章前读取。它定义 `00-广播任务总结.md` 的职责和最小结构。

## 定位

广播任务总结是转写控制单，不是事实来源、知识账本、文章提纲或隐藏母稿。

```text
内部底稿：决定写什么、什么是真的
任务总结：决定对谁写、要产生什么效果、从什么入口进入、各平台怎样呈现
```

四个平台都必须直接读取内部底稿和任务总结。任何平台稿都不能成为另一个平台稿的上游。

## 最小模板

```markdown
# 广播任务总结

- 内部底稿：
- 目标读者：
- 可用于识别主题的术语：
- 可直接参与理解的共同概念：
- 必须先解释或容易误解的概念：
- 关键认知缺口：
- 主要目标效果：
- 传播主线：
- 入口承诺：
- 入口张力：
- 目标平台：
- 风格与作者关系：
- 交付边界：

## 平台侧重点

- 公众号：
- 知乎：
- CSDN：
- 掘金：

## 特别要求

- 只记录用户本次明确提出的偏好、禁区和例外；没有则写“无”。

## 视觉任务

- 共享正文图：
- 平台封面方向：
```

只保留用户选择的目标平台；未选择的平台从“平台侧重点”中删除。

主要目标效果从底稿的公开价值和目标读者任务中推导，选择正确理解、形成判断或推动行动中的一个主要终点。无法判断且不同终点会改变文章主线时才请求用户确认。

平台侧重点同时写清该平台的内容主线、标题任务、封面方向和开头任务。入口张力说明目标读者看到的反常、冲突、变化、损益或未解决问题。只保存已经选定的方向，不保留大批候选标题、样本和封面方案。

## 简洁门禁

- 不复述内部底稿的事实、定义、章节和论证。
- 不建立大型事实清单、知识单元账本或来源映射表。
- 不预写完整开头、正文段落、案例和结尾。
- 传播主线、入口承诺、入口张力和平台侧重点可以点名目标读者能够识别的主题术语，但不得依赖读者已经理解其定义。
- 不把“影响用户心智”“增强传播力”一类不可验收的抽象词当作目标效果。
- 每项尽量一两句话，通常保持一屏左右。
- 如果一句话能够说明，不拆成多条同义规则。
- 复杂的事实覆盖、平台压缩理由、异常和风险进入 `05-验收报告.md`。

任务总结变长时，先删除底稿复述、写作常识、候选方案和重复要求；不能为了缩短而删除主题识别词、共同概念、必须先解释或容易误解的概念、认知缺口、主要目标效果、入口承诺、用户明确的传播主线、平台差异、禁区或授权边界。

## 底稿门禁

生成任务总结前确认：

- 已指定一篇权威内部底稿；
- 底稿能够独立阅读；
- 事实、观点、条件、未知和结论已经收敛；
- 底稿适合公开转写，或者敏感内容已经有明确排除边界。

不满足时停止 `broadcast`。材料零散或结论未收敛时转交 `$lightning`；事实冲突影响核心结论时请求用户确认。不得用任务总结替代底稿整理。

## 向平台层交接

每个平台接收：

```text
权威内部底稿路径：
广播任务总结路径：
目标平台 reference：
本次风格说明：
主要目标效果：
入口承诺与封面方向：
已有共享或平台视觉：
```

平台层可以按阅读任务压缩、展开和重排底稿已有内容，但不能从任务总结推断新事实，也不能加入底稿不存在的案例、经历、数据、观点或运行结果。

平台稿完成后，从底稿重新核对事实与观点，并在 `05-验收报告.md` 记录重要压缩、省略、技术门禁和未决项。任务总结不因验收信息增加而扩写。
