# 能力编排

`broadcast` 负责底稿门禁、传播效果设计、广播任务总结、平台入口、正文转写、视觉信息任务、跨平台一致性和最终验收。公开长文默认调用 `$writing-style`；其他外部能力只在当前任务确实需要时调用。

## 标准流程

```text
完整内部底稿
    ↓
底稿门禁
    ├── 未收敛 → $lightning 或停止
    └── 通过
    ↓
00-广播任务总结.md
    ↓
$writing-style 写作前风格说明
    ↓
按平台设计目标效果、认知缺口和入口承诺
    ├── 真实标题样本校准
    ├── 入口张力与标题候选
    ├── 封面方向
    └── 开头任务
    ↓
按目标平台分别读取底稿、任务总结和平台 reference，形成完整平台稿
    ├── 01-公众号文章.md
    ├── 02-知乎文章.md
    ├── 03-CSDN文章.md
    └── 04-掘金文章.md
    ↓
$writing-style 完整平台稿结构与语言去模板化
    ↓
跨平台事实与观点一致性复核
    ↓
校准并生成平台封面，按需生成正文图
    ↓
平台格式处理 + $writing-style 平台终检
    ↓
入口门、兑现门、效果门与隔离冷读
    ↓
05-验收报告.md + 06-读者测试.md
    ↓ 用户明确授权时
平台专属 Playwright MCP 保存草稿
```

平台之间可以按用户允许的执行方式分别处理，但不得互相读取成稿作为内容上游。共同输入只有内部底稿和广播任务总结。

## 职责边界

| 能力 | 负责 | 不负责 |
|---|---|---|
| `$lightning` | 把零散、冲突或未收敛材料整理为完整内部底稿 | 公开传播、平台适配和发布 |
| `broadcast` | 底稿门禁、目标效果、认知缺口、入口承诺、平台主线、深度、视觉任务、Markdown、跨平台一致性和验收 | 风格档案、平台登录和发布实现 |
| `$writing-style` | 主风格、场景语气、去模板化、身份保护和跨平台人格一致性 | 改变事实、传播主线和平台结构 |
| `$frontend-design` | 精确结构图、信息图、文字型封面和可编辑视觉源 | 决定文章事实和观点 |
| `$canvas-design` | 概念视觉、编辑插画、视觉隐喻和艺术方向 | 承载密集正文和改变内容内核 |
| `$imagegen` | 既定方向下的照片、复杂插画、纹理和位图素材 | 替代信息结构与艺术指导 |
| 平台 Playwright MCP | 页面读取、素材上传、草稿保存和可见状态核验 | 内容重写、获取授权和公开发布 |

## 底稿与任务总结

底稿未达到以下条件时不进入广播：

- 只有一篇明确权威来源；
- 可以独立阅读；
- 事实、观点、条件、未知和结论已经收敛；
- 不依赖 Agent 从零散材料中重新选择事实版本。

需要整理时调用 `$lightning`。不可用或整理后仍冲突时停止，不用广播任务总结补正文。

任务总结只记录可用于识别主题的术语、可直接参与理解的共同概念、必须先解释或容易误解的概念、认知缺口、主要目标效果、传播主线、入口承诺、入口张力、平台侧重点、本次特别要求、视觉任务和授权边界。标题样本、候选与淘汰理由进入验收报告，不扩写任务总结。详细结构读取 [task-summary.md](task-summary.md)。

## 标题研究与选择

标题优化不能只在内部底稿中闭门完成。传播机会或标题吸引力是主要诉求时，读取 [headline-engineering.md](headline-engineering.md)，用同平台、同主题或相邻读者任务的真实样本建立研究包，明确哪些样本有数据、哪些只是平台热门、哪些只是编辑观察。

从可识别对象、未解决张力和读者损益建立标题命题，生成机制不同的候选并执行淘汰门。没有底稿证据时，不借用样本中的热点、人物、数字、实测和极端结论。最终标题与封面、开头和正文共同兑现同一承诺。

## 与 writing-style 协作

写作前提供：

```text
内部底稿：
广播任务总结：
目标平台：
目标读者：
主题与风险：
用户指定风格：
```

接收一个主风格、场景语气、叙述视角、读者关系、应强化和应抑制项。

每篇完整平台稿形成后分别提供全文、对应平台阅读任务、底稿路径、目标效果和风格说明，请求一次结构与语言去模板化。它可以修复机械结构、假洞察、清单堆叠、均匀节奏和身份问题，但不能改变平台主线。收到缺失材料时：

- 底稿中已有：回到底稿取得并补入当前平台稿；
- 底稿中没有且不影响核心结论：缩小或删除对应表达；
- 缺口影响核心结论：停止该平台稿并请求补充底稿。

平台格式和视觉完成后，再提供最终平台稿执行终检，只检查重新引入的套话、机械节奏、身份问题和人格漂移，不重新设计文章结构。不得从另一个平台稿复制缺失材料。

## 视觉路由

封面执行两阶段路由：

1. 写正文前列出每个平台封面的目标读者、入口承诺、信息任务、视觉方向和与标题的分工；
2. 正文完成后根据最终标题和实际内容生成或校准，实际渲染并检查目标尺寸。

封面分别服务各自平台入口，不因正文共享就复制同一封面。封面不得加入正文没有的事件、人物、结果、冲突或权威感。

全部平台正文初稿完成后，再列出每张候选正文图的信息任务、底稿依据、使用平台和阅读宽度。

- 至少两个平台需要解释同一关系时，可以生成 `assets/shared/` 正文图。
- 只有一个平台需要时，生成平台专属图。
- 没有视觉增加理解时，不生成正文图。

精确框架、流程、因果、对比、层级、连续谱、数据和中文文字优先调用 `$frontend-design`。概念视觉、编辑插画和视觉隐喻优先调用 `$canvas-design`。需要照片、复杂插画或纹理时，在既定视觉方向下调用 `$imagegen`。

正式图片必须保留可编辑源或设计说明，实际渲染并查看目标尺寸。正文图片不得加入底稿没有的事实，也不得首次介绍正文尚未解释的核心概念。

## 发布路由

只有本地发布包通过验收、用户明确要求投递，并给出目标平台和草稿边界时调用发布能力。

按 front matter 的 `platform` 选择实例：

| platform | 实例 |
|---|---|
| `wechat` | `publisher_wechat` |
| `zhihu` | `publisher_zhihu` |
| `csdn` | `publisher_csdn` |
| `juejin` | `publisher_juejin` |

缺失实例时按 [dependencies.md](dependencies.md) 和 [publishing-playwright.md](publishing-playwright.md) 自动安装并注册官方 Playwright MCP。需要宿主重载时标记“已安装待重载”，不在当前会话假装可用。

发布前重新读取当前文章文件，不从旧草稿或历史发布包推断内容。每个平台只保存一次；结果不明时先查草稿箱，不自动重复提交。

## 失败与降级

- 底稿不完整或冲突：转 `$lightning` 或停止，不生成任务总结和平台稿。
- 写作风格能力不可用：使用内置通用风格执行同等人工门禁，并记录降级。
- 技术内容门禁失败：跳过 CSDN 或掘金，在 `05-验收报告.md` 记录原因。
- 单个平台内容门禁失败：不影响其他已经通过的平台稿；修正该平台，不创建母稿统一重写。
- 必要视觉能力不可用：保留准确视觉规格，标记对应图文产物未完成。
- 发布能力不可用：保留本地发布包，转人工保存草稿。
- 外部能力试图改变底稿事实：拒绝修改并回到底稿核对。
- 登录、权限、网络或页面适配失败：不自动改用扩展、Token、CLI 或 WebSocket 桥接。
