## 共同上游定位

共同上游由“事实、观点与知识单元账本”和“完整对外母稿”组成。母稿是一篇平台中立、能够从头读到尾的完整公开文章，不是提纲、字段表、入门摘要、内容策划案或待补写的半成品。

无论用户只要求一个平台还是多个平台，都保留：

```text
01-大众基础长文.md
assets/shared/              # 存在共享正文插图时
```

为兼容既有发布包，完整对外母稿继续使用文件名 `01-大众基础长文.md`。大众化只降低理解门槛，不删除专业读者判断结论所需的机制、边界和细节。

所有平台版本共享已经通过门禁的账本和母稿，不能把某个平台稿作为另一个平台稿的上游。公众号可以主动压缩非核心枝节；知乎、CSDN 和掘金必须保留与各自阅读任务相关的完整论证。

## 知识单元账本

在写母稿前，把需要公开传播的内容拆成可检查的知识单元。每个核心单元记录：

```text
名称：
结论或判断：
机制、证据或推理：
易混淆概念：
边界、反例或失败条件：
对实践、选择或判断的影响：
来源项：
平台去向：必须保留 / 可以压缩 / 不适配
```

术语在正文中出现，不等于知识单元已经覆盖。只有目标读者能够理解该单元在文章中的作用，才算有效覆盖。

## 生成顺序

1. 根据事实与观点账本锁定核心结论、边界和不可改变项，并建立知识单元账本。
2. 建立最小读者模型和唯一传播承诺，读取 [reader-continuity.md](reader-continuity.md)，选择文章原型和贯穿全文的具体锚点。
3. 建立段落推进链；用户要求参考现成写作 Skill、样文或方法时，先完成只读方法研究。
4. 按 [orchestration.md](orchestration.md) 调用 `$writing-style`，确定主风格、场景语气和不可改变项。
5. 先写完整正文初稿，不用视觉掩盖尚未讲清的逻辑。
6. 检查每个核心部分是否形成结论、机制、边界和实践影响闭环。
7. 调用 `$writing-style` 执行完整去模板化编辑；不可用时按同一类别人工降级。删除内部讨论痕迹、重复结论、无效铺垫和 AI 套话，并保留问题与修改记录。
8. 收到缺失材料时，先查事实、观点与知识单元账本：输入中已有可靠来源就补回正文；没有支撑就缩小结论或删除对应段落；缺口影响核心结论时停止并请求补充材料。处理后重新执行去模板化编辑。
9. 把抽象判断落到来源支持的场景、动作、例子或后果。
10. 判断哪些关系确实需要视觉解释。
11. 按 [orchestration.md](orchestration.md) 的视觉路由生成必要的共享正文插图，写入图注、替代文字和来源关系。
12. 把插图嵌入正文，执行图文联合阅读。
13. 按 [reader-continuity.md](reader-continuity.md) 执行母稿隔离冷读，修正并复测。
14. 通过母稿门禁后才进入平台重构。

## 正文要求

完整对外母稿必须包含：

- 平台中立的工作标题；
- 让目标读者进入问题的具体开头；
- 清楚且单一的核心判断；
- 连续的论证或叙事推进；
- 已经写入正文的事实、证据、案例和解释；
- 与相关结论就近出现的条件、例外、反例和风险；
- 知识单元账本中标记为核心或不可省略的全部内容；
- 每个核心部分的结论、机制、边界和实践影响；
- 可以独立成立的结尾与读者带走项；
- 必要时，已经生成并嵌入的共享正文插图。

不得出现：

- “此处补案例”“待扩写”“配图位置”等占位；
- 只对作者有意义的讨论历史；
- 任一平台专属的关注、点赞和互动话术；
- 为凑篇幅加入的重复解释；
- 来源不支持的数字、经历、案例和权威背书。

材料不足时保持短而完整。没有材料支撑的段落直接删除或缩短，不用同义改写、抽象意义、假例子和虚构细节补篇幅。无法补齐影响核心结论的事实时停止并请求补充材料。

## 内容深度

每个核心部分至少回答：

1. 结论是什么；
2. 它为什么成立，依赖什么机制、证据或推理；
3. 它不适用于哪里，最容易被误解成什么；
4. 理解后会怎样改变实践、选择或判断。

不要求机械写成四段，可以用案例、流程、代码、对比或作者真实观察完成。以下情况视为深度不足：

- 只给术语定义，不解释怎样工作；
- 只给结论，不说明成立条件和反例；
- 只列能力清单，不说明关系与取舍；
- 只给操作步骤，不解释原因和结果判断；
- 只把原材料改得更口语，却删掉验证结论所需的细节；
- 用字数、标题数或术语数量冒充知识覆盖。

## 写作节奏

优先使用可迁移的长文机制：

- 从读者熟悉的问题、真实场景、已有结果或矛盾进入；
- 按“现象 → 追问 → 判断 → 解释 → 影响”推进；
- 让观点、解释和案例交替出现；
- 每一部分回答一个新问题；
- 检查每个承担论证的段落依据什么材料，或者能否从前文事实直接推导，并说明相比前文增加了什么；没有新增信息时删除或合并；
- 偏离主线后及时扣回；
- 用长短段落、疑问和转场调节阅读速度；
- 结尾回收开头，或交付可复用的判断框架。

这些是通用结构，不是固定模板。不要为了显得有节奏而机械插入金句、疑问、小标题和一句话段落。

## 读者连续性

知识单元账本只负责防止事实和重要内容丢失，不负责决定读者看到内容的顺序。正文围绕一个具体锚点推进，让概念在当前问题需要它时出现；不得把概念分类、能力地图或账本顺序直接翻译成章节顺序。

逐段检查读者已经知道什么、上一段留下什么问题、本段新增什么、依据什么材料、怎样扣回标题承诺，以及下一段为什么自然出现。转场词只能表达已经存在的逻辑关系，不能替代逻辑关系。

第一人称必须落在真实观察、动作、取舍或判断变化上。图片只能解释正文已经建立的内容，不能成为陌生概念的首次入口。完整规则和冷读方法读取 [reader-continuity.md](reader-continuity.md)。

## 共享正文插图

先判断视觉是否能增加理解、记忆或传播价值。

适合在完整对外母稿阶段生成：

- 核心概念对比；
- 流程、因果、层级和连续谱；
- 正文理解不可缺少的信息图；
- 各目标平台都能复用的原始高清图。

每张共享图记录：

```text
用途：
正文位置：
目标画布与阅读宽度：
准确文案：
来源项：
必须保留的限定：
替代文字：
禁止出现：
```

结构、流程、因果、对比、层级、连续谱、框架和精确文字信息图，默认调用 `$frontend-design`，同时保留可编辑 HTML/CSS 或 SVG 与渲染后的 PNG。以视觉隐喻、编辑插画或概念表达为主时，调用 `$canvas-design` 并保留设计说明和 PNG。具体选择以信息任务为准，不以文件所在目录机械决定。

必要图片必须实际生成、嵌入并检查，不能只交付建议。每张图至少经过一次截图视觉批评和修正；只验证代码能运行不算视觉验收。没有视觉能增加价值时记录“无需共享正文插图”，不添加装饰图。

平台封面、裁切比例、清晰度版本和平台排版不属于共享正文视觉，留给平台 reference 处理。

## Markdown 产物

完整对外母稿使用标准 Markdown：

- 一个以 H1 表达的文章主标题；
- 自然段和必要的小标题；
- 引用、列表、强调、链接和脚注按内容需要使用；
- 图片使用相对路径并提供准确替代文字；
- 图注紧随图片，说明用途或来源；
- 避免依赖特定平台才成立的 HTML 样式。

文章本身必须可以直接阅读。读者模型、来源账本和验收过程放入验收报告，不插入正文打断阅读。

## 母稿门禁

逐项确认：

- 脱离原始材料和平台稿后仍能独立阅读；
- 全文只兑现一个传播承诺；
- 知识单元账本中的核心项都有明确去向，没有因追求简短而静默丢失；
- 开头、推进、解释、案例、边界和结尾完整；
- 标题、开头和结尾服务同一主线；
- 有贯穿全文的具体锚点，各部分能够沿读者问题链自然出现；
- 知识单元账本没有直接变成概念目录或分类讲义；
- 抽象判断已经转成普通读者能理解的表达；
- 专业概念首次出现时已经给出入口；
- 每个核心部分已经形成结论、机制、边界和实践影响闭环；
- 每个重要事实和案例可以追溯到来源项；
- 每个承担论证的段落都有已有材料支撑，或者能从前文事实直接推导；只换说法而没有增加信息的段落已经删除或合并；
- 条件、例外、风险和未知没有被传播性压缩删除；
- 已完成去模板化编辑，没有影响阅读的机械结构、空泛套话、均匀节奏、重复总结和伪人类化；
- 每项语言修改都有具体问题和位置记录，已经自然准确的部分保持不变；
- 没有为制造“人味”新增错别字、粗口、情绪、口癖、经历和具体事实；
- 第一人称不是语气外壳，能够追溯到真实材料中的原因、动作、取舍或后果；
- 没有提纲式占位和待补写段落；
- 被判断为必要的共享图片已经生成、嵌入且文字可读，并保留对应可编辑源文件或设计说明；
- 图片已经在目标阅读宽度下完成截图复核，没有落入与主题无关的通用 AI 模板；
- 图片没有引入正文未解释的核心概念、角色或流程；
- 已完成隔离冷读，问题证据、修改动作和复测结论已写入 `07-读者测试.md`；
- 能回答为什么点开、为什么读完、能复述什么、愿意转给谁。

任一项失败时先修复知识单元账本或完整对外母稿。不得依赖平台稿掩盖共同上游缺陷。

## 向平台层交接

向平台 reference 提供：

```text
完整对外母稿文件：
事实、观点与知识单元账本：
读者模型：
传播承诺：
主风格：
去模板化编辑记录：
缺失材料处理记录：
共享正文插图：
已有代码、命令和配置：
不可改变项：
允许压缩或展开项：
```

完整对外母稿的正文 H1 只服务母版独立阅读。平台层选定标题后，将它写入平台稿 front matter 的 `title`，并删除正文 H1；具体规则读取 [platform-markdown-contract.md](platform-markdown-contract.md)。

平台层可以改变阅读路径和格式，也可以重新展开账本和母稿中已经确认的知识单元，但不能改变内容事实。发现目标平台需要的机制、边界或证据尚未进入共同上游时，退回账本和母稿修正并重新执行门禁。
