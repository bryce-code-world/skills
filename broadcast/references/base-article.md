## 产物定位

大众基础长文是一篇平台中立、能够从头读到尾的完整文章。它不是提纲、字段表、内容策划案、平台稿摘要或待补写的半成品。

无论用户只要求一个平台还是多个平台，都保留：

```text
01-大众基础长文.md
assets/shared/              # 存在共享正文插图时
```

所有平台版本只能从已经通过门禁的这一产物重构，不能把某个平台稿作为另一个平台稿的上游。

## 生成顺序

1. 根据事实与观点账本锁定核心结论、边界和不可改变项。
2. 建立最小读者模型和唯一传播承诺。
3. 按 [orchestration.md](orchestration.md) 调用 `$writing-style`，确定主风格、场景语气和不可改变项。
4. 先写完整正文初稿，不用视觉掩盖尚未讲清的逻辑。
5. 调用 `$writing-style` 执行完整去模板化编辑；不可用时按同一类别人工降级。删除内部讨论痕迹、重复结论、无效铺垫和 AI 套话，并保留问题与修改记录。
6. 收到缺失材料时，先查事实与观点账本：输入中已有可靠来源就补回正文；没有支撑就删除或缩短对应段落；缺口影响核心结论时停止并请求补充材料。处理后重新执行去模板化编辑。
7. 把抽象判断落到来源支持的场景、动作、例子或后果。
8. 判断哪些关系确实需要视觉解释。
9. 按 [orchestration.md](orchestration.md) 的视觉路由生成必要的共享正文插图，写入图注、替代文字和来源关系。
10. 把插图嵌入正文，执行图文联合阅读。
11. 通过基础长文门禁后才进入平台重构。

## 正文要求

基础长文必须包含：

- 平台中立的工作标题；
- 让目标读者进入问题的具体开头；
- 清楚且单一的核心判断；
- 连续的论证或叙事推进；
- 已经写入正文的事实、证据、案例和解释；
- 与相关结论就近出现的条件、例外、反例和风险；
- 可以独立成立的结尾与读者带走项；
- 必要时，已经生成并嵌入的共享正文插图。

不得出现：

- “此处补案例”“待扩写”“配图位置”等占位；
- 只对作者有意义的讨论历史；
- 任一平台专属的关注、点赞和互动话术；
- 为凑篇幅加入的重复解释；
- 来源不支持的数字、经历、案例和权威背书。

材料不足时保持短而完整。没有材料支撑的段落直接删除或缩短，不用同义改写、抽象意义、假例子和虚构细节补篇幅。无法补齐影响核心结论的事实时停止并请求补充材料。

## 写作节奏

优先使用可迁移的长文机制：

- 从读者熟悉的问题、真实场景、已有结果或矛盾进入；
- 按“现象 → 追问 → 判断 → 解释 → 影响”推进；
- 让观点、解释和案例交替出现；
- 每一部分回答一个新问题；
- 检查每个承担论证的段落依据什么材料，或者能否从前文事实直接推导，并说明相比前文增加了什么；没有新增信息时删除或合并；
- 偏离主线后及时扣回；
- 用长短段落、疑问和转场调节阅读速度；
- 结尾回收开头，或交付可复用的判断框架。

这些是通用结构，不是固定模板。不要为了显得有节奏而机械插入金句、疑问、小标题和一句话段落。

## 共享正文插图

先判断视觉是否能增加理解、记忆或传播价值。

适合在基础长文阶段生成：

- 核心概念对比；
- 流程、因果、层级和连续谱；
- 正文理解不可缺少的信息图；
- 各目标平台都能复用的原始高清图。

每张共享图记录：

```text
用途：
正文位置：
目标画布与阅读宽度：
准确文案：
来源项：
必须保留的限定：
替代文字：
禁止出现：
```

结构、流程、因果、对比、层级、连续谱、框架和精确文字信息图，默认调用 `$frontend-design`，同时保留可编辑 HTML/CSS 或 SVG 与渲染后的 PNG。以视觉隐喻、编辑插画或概念表达为主时，调用 `$canvas-design` 并保留设计说明和 PNG。具体选择以信息任务为准，不以文件所在目录机械决定。

必要图片必须实际生成、嵌入并检查，不能只交付建议。每张图至少经过一次截图视觉批评和修正；只验证代码能运行不算视觉验收。没有视觉能增加价值时记录“无需共享正文插图”，不添加装饰图。

平台封面、裁切比例、清晰度版本和平台排版不属于共享正文视觉，留给平台 reference 处理。

## Markdown 产物

基础长文使用标准 Markdown：

- 一个文章主标题；
- 自然段和必要的小标题；
- 引用、列表、强调、链接和脚注按内容需要使用；
- 图片使用相对路径并提供准确替代文字；
- 图注紧随图片，说明用途或来源；
- 避免依赖特定平台才成立的 HTML 样式。

文章本身必须可以直接阅读。读者模型、来源账本和验收过程放入验收报告，不插入正文打断阅读。

## 基础长文门禁

逐项确认：

- 脱离原始材料和平台稿后仍能独立阅读；
- 全文只兑现一个传播承诺；
- 开头、推进、解释、案例、边界和结尾完整；
- 标题、开头和结尾服务同一主线；
- 抽象判断已经转成普通读者能理解的表达；
- 专业概念首次出现时已经给出入口；
- 每个重要事实和案例可以追溯到来源项；
- 每个承担论证的段落都有已有材料支撑，或者能从前文事实直接推导；只换说法而没有增加信息的段落已经删除或合并；
- 条件、例外、风险和未知没有被传播性压缩删除；
- 已完成去模板化编辑，没有影响阅读的机械结构、空泛套话、均匀节奏、重复总结和伪人类化；
- 每项语言修改都有具体问题和位置记录，已经自然准确的部分保持不变；
- 没有为制造“人味”新增错别字、粗口、情绪、口癖、经历和具体事实；
- 没有提纲式占位和待补写段落；
- 被判断为必要的共享图片已经生成、嵌入且文字可读，并保留对应可编辑源文件或设计说明；
- 图片已经在目标阅读宽度下完成截图复核，没有落入与主题无关的通用 AI 模板；
- 能回答为什么点开、为什么读完、能复述什么、愿意转给谁。

任一项失败时先修复基础长文。不得依赖平台稿补写或掩盖共同上游的缺陷。

## 向平台层交接

向平台 reference 提供：

```text
基础长文文件：
事实与观点账本：
读者模型：
传播承诺：
主风格：
去模板化编辑记录：
缺失材料处理记录：
共享正文插图：
已有代码、命令和配置：
不可改变项：
允许压缩或展开项：
```

平台层可以改变阅读路径和格式，不能改变内容事实。发现需要新增实质内容时，退回基础长文修改并重新执行门禁。
