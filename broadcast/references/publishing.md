# 草稿投递契约

本文件定义 `broadcast` 与草稿投递入口之间的稳定契约。具体安装与浏览器状态管理读取 [publishing-playwright.md](publishing-playwright.md)，内容渲染与视觉验收读取 [platform-format-contract.md](platform-format-contract.md)。

## 默认边界

没有明确投递要求时，停止在本地发布包：不连接账号、不打开平台后台、不上传素材、不保存草稿、不公开发布。

用户明确要求投递，同时授权为本次任务自动安装和注册来源可核验的官方 Playwright MCP。该授权只覆盖 MCP Server、客户端注册、在用户指定或项目已经声明的登录缓存根目录中创建平台专属 Profile，以及工具重新发现；不覆盖读取日常浏览器 Profile、代替用户完成首次登录或公开发布。

## 支持范围

只处理已经通过 Broadcast 验收的以下产物：

- 微信公众号标准文章；
- 知乎独立文章；
- CSDN 技术文章；
- 掘金技术文章。

不投递公众号卡片、知乎回答、小红书或其他未列入范围的形态。

## 入口要求

目标平台入口必须能够：

- 使用该平台独立且持久化的浏览器 Profile；
- 打开当前平台登录页、编辑器和草稿箱；
- 在当前页面中识别标题、正文、图片和适用的封面、分类、标签字段；
- 保存草稿，并用草稿箱中的可见结果区分“已填写”和“已持久化”；
- 说明失败阶段、是否可能已创建草稿以及能否安全重试；
- 遇到未覆盖字段时明确转人工处理，不静默丢失。

平台页面会变化，不把长期选择器写进 Broadcast。每次投递都读取当前页面的可访问性树或等价结构，再定位字段。

## 入口选择

1. 只调用目标平台的专属 Playwright MCP 实例：`publisher_wechat`、`publisher_zhihu`、`publisher_csdn` 或 `publisher_juejin`。
2. 实例缺失时，按 [publishing-playwright.md](publishing-playwright.md) 自动安装官方包并注册四个独立实例，不重复请求安装确认。
3. 安装后重新发现工具并检查来源、固定版本、真实 schema、启动状态与 Profile 路径。需要宿主重载时停止在“已安装待重载”。
4. 官方 Playwright MCP 无法安装、连接或可靠操作当前页面时，交付人工发布包；不自动切换到其他浏览器扩展、Token、CLI 或 WebSocket 桥接。

## 单平台投递流程

每个平台独立执行，不能用一个平台的成功推断其他平台成功：

1. 确认目标账号、文章文件、素材目录和只保存草稿的授权边界。
2. 运行平台标题检查器，确认 front matter 只有一个 `title`，正文没有 H1。
3. 确认对应 Profile 没有被其他会话或浏览器进程占用。
4. 打开平台后台并检查登录状态。首次登录或登录失效时停在登录页，等待用户本人扫码、验证码或确认。
5. 打开新建文章页面，核对当前页面字段后再填写标题、正文、图片和平台适用字段。
6. 保存一次草稿，不点击发布、群发、定时发布或提交审核。
7. 打开草稿箱或草稿详情，核验标题、正文开头、图片及适用字段。
8. 按 [platform-format-contract.md](platform-format-contract.md) 检查目录、标题样式、段落、图片、代码和适用终端呈现；微信公众号必须确认无不必要目录、无蓝底标题块且移动端节奏正常。
9. 记录内容确认、排版确认和未决项，释放该平台实例后再处理下一个平台。

同一篇文章在同一平台只提交一次。超时、页面跳转异常或返回状态不清楚时，先查询草稿箱；在确认没有草稿前不得重试。

## 状态

只使用与证据一致的状态：

| 状态 | 含义 |
|---|---|
| 已生成发布包 | 本地内容和素材完成 |
| 已安装待重载 | MCP 配置完成，当前会话尚未重新发现工具 |
| 待首次登录 | 专属 Profile 可用，用户尚未完成平台登录 |
| 预检通过 | 工具、Profile、登录、账号和素材检查通过 |
| 已填写 | 编辑器已填入内容，尚未证明平台保存成功 |
| 已保存草稿 | 草稿箱或草稿详情出现可见草稿 |
| 草稿内容已确认 | 标题唯一，正文从导语开始，适用字段逐项确认 |
| 草稿排版已通过 | 已打开真实草稿检查平台渲染，目录、标题、段落、图片、代码和适用终端阅读均符合格式契约 |
| 需人工处理 | 草稿存在，但仍有封面、裁切、分类、标签或排版待处理 |
| 待人工发布 | 自动入口不可用，本地发布包完整 |
| 失败 / 未知 | 草稿不存在，或是否创建无法确认 |
| 已公开发布 | 仅在用户另行明确授权且存在公开页面证据时使用 |

MCP 调用成功、页面点击成功和编辑器出现内容都不等于“已保存草稿”；草稿可见也不等于“草稿排版已通过”。无法查看真实草稿时，写“草稿已保存，排版未验收”。

## 安全与并发

- Profile 根目录必须由用户指定或由项目明确声明，并专用于发布登录态；位于 Git 工作区时必须在首次启动浏览器前加入精确忽略规则。Profile 内容不得进入 Git、发布包或日志。
- 不读取或复用用户日常 Chrome、Edge Profile，不复制 Cookie，不要求账号密码。
- 四个平台各用一个独立 Profile；同一 Profile 同时只允许一个 MCP 浏览器实例。
- 发现同平台 Profile 被占用时等待或停止，不结束未知会话、不删除锁文件、不创建第二份重复草稿。
- 日志只记录平台、阶段、状态和非敏感证据，不记录 Cookie、Token、二维码、验证码或完整页面存储。
- 用户只要求草稿时，任何“发布”“群发”“提交审核”“定时发布”控件都属于禁区。

## 失败处理

| 情况 | 处理 |
|---|---|
| MCP 未安装 | 自动安装和注册，随后重新发现工具 |
| 需要宿主重载 | 标记“已安装待重载”，本轮停止投递 |
| Profile 被占用 | 等待占用释放或停止该平台，不强制解锁 |
| 首次登录或登录失效 | 打开有头浏览器等待用户本人完成登录 |
| 页面字段变化 | 重新读取当前页面结构；无法可靠定位时停止 |
| 保存结果不明确 | 先查草稿箱，不自动再次保存 |
| 草稿已保存但格式不合格 | 保留草稿，修正源稿或渲染方式后覆盖同一草稿，不创建重复草稿 |
| 某个平台失败 | 保留该平台准确状态，继续处理不依赖它的其他平台 |
| 所有入口不可用 | 交付完整人工发布包 |
