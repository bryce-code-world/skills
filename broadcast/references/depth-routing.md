# 内容深度路由

完成 [content-routing.md](content-routing.md) 后、生成广播任务总结前读取。只在本文件确定内容拓扑、阅读方式、知识单元角色和平台输出形态；平台 reference 只消费结果。

## 识别内容拓扑

只选择一种主要拓扑：

| 内容拓扑 | 识别依据 | 默认处理 |
| --- | --- | --- |
| 单命题 | 一个问题、结论或方法能够独立完成主要目标效果 | 单篇完整展开 |
| 多模块全景 | 多个相互依赖的知识单元共同构成认知地图，删除任一核心模块都会破坏全貌 | 优先单篇深度长文；无法保持可读性时提出有总入口的系列 |
| 双主线 | 两个相邻问题域都影响最终判断，各自需要独立证据和推理 | 同一总命题能够统领时并列深展；否则提出两篇并明确关系 |

题目字数、标题数量和术语数量不能直接决定拓扑。检查：

- 删除哪个单元会改变标题承诺或主要目标效果；
- 单元之间是前置依赖、并列分支、因果链还是查询关系；
- 每个单元是否需要独立证据、反例、机制、步骤或案例才能成立；
- 全部单元是否仍由一个总命题统领。

一篇文章只保留一条传播主线，但总命题下可以有多个不可缺少的知识分支。“一条主线”不得被解释为每个分支只能保留一段摘要。

## 判断阅读方式

只选择一种主要阅读方式：

- 连续阅读：依靠前后推进完成理解、判断或行动；
- 参考查询：主要价值在长期检索、比较、复用或评审，需要稳定标题层级和完整知识单元。

阅读方式决定信息顺序和导航强度，不决定文章必须长或短。

## 标记知识单元

只记录名称、角色、依赖和平台去向，不复制底稿正文：

| 角色 | 判断 | 处理 |
| --- | --- | --- |
| 核心知识单元 | 缺失后标题承诺或主要目标效果不成立 | 必须完整展开 |
| 支撑知识单元 | 提供证据、反例、机制、应用或过渡 | 按平台调整密度 |
| 延伸知识单元 | 删除后当前命题仍然成立 | 省略、下沉或进入后续篇 |

核心知识单元的“完整展开”不要求固定段落，但至少让目标读者获得当前命题所需的结论、成立依据、重要边界和实践影响。底稿已有案例、反例、数据、推导、步骤或验证时，优先保留能形成独特理解和复用价值的材料。

## 选择平台输出形态

按以下顺序决定：

1. 先确定标题和入口承诺需要哪些核心知识单元；
2. 再选择单篇深度长文、平台聚焦篇、系列或微信精华版；
3. 最后压缩转场、重复解释、实现枝节和延伸知识；
4. 压缩后回查标题，无法兑现时缩小命题、恢复核心单元或提出拆篇。

默认每个平台只生成一篇文章。需要系列时，先向用户提供拟拆分命题、文章数量、共同关系和每篇核心单元；用户确认后，每篇进入独立主题目录和广播任务。不得静默增加发布文章数量。

知乎、CSDN 和掘金不设默认 3000 字上限。底稿能够支撑且读者有深度阅读任务时，优先保留完整证据、推理、边界和应用。

微信公众号可以减少过深实现、次级分支和延伸材料，但必须保留核心结论、关键证据、最短完整推理链、主要边界，以及至少一个可迁移判断或应用方式。无法同时保留时，缩小微信命题或提出拆篇。

## 识别均匀削薄

字数只提供异常线索，不直接判定深度。

多模块全景、双主线或参考查询稿虽然点到了所有核心单元，但每个单元只剩定义或结论时，判定为均匀削薄。标题承诺“全景、完整架构、系统路线”而正文只给概览时，判定为承诺未兑现。

修正顺序：

1. 恢复核心单元的依据、边界和实践影响；
2. 删除重复转场、泛化铺垫和延伸知识；
3. 仍然无法保持可读性时缩小标题；
4. 多个命题都必须保留时提出系列并等待确认。

## 向下游交接

把以下结果写入 `00-广播任务总结.md`：

```text
内容拓扑：单命题 / 多模块全景 / 双主线
阅读方式：连续阅读 / 参考查询
核心知识单元：名称、依赖、各平台去向
支撑知识单元：名称、用途、各平台去向
延伸知识单元：名称、各平台去向
平台输出形态：单篇深度长文 / 平台聚焦篇 / 系列 / 微信精华版
```

标题、开头、正文、平台规则和验收必须消费同一结果，不得在平台层重新统一压缩。
