# 四平台格式与真实草稿验收契约

本文件定义微信公众号、知乎、CSDN 和掘金共享的视觉骨架、平台渲染方式和真实草稿验收。生成平台稿、准备投递或检查草稿时读取。

## 三层格式契约

依次完成：

1. **语义结构**：Markdown 正确表达标题层级、自然段、列表、图片、平台允许的图注、代码和提示关系。
2. **平台渲染**：根据目标编辑器能力，把语义转换为能稳定保存的原生结构或富文本。
3. **真实草稿视觉验收**：执行投递时打开真实草稿，检查实际字号、颜色、间距、目录、换行、图片、代码和目标终端呈现。

只生成本地发布包时完成前两层，把第三层记录为“待投递验收”。未投递不影响本地内容产物完成，但不得报告“草稿排版已通过”。

## 入口传播组合

标题和封面不是排版附件。写正文前先确定入口承诺、标题假设和封面信息任务；平台稿完成后，再用最终内容校准并生成封面。

本地封面验收至少检查：

- 缩略图中能够感知清楚的情绪、场景、对象或风格以及主要视觉层级；主题可以由标题承担；
- 标题与封面互相补充，没有重复堆满同一句话；
- 开头立即承接标题和封面承诺；
- 文本在目标尺寸可读，主体和关键信息不会被常见裁切破坏；
- 没有正文不存在的事件、人物、结果、冲突或权威标识。

真实平台缩略图、推荐流裁切和草稿呈现只在实际投递后验收。本地渲染通过不能替代真实平台视觉检查。

## 统一视觉骨架

四个平台共享“克制编辑感”：

- 白色或接近白色背景，深灰正文；
- 暖琥珀或棕色只用于小面积编号、细线和浅提示，不铺大色块；
- 用标题层级、短编号、细分隔线和留白建立节奏；
- 封面、正文信息图和编号方式保持同一作者识别度；使用图注的平台让图注服从同一视觉层级；
- 不使用通用渐变、大面积蓝底标题、卡片堆叠和无关装饰图标；
- 不为复刻视觉而把正文文字截图化，也不依赖平台不稳定的复杂 HTML。

平台不支持自定义样式时，优先保住语义层级和阅读节奏，退回平台原生样式。

## 微信公众号

### 内容结构

- 默认不生成目录，也不写“本文将介绍”式导航；
- 只有超长工具书、手册或明确依赖跳读的参考型文章可以使用目录；
- 目录启用时使用轻量文本导航，不使用蓝底、卡片或大色块；
- 正文最高使用二级标题，三级标题只在确有从属关系时使用；
- 小标题数量由内容关系决定，不把每两三段切成一个标题。

### 富文本基线

Markdown 是内容真相源，投递时转换为移动端稳定富文本。使用以下范围，不要求所有编辑器逐像素一致：

| 元素 | 基线 |
|---|---|
| 正文 | 15–16px，行高 1.75–1.9，深灰色，左对齐 |
| 二级标题 | 18–20px，半粗或加粗，深灰色，无填充背景，可带小号暖色编号或底部细线 |
| 三级标题 | 16–17px，半粗，深灰色，不使用色块 |
| 段间距 | 约一行正文高度，避免连续密墙和大量空行 |
| 提示 | 极浅暖色背景或左侧细线，小面积使用，不替代正文论证 |
| 图片 | 宽度适应正文栏，前后留白，不添加独立图注 |
| 强调 | 少量加粗或暖色短语，不整段变色，不连续高亮 |
| 列表 | 与正文同字号、同一行高区间；平台原生列表压缩时改用正文级编号或项目段落 |

不得接受平台或 Markdown 导入器自动产生的大面积蓝底标题。无法控制富文本时，宁可使用普通深色标题和留白，也不用默认蓝色模块。

强调不是装饰。Markdown 中的加粗应来自 `writing-style` 对核心判断、关键转折、选择标准和记忆锚点的语言层检查；`broadcast` 决定它是否符合公众号阅读任务；`distribution` 只负责准确渲染，不在投递时临时增加重点。

### 移动端验收

- 首屏自然进入问题，不被目录、摘要框或大色块占满；
- 标题、段落、列表和图片在手机宽度下不横向滚动；
- 段落不过密，小标题不碎片化；
- 二级标题左对齐、深色加粗，并通过字号和留白形成可扫读分段；
- 重点锚点少量、准确，读者能够在扫读时识别关键判断；
- 列表项与正文同字号、同一行高区间，不出现缩小、挤压和异常缩进；
- 图片文字可读，裁切和顺序正确，图片后没有独立图注；
- 没有蓝底标题块、重复标题和不必要目录；
- 作者真实观察和思考没有被排成课程讲义或媒体模板。

## 知乎

- 使用平台原生标题、自然段、列表、图片和少量强调；
- 通常不手写目录，依靠清楚的标题层级支持跳读；
- 不用自定义色块、复杂 HTML 或公众号式富文本装饰；
- 图片紧邻相关论证并配准确图注；
- 验收命题、推理、反对意见和边界是否能沿标题层级连续阅读。

## CSDN

- 使用平台原生 Markdown、代码块、标题锚点和自动目录能力；
- 不手写与自动目录重复的目录；
- 环境、命令、代码和结果说明保持相邻；
- 代码块语言、换行、缩进和长行在常见桌面阅读宽度下可读；
- 不用富文本色块包装技术结论，不把公众号样式复制到技术文档。

## 掘金

- 使用平台原生 Markdown、代码块、标题层级和简洁分隔；
- 不手写重复目录；
- 代码与设计理由、关键取舍和结果说明相邻；
- 不用复杂富文本破坏工程叙事连续性；
- 验收长代码、图片、列表和小标题在编辑器与草稿详情中的实际呈现。

## 真实草稿验收交接

本文件只定义真实草稿应满足的视觉和格式条件。草稿、发布和结果未知等外部状态及其证据由 `$distribution` 的 `delivery-contract.md` 统一定义。

执行分发时，只有重新打开真实草稿，并确认目录、标题、段落、图片、代码和适用终端阅读均符合本契约，才能把状态提升为 `draft_verified`。编辑器接收内容、自动保存提示或浏览器调用成功都不能证明排版通过。

排版不符合契约时保留草稿，把内容或渲染问题返回上游；获得覆盖授权后只修改同一草稿，不创建重复草稿，也不为修正排版触发公开发布。
