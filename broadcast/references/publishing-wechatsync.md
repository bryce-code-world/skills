# Wechatsync 发布适配

本文件只负责把已经验收的平台发布包交给官方 Wechatsync。内容设计、事实判断、风格和平台转译仍由 `broadcast` 负责。

当前能力以 [Wechatsync 官方仓库](https://github.com/wechatsync/Wechatsync) 为准。平台、命令和接口会变化，实际投递前必须重新核对官方文档和当前环境。

## 授权边界

默认不执行任何外部操作。

只有用户明确给出以下信息后才开始预检：

- 要投递的平台；
- 使用的账号或浏览器登录环境；
- 只保存草稿，还是存在进一步动作；
- 准确的成稿和素材；
- 是否允许配置或启动缺失组件。

“帮我写”“生成发布稿”“适配多个平台”不等于授权投递。

没有额外明确授权时：

- 不安装 CLI、扩展或 Skill；
- 不配置或读取 Token；
- 不打开远程端口或桥接；
- 不登录账号；
- 不上传图片；
- 不保存草稿；
- 不公开发布。

## 选择官方入口

使用当前环境已经可用、最直接的官方入口：

1. 已安装的官方 Wechatsync Skill；
2. 已连接的 Wechatsync MCP；
3. 已安装且已经连接扩展的 Wechatsync CLI；
4. 用户可操作的 Wechatsync 浏览器扩展；
5. 无可用入口时，交付人工发布包。

不要在 `broadcast` 中复刻登录、图片上传、平台 API、重试或发布脚本。

不要仅凭文件存在就声称入口可用。必须实际检查命令、工具连接和平台登录状态。

用户已经明确要求投递，但官方 Wechatsync Skill 缺失时，按 [dependencies.md](dependencies.md) 展示准确来源并单独请求安装确认。

该确认只允许安装 Skill。CLI、浏览器扩展、Token、平台登录和本次投递继续分别确认。

## 发布前预检

逐平台确认：

```text
平台：
账号或登录环境：
目标形态：
标题：
正文文件：
封面：
插图或图卡：
四重验收：
授权动作：
```

然后检查：

- Wechatsync 入口可调用；
- 浏览器扩展已经连接；
- 目标平台处于已登录状态；
- 文件路径和素材可读；
- 标题、正文和素材对应同一平台版本；
- 内容没有未解决的事实 TODO；
- 当前入口能够承载目标形态。

逐项记录当前发布入口和目标平台适配器的字段能力：

```text
标题：支持 / 不支持 / 未确认
摘要：支持 / 不支持 / 未确认
正文：支持 / 不支持 / 未确认
正文图片：支持 / 不支持 / 未确认
封面：支持 / 不支持 / 未确认
```

命令、MCP schema 或界面存在某个参数，只能证明入口接收该字段，不能证明目标平台适配器已经应用。首次投递、入口升级或平台适配器变化后，应结合当前文档、实现、预览或真实草稿重新确认。

明确不支持但可以人工补充的字段，不必阻止保存草稿；投递前必须告知用户，并把它保留为人工处理项。正文或目标形态无法可靠承载时停止自动投递。

若某种图卡或平台编辑器能力不能由当前入口稳定承载，停止该平台自动投递，保留完整人工发布包。

## 使用 CLI

只有 CLI 已安装、扩展已连接、Token 已由用户配置且用户授权时才运行。

先检查：

```text
wechatsync platforms --auth
```

如果当前版本支持，先使用预览：

```text
wechatsync sync <article.md> -p <platform> --dry-run
```

确认预览和目标无误后再保存草稿：

```text
wechatsync sync <article.md> -p <platform>
```

平台 ID 以当前 `wechatsync platforms` 和官方文档为准。不得把旧清单当作永久事实。

## 使用 MCP

优先调用只读工具检查平台和授权状态，再调用草稿同步工具。

当前官方 MCP 文档中的核心能力包括：

- `list_platforms`：列出平台和登录状态；
- `check_auth`：检查指定平台登录状态；
- `sync_article`：把文章保存为草稿；
- `upload_image_file`：按需上传本地图片；
- `extract_article`：从当前浏览器页面提取文章。

调用前核对当前已连接工具的真实 schema，不根据本文猜参数。

图片只有在目标发布包需要且用户授权上传时才上传。记录本地文件、目标平台和返回地址的对应关系。

## 安全要求

- 不在日志、文档或回复中回显 Token、Cookie 和凭据；
- 不把 Token 写入 Skill 或发布包；
- 不替用户创建或修改登录凭据；
- 不把草稿链接误报为公开链接；
- 不因一个平台成功而假定其他平台成功；
- 失败后不盲目重复提交，先确认是否已经生成草稿。

官方文档说明远程桥接的 Token 可能明文传输。除非用户明确授权并已使用 SSH 隧道、VPN 或等价保护，否则不建立远程桥接。

## 逐平台投递

即使工具支持多平台参数，也按平台记录独立状态：

```text
平台：
开始前登录状态：
提交内容版本：
动作：
结果：
草稿链接或记录：
失败原因：
是否可能已经创建草稿：
下一步：
```

高风险或首次投递时优先逐个平台执行，避免一个错误同时污染多个草稿箱。

重试前先查询或让用户检查草稿箱。无法确认幂等性时，不自动重试。

## 草稿落地验收

工具返回成功只证明其明确返回的结果，不自动证明草稿字段完整或移动端呈现正确。

投递后逐项核对：

```text
正文：
正文图片：
封面：
移动端呈现：
草稿状态：
公开发布：
人工处理：
```

可以通过安全入口查看真实草稿时，核对标题、摘要、正文、图片顺序、封面和目标平台呈现。无法查看时，把对应字段标为“未确认”，不得根据命令参数或上传日志推断已经落地。

草稿已经创建但字段缺失时，保留草稿并报告人工处理项，不自动重复投递。用户反馈草稿状态后，按最新事实更新记录。

## 状态词

只使用与证据一致的状态：

| 状态 | 含义 |
|---|---|
| 已生成发布包 | 仅本地内容完成 |
| 预检通过 | 工具、登录和素材检查通过 |
| 预览通过 | 只完成 dry-run 或等价预览 |
| 已提交 | 工具接受请求，尚未确认草稿 |
| 已保存草稿 | 有工具结果或草稿证据 |
| 草稿内容已确认 | 目标平台中的关键字段已经逐项确认 |
| 需人工处理 | 草稿存在，但仍有平台字段或呈现需要人工完成 |
| 已公开发布 | 只有用户明确授权且有公开页面证据时使用 |
| 失败 / 未知 | 记录准确阶段和是否可能产生副作用 |

## 降级

遇到以下任一情况，停止对应平台自动投递并交付人工发布包：

- 未获明确授权；
- 官方入口不存在或不可连接；
- 登录状态失效；
- 当前入口不支持目标形态；
- 素材上传失败；
- 工具结果无法判断是否创建草稿；
- 需要安装、配置凭据或改变网络暴露面但未获授权。

降级不影响已经完成的内容产物。报告缺失条件，不尝试绕过。
