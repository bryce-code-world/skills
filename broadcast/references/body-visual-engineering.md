# 正文视觉工程

正文图服务解释传播。它必须比对应正文更快地建立关系、层级或调用路径，不能只是把段落压进卡片和箭头。

## 先定义信息任务

生成正文图前，写清：

```text
读者看图前已经知道什么：
看图后必须多理解什么：
第一阅读层级：
第二阅读层级：
可以省略的说明：
使用平台与最窄阅读宽度：
```

一张图只承担一个主要信息任务。无法用一句话说明新增理解时，不生成图片。图片不得首次引入正文尚未解释的核心概念。

## 先压缩信息，再设计版面

1. 从底稿提取完整关系，不直接把段落逐句搬入画布；
2. 确定一条第一阅读主线，其他内容只作为节点、证据或注释；
3. 按阶段、责任、因果或读者任务合并同类节点；语义节点数量不等于卡片数量；
4. 标题负责命名，短语负责补充作用，正文负责完整解释；不要让每个节点同时承载编号、标题、完整句和说明标签；
5. 当关系必须依靠密集小字才能成立时，拆成两张图、改为正文列表或取消图片，不通过缩小字号硬塞。

默认不把所有节点画成同尺寸、同颜色、同信息量的等重卡片。只有节点确实同级、读者需要逐项比较时才使用等重布局。

## 选择与关系匹配的结构

- 顺序与状态变化：使用单一主轴，回流线沿内容外缘返回，不穿过文字或侵占卡片宽度；
- 责任与系统边界：优先使用责任区、泳道或分层，而不是为每个步骤复制一张卡片；
- 对比：只保留共同维度，避免两侧分别堆成长段；
- 层级：用位置、尺寸和留白建立父子关系，不依赖更多边框；
- 因果：区分主因、机制和结果，不让装饰连线冒充关系；
- 数据：图形承担比较，文字只保留名称、单位和必要注释。

精确流程、框架、因果、对比、层级、数据和中文文字优先使用原生可编辑图形能力。生成式图片不负责精确中文排版、节点对应和连线关系。

## 建立阅读层级与空间秩序

- 第一阅读层级只保留核心对象和核心关系；读者不读次级说明也能理解图意；
- 第二阅读层级解释节点作用，字号、颜色和位置明显弱于主标题；
- 装饰不得与标题、节点和方向争夺注意；
- 标题区、内容区和结论区保留可感知的间隔，不用巨大标题制造下方拥挤；
- 文本与边框、编号、图标和连线保持稳定内边距；
- 反馈、注释和跨区连线优先放在内容外缘；空间不足时先压缩信息，不先压缩字体；
- 颜色用于表达责任、状态或分组，不用换色掩盖层级缺失。

## 执行最窄阅读宽度门禁

正式图片必须查看原尺寸和实际使用平台中的最窄代表宽度。包含公众号时至少查看约 360 像素宽的等比例结果；同时服务多个平台时，以最窄正文栏作为共同门禁。

只看缩略正文图，在五秒内回答：

1. 第一眼看到的核心对象是什么；
2. 主关系或阅读方向是什么；
3. 哪些内容是次级说明；
4. 是否需要放大、逐字阅读或追踪复杂连线才能理解。

出现以下任一情况即失败：

- 只能辨认节点名称，却不能快速说出核心关系；
- 必须放大后才能读取第一层信息；
- 所有节点视觉等重，读者不知道先看哪里；
- 每个节点都塞入编号、长标题和完整说明，文字贴边或彼此争抢；
- 连线、回路、图例或装饰挤占文字宽度、穿过内容或制造错误方向；
- 画布存在大片无任务留白，而有效内容仍然拥挤；
- 验收理由只有“文字可识别”“节点齐全”或“尺寸正确”。

第二层说明可以在缩略状态下降权，但不得模糊、截断或成为理解核心关系的必要前提。

## 批评、修正与记录

生成后执行一次针对正文图的视觉批评，分别检查信息压缩、第一阅读层级、空间秩序和最窄宽度冷读。发现失败项时，优先按以下顺序修正：

1. 删除重复说明；
2. 合并同类节点；
3. 重建责任区或主轴；
4. 移出反馈线、图例和注释；
5. 调整画布比例、字号和细节。

修正后重新查看原尺寸和最窄宽度。`05-验收报告.md` 只记录最终结构、尺寸、代表宽度和通过结论，不保存初稿、轮次和废弃布局；实际冷读问题、修改动作和复测结论进入 `06-读者测试.md`，过程历史交给 Git 和任务日志。没有独立读者时，只能写“设计自检完成，未独立验收”。
