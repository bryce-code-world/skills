# 广播

把已经想清楚的内容完成为大众愿意读、能够理解、值得传播的长图文。

## 遵守质量顺序

按以下顺序处理，后项不能破坏前项：

1. 事实和原意准确。
2. 核心知识单元完整且有足够深度。
3. 普通读者能够理解。
4. 内容确实值得读。
5. 具备自然传播力。
6. 风格稳定且适合场景。
7. 符合目标平台的长文语境。
8. 视觉与排版增强理解。

不得为标题、情绪、故事、节奏或平台感改变事实、观点强度、条件和适用边界。

## 维护版本与依赖

每次触发时读取 [dependencies.md](references/dependencies.md)，按其中的 24 小时规则执行非阻塞自身更新检查。

更新检查失败或发现新版本时继续当前内容任务，只在交付时报告。公开长文默认需要 `$writing-style` 执行风格说明和去模板化门禁；其他能力只在当前任务确实需要时检查对应依赖。

## 守住范围

正式支持：

- 平台中立的完整对外母稿；
- 微信公众号标准文章；
- 知乎独立文章；
- 通过技术内容准入门禁的 CSDN 技术文章；
- 通过技术内容准入门禁的掘金技术文章；
- 上述长文的共享正文插图、平台封面和带格式 Markdown；
- 已有公开长文的读者对象感、传播主线和平台节奏优化。

不处理公众号卡片、小绿书、知乎回答、小红书、短视频、音频、海报和其他非长文章形态。用户提出这些请求时说明当前边界，不用相邻能力勉强模拟。

默认只生成本地产物。没有明确投递授权时，不连接账号、不上传素材、不保存草稿、不公开发布。

## 判断输入能否转译

输入满足以下条件时直接开始：

- 主题、核心结论和重要事实清楚；
- 事实、观点、条件、未知和采用状态可以区分；
- 目标是公开传播，而不是继续整理内部材料。

输入仍然零散、冲突或结论未收敛时，使用 `$lightning` 整理。不可用时按 [dependencies.md](references/dependencies.md) 处理；事实仍不清楚时停止公开转译，不替用户选择事实版本。

内容短或材料有限时保持短而完整，不凭空补充案例、数据和经历。

## 建立事实、观点与知识单元账本

写作前内部记录：

- 主题、核心结论和作者立场；
- 事实、数据、来源、归属和时间范围；
- 观点与事实的区别；
- 条件、例外、风险、未知和确认状态；
- 作者真实拥有的经历和观察；
- 可以压缩、解释或重排的内容；
- 不得改变的术语、名称和表达强度。

把需要进入公开文章的内容拆成知识单元。每个核心知识单元至少记录：

- 结论或判断；
- 成立机制、证据或推理；
- 易混淆概念、适用边界、反例或失败条件；
- 对读者理解、选择或实践的影响；
- 必须保留的平台和允许压缩的平台。

逐项记录“来源项 → 知识单元 → 对外母稿位置 → 平台去向”。每项只能准确保留、移入可访问的附录或权威链接，或者明确标为未知、争议和待确认。不得静默省略，不得把术语出现次数或统一字数当作覆盖证明，不得把推断写成事实，不得编造第一人称经历。

## 执行强制流程

1. 读取输入、目标读者、目的、目标平台和授权边界。
2. 判断是否需要先由 `$lightning` 收敛内容。
3. 建立事实、观点与知识单元账本、最小读者模型和单一传播主线。
4. 读取 [reader-continuity.md](references/reader-continuity.md)，选择有材料支撑的文章原型和贯穿全文的具体锚点；用户要求参考现成写作 Skill、样文或方法时，先执行其中的只读方法研究。
5. 调用 `$writing-style` 解析主风格和场景语气；不可用时使用通用默认风格并记录降级。
6. 读取 [base-article.md](references/base-article.md)，按段落推进链生成完整对外母稿。为兼容既有发布包，文件名继续使用 `01-大众基础长文.md`。
7. 调用 `$writing-style` 执行完整去模板化编辑；不可用时按同一门禁人工降级。收到缺失材料时，补入输入中已有的可靠材料、缩小结论，或者停止并请求补充影响核心结论的材料；处理后重新执行本步骤。未通过时不进入视觉和平台层。
8. 判断正文视觉是否真正增加理解；必要时按视觉任务调用 `$frontend-design` 或 `$canvas-design`，生成共享正文插图并嵌入完整对外母稿。
9. 完成母稿图文、内容深度和隔离冷读门禁。未通过时先修复共同上游，不生成平台稿。
10. 按用户指定的平台读取对应 reference；CSDN 和掘金先执行技术内容准入门禁，再结合知识单元账本和同一完整对外母稿重构带格式 Markdown。
11. 调用 `$writing-style` 执行平台稿语言终检，只修正平台改写重新引入的问题；不可用时人工降级。
12. 读取 [platform-markdown-contract.md](references/platform-markdown-contract.md) 和 [platform-format-contract.md](references/platform-format-contract.md)，运行当前系统的原生标题检查器。平台稿缺少 front matter 标题、正文含 H1、首段重复标题、正文为空或违反平台格式契约时不得继续。
13. 按封面的信息任务调用 `$canvas-design` 或 `$frontend-design`，生成平台封面和必要的裁切或清晰度版本。
14. 按 [reader-continuity.md](references/reader-continuity.md) 对平台终稿执行隔离冷读，修正后复测并写入 `07-读者测试.md`。
15. 执行事实、深度、传播、风格、平台和源稿格式六项验收。公众号和知乎出现围栏代码块、引用块、Markdown 表格、ASCII 排版或横向滚动结构时不得交付；CSDN 和掘金按受控代码块规则检查。所有公开正文出现文末参考资料章节时不得交付。格式和文字形状检查不得替代冷读证据。
16. 交付完整对外母稿、目标平台稿、素材、验收报告和读者测试。
17. 只有用户明确授权投递时，才按 [publishing.md](references/publishing.md) 调用目标平台专属 Playwright MCP；实例缺失时自动安装官方 MCP、注册独立持久化 Profile、重新发现并检查能力，再处理草稿。

无论用户只要求一个平台还是多个平台，都必须保留完整对外母稿这一正式产物。不得绕过知识单元账本和母稿直接生成平台稿。

## 建立读者与传播主线

使用完成本次写作所需的最小读者模型：

```text
读者是谁：
已经知道什么：
最关心什么：
最容易误解什么：
读完应获得什么：
希望采取什么动作：
```

只保留一个主要传播承诺：

```text
读者为什么要点开：
为什么值得读完：
读完能复述什么：
愿意转给谁：
```

首次出现专业概念时，优先采用“通俗定义 → 为什么重要 → 准确名称”。例子、类比和故事只能解释已有内容，不能成为新的证据。

读者模型和传播承诺确定后，按 [reader-continuity.md](references/reader-continuity.md) 建立段落推进链。知识单元账本是后台覆盖工具，不得直接变成正文目录或概念清单。

## 处理风格

按以下顺序选择主风格：

```text
用户本次明确指定
        ↓ 没有
用户默认个人档案
        ↓ 没有
广播通用默认风格
```

每次公开长文都使用 `$writing-style`，并按其广播集成契约执行写作前说明、完整对外母稿去模板化和平台稿语言终检。没有个人档案时由它使用内置通用默认风格，不因此跳过。

不可用时使用通用默认风格，并由 `broadcast` 按同一问题类别执行最小编辑和内容内核检查，记录“writing-style 不可用”的降级。不得省略门禁。

可以吸收具体场景进入、现象到本质递进、观点与案例交替、偏离后扣回主线、长短段落调节和结尾回收等通用机制。不得复制其他作者的身份、人格、标志性口癖、固定标题或签名结构。

第一人称只用于作者真实拥有的观察、判断过程、犹豫、取舍和复盘。四个平台保留同一个作者：公众号的作者关系最强，知乎次之，CSDN 和掘金更克制，但都不写成无人称说明书。

## 生成平台稿

只生成用户指定的平台版本：

- 公众号标准文章：读取 [platform-wechat.md](references/platform-wechat.md)。
- 知乎独立文章：读取 [platform-zhihu.md](references/platform-zhihu.md)。
- CSDN 技术文章：先通过下述技术内容准入门禁，再读取 [platform-csdn.md](references/platform-csdn.md)。
- 掘金技术文章：先通过下述技术内容准入门禁，再读取 [platform-juejin.md](references/platform-juejin.md)。

CSDN 和掘金必须同时满足：

- 主题属于软件开发、系统架构、AI、数据、产品技术、工程管理或可复用的工程实践；
- 材料能够支撑机制解释、问题复现、方案比较、实现过程或实践结论中的至少一种；
- 文章包含普通转载之外的解释、验证、分析或判断；
- 环境、版本、运行结果和适用边界能够按证据强度准确表达。

未通过时不生成 CSDN 和掘金稿，在 `06-验收报告.md` 记录不适配原因。未核实运行结果时，只能标记为设计、示例或待验证，不能写成已经跑通。

平台版本必须是带结构的 `.md` 文件。front matter 的 `title` 是唯一发布标题，正文直接从导语开始，不得出现 H1；正文小标题从 `##` 开始。标题约束与机器检查读取 [platform-markdown-contract.md](references/platform-markdown-contract.md)，统一视觉骨架、平台渲染和真实草稿验收读取 [platform-format-contract.md](references/platform-format-contract.md)。Markdown 负责语义结构，最终视觉由渲染器或平台编辑器实现，但平台默认导入样式不能直接视为排版通过。

公众号和知乎成稿执行以下硬限制，任一命中都视为平台验收失败：

- 不使用三个反引号或三个波浪线形成的围栏代码块，包括标记为 `text` 的普通文字块；
- 不使用以 `>` 开头的 Markdown 引用块承载原话、定义、结论或重点内容；
- 不使用 Markdown 表格、ASCII 图、空格对齐的多列文本和 `<pre>` 等不自动换行结构；
- 不把长网址、长路径、长命令或连续标识符作为独立可见文本；
- 不生成“参考资料”“参考文献”“资料来源”“来源列表”或同类文末章节，不使用脚注、尾注和编号链接列表模拟参考文献。

需要表达对照关系时改为短段落、分点列表或手机宽度下可读的纵向信息图。

CSDN 和掘金允许保留技术论证必需的围栏代码块、命令和配置，并执行：

- 代码块标注语言，前文交代用途、环境和前置条件，后文说明预期结果或观察方法；
- 代码来自知识单元账本和完整对外母稿已经锁定的事实与内容范围，平台层可以按目标读者展开解释，但不能补造未验证结果；
- 只保留理解和复现所需的关键片段，完整源码优先链接到持续可访问的仓库；
- Token、Cookie、内网地址、个人数据和其他敏感信息必须脱敏；
- 未执行的代码不得声称已经验证，具有破坏性的命令必须明确标注影响和前置条件。

需要说明出处时，在相关句子中自然写明来源名称，必要时给名称添加短链接；事实、观点与知识单元账本、完整链接、素材授权和风险记录只放入 `06-验收报告.md`，不进入公开正文。

平台层允许调整标题、摘要、开头入口、段落长短、转场、小标题，并对知识单元账本和母稿中已有的解释、代码、证据与边界进行压缩、展开和重新组合。

不得在平台层新增共同上游不存在的事实、案例、核心观点或第二条传播主线。目标平台需要的机制、边界或证据尚未进入知识单元账本时，先修复共同上游；已经确认但在其他平台被压缩的知识单元可以在目标平台重新展开，不要求四个平台保持同样篇幅。

## 守住内容深度

大众化只降低理解门槛，不降低知识上限。每个核心部分至少让目标读者理解：

1. 结论是什么；
2. 它为什么成立；
3. 它不适用于哪里或最容易被误解成什么；
4. 它如何改变实践、选择或判断。

可以用证据、案例、流程、代码、对比或真实经验完成闭环，不机械套用四段式。只给定义、只列清单、只写步骤、只换口语说法，或者用字数和术语数量冒充覆盖，均视为深度不足。文章可以短，但不能粗糙；材料不足时缩小结论或停止，不用流畅空话补篇幅。

## 处理视觉

先完成完整对外母稿正文初稿，再判断视觉。正文视觉必须在母稿阶段解决，平台层只处理封面、裁切、比例和排版。

`broadcast` 先锁定图片表达的事实和信息任务，再按场景选择视觉 Skill：

- 精确表达对比、流程、因果、层级、连续谱、框架、数据或中文文字时，调用 `$frontend-design`。应用其主题落地、反模板、字体、构图、标志性元素和两轮自我批评方法，生成可编辑 HTML/CSS 或 SVG，并渲染为 PNG；忽略不适用于静态图片的动效与交互要求。
- 生成平台封面、概念视觉、编辑插画或其他以气质、空间和视觉隐喻为主的静态画面时，调用 `$canvas-design`。先形成简短视觉哲学，再输出 PNG，并保留对应设计说明；文字保持稀少且准确。
- 封面需要精确承载框架、对比或较多中文时，可以改用 `$frontend-design`；正文需要纯概念性视觉时，可以改用 `$canvas-design`。不得仅根据“正文图”或“封面”机械路由。
- 需要照片、写实场景、复杂插画或纹理素材时，才在已选定的视觉方向下调用 `$imagegen` 或等价位图能力；它不替代信息结构和艺术指导。

不得把两个外部 Skill 的完整规则复制进 `broadcast`。调用细节、依赖来源和降级路径统一读取 [orchestration.md](references/orchestration.md) 与 [dependencies.md](references/dependencies.md)。

每张图至少承担一种任务：

- 解释结构、流程、因果或对比；
- 降低长段落理解成本；
- 帮助记忆核心框架；
- 为平台封面提供准确入口。

必要的共享正文插图必须实际生成、嵌入并验收，不能只留下“配图建议”。没有正文视觉能够增加理解价值时，明确记录“无需共享正文插图”，不为满足形式添加装饰图。

代码生成视觉必须同时保留可编辑源文件和最终 PNG。生成后实际渲染并检查：主题专属性、信息层级、中文字体、留白、对齐、裁切、目标阅读宽度下的字号，以及是否落入与主题无关的 AI 默认模板。至少完成一次基于截图的视觉批评和修正，不能只检查 HTML 或 CSS 代码正确。

需要调用视觉、风格、整理或发布能力时读取 [orchestration.md](references/orchestration.md)，只调用完成当前任务所需的最少能力。

## 完成验收

完整对外母稿必须先通过 [base-article.md](references/base-article.md) 中的门禁，再执行：

### 事实验收

- 事实、数据、来源和归属准确；
- 核心观点、条件、例外、风险和未知没有漂移；
- 没有把推断写成事实；
- 没有虚构身份、经历、案例或引用；
- 账本中的来源项都有去向。

### 深度验收

- 核心知识单元形成结论、机制、边界和实践影响闭环；
- 公众号的主动压缩没有破坏核心理解；
- 知乎保留命题、推理、反对意见和适用边界；
- CSDN 保留相关的结构、机制、契约、失败、验证和适用范围；
- 掘金保留相关的动机、备选方案、取舍、代价和演进；
- 不以统一字数线替代知识闭环判断。

### 传播验收

- 标题兑现正文；
- 开头快速建立对象感和阅读收益；
- 全文只有一个传播主线；
- 有一个贯穿全文的具体锚点，每个核心部分都能说明为什么在此刻出现；
- 概念由读者已经遇到的问题引出，没有成组倾倒陌生术语；
- 每部分都推进理解、信任或行动；
- 每个承担论证的段落都有已有材料支撑，或者能从前文事实直接推导；只换说法而没有增加信息的段落已经删除或合并；
- 有可复述、可收藏或可转发的真实价值；
- 没有噱头、煽动和虚假紧迫感。
- 已完成隔离冷读，首次卡顿位置、修改动作和复测结论有真实证据。

### 风格验收

- 主风格前后一致；
- 严肃度与话题匹配；
- 平台差异没有变成人格变化；
- 没有模仿身份和标志性口癖；
- 没有影响阅读的模板化结构、空泛套话、机械节奏和重复总结；
- 没有通过错别字、粗口、刻意情绪或虚构经历制造“人味”；
- 去模板化修改有具体问题和位置记录，已经自然准确的部分保持不变；
- 第一人称只承载真实观察和判断过程，跨平台保持同一作者；
- 第一人称说明了真实材料中的原因、动作、取舍或后果，不只使用“我发现”“我认同”制造语气外壳；
- 语言调整没有改变内容内核。

### 平台与源稿格式验收

- 目标形态是公众号标准文章、知乎独立文章、CSDN 技术文章或掘金技术文章；
- 平台 Markdown、正文视觉和封面素材完整；
- front matter 包含唯一发布标题，正文从导语开始且不存在 H1；
- 平台版本能追溯到同一知识单元账本和完整对外母稿；
- 多平台版本存在真实节奏差异，不是换标题复制；
- 公众号和知乎 Markdown 不含围栏代码块、引用块、Markdown 表格、ASCII 排版和其他需要横向滚动的结构；
- CSDN 和掘金的必要代码块具备语言、用途、环境、前置条件和结果说明，并已经脱敏；
- 公开正文不含参考资料、参考文献、资料来源、脚注、尾注或编号链接列表；
- 微信公众号源稿默认无目录，不设计大面积蓝底标题块，段落与图片适合移动端；
- 知乎、CSDN 和掘金优先使用平台原生结构，不用脆弱自定义样式复刻公众号；
- 标题、列表、图片、图注和代码等语义结构符合 [platform-format-contract.md](references/platform-format-contract.md)；
- 没有依赖未经核对的易变平台限制；
- 发布包可以独立交付，不依赖发布工具才能阅读。

执行投递时再做真实草稿视觉验收。未投递不影响本地内容任务完成，但不得报告“草稿排版已通过”。

事实底线失败时停止交付成稿。其他问题采用最小修改，不重写已经正确的部分。

## 处理发布

默认停止在本地发布包。

用户明确给出目标平台、账号、草稿边界并授权投递后，读取 [publishing.md](references/publishing.md) 和 [publishing-playwright.md](references/publishing-playwright.md)。只把验收通过的公众号、知乎、CSDN 或掘金文章交给对应的 `publisher_wechat`、`publisher_zhihu`、`publisher_csdn` 或 `publisher_juejin` 实例。四个平台必须使用独立且持久化的浏览器 Profile，不读取或复用用户日常浏览器 Profile。

明确投递请求同时授权自动安装和注册来源可核验的官方 Playwright MCP，不再单独请求一次安装确认。优先调用宿主原生 MCP 安装能力；没有时按实现 reference 注册四个平台实例。安装后必须重新发现工具并核对真实 schema；当前会话需要重载时准确报告“已安装待重载”。Profile 根目录优先使用用户本次指定的位置，其次使用项目已经声明的位置；两者都没有时只询问一次。该目录必须专用于发布登录态并禁止进入 Git、发布包和日志。该授权不覆盖首次平台登录或公开发布。

MCP 只提供浏览器操作能力，不自动代表平台草稿已经保存。每次投递必须读取当前页面结构，同一平台只保存一次，结果未知时先查草稿箱；不得根据工具名称猜测 schema，不得把“已生成发布包”“已填写”“已保存草稿”“草稿内容已确认”“草稿排版已通过”和“已公开发布”混为一谈。安装、启动、Profile、登录或页面适配失败时保留完整本地产物，降级为人工发布，不自动切回扩展、Token、CLI 或 WebSocket 桥接。
