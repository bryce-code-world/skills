# 广播

把已经想清楚的一篇内部文章，转写为能够获得阅读机会、完成预定传播效果并适合目标平台的长图文。

## 守住底线并联合优化

以下内容是不可突破的硬底线：

1. 事实、观点和原意准确。
2. 条件、例外、风险和不确定性不被削弱。
3. 作者身份、经历、来源和证据强度真实。
4. 隐私、版权、平台和发布授权边界清楚。

不得为标题、情绪、故事、节奏或平台感改变事实、观点强度、条件和适用边界。

在硬底线内联合优化：

- 标题和封面经过真实样本校准，能让目标读者获得准确、具体且有竞争力的进入理由；
- 内容使用目标读者能够按预期解码的共同语言，不把作者熟悉的术语当作读者前提；
- 文章建立与平台、话题和受众相称的作者—读者关系，让真实判断、具体对象和自然节奏承载内容；
- 开头保住进入机会，正文持续交付回报，结尾固化主要目标效果；
- 文章完成预定的理解、判断或行动效果；
- 内容具有足够深度，并适合目标平台的阅读与分发环境；
- 风格、视觉和排版共同降低理解与记忆损耗。

这些目标没有固定生产先后。标题和封面是传播内容的一部分，必须在正文前确定方向，并在成稿后反向校准。

## 维护版本与依赖

每次触发时读取 [dependencies.md](references/dependencies.md)，按其中的 24 小时规则执行非阻塞自身更新检查。

更新检查失败或发现新版本时继续当前内容任务，只在交付时报告。公开长文默认需要 `$writing-style` 执行风格说明和去模板化门禁；其他能力只在当前任务确实需要时检查对应依赖。

## 守住输入与范围

只接受一篇明确的权威内部底稿。底稿必须满足：

- 主题、核心结论和重要事实清楚；
- 事实、观点、条件、未知和采用状态可以区分；
- 文章已经能够独立阅读，不依赖补齐零散聊天或隐含背景；
- 用户目标是公开转写，而不是继续整理内部材料。

输入仍然零散、冲突或结论未收敛时，使用 `$lightning` 整理。不可用时按 [dependencies.md](references/dependencies.md) 处理；仍不满足时停止，不在 `broadcast` 内补写底稿，也不生成平台中立母稿。

正式支持：

- 微信公众号标准文章；
- 知乎独立文章；
- 通过技术内容准入门禁的 CSDN 技术文章；
- 通过技术内容准入门禁的掘金技术文章；
- 上述长文的共享正文插图、平台封面和带格式 Markdown；
- 已有公开长文的读者对象感、传播主线和平台节奏优化。

不处理公众号卡片、小绿书、知乎回答、小红书、短视频、音频、海报和其他非长文章形态。默认只生成本地产物；没有明确投递授权时，不连接账号、不上传素材、不保存草稿、不公开发布。

## 执行强制流程

1. 读取内部底稿、目标读者、目的、目标平台和授权边界。
2. 验证底稿是否完整、收敛并适合公开转写；失败时转交 `$lightning` 或停止。
3. 读取 [communication-effects.md](references/communication-effects.md)，从底稿和目标读者推导受众认知层级、主要目标效果、关键认知缺口和心智迁移方向。
4. 读取 [task-summary.md](references/task-summary.md)，在转写目录生成简洁的 `00-广播任务总结.md`。它只保存传播策略，不复述底稿事实、定义和论证。
5. 读取 [reader-continuity.md](references/reader-continuity.md) 和 [relationship-engineering.md](references/relationship-engineering.md)，为每个平台分别建立可解码语言基线、文章原型、内容主线、读者推进链和关系契约。
6. 调用 `$writing-style` 解析主风格和场景语气，并把作者说话位置、读者关系、对话距离、情绪温度和口语边界交给它落实；不可用时使用通用默认风格并记录降级。
7. 读取 [headline-engineering.md](references/headline-engineering.md)、[cover-engineering.md](references/cover-engineering.md) 和 [opening-engineering.md](references/opening-engineering.md)，为每个平台建立真实样本校准、入口张力、机制不同的标题、封面和开头候选，再确定入口承诺、标题假设、封面视觉命题和第一屏任务；CSDN 和掘金先执行技术内容准入门禁，不适配时记录原因并跳过。
8. 读取 [body-engineering.md](references/body-engineering.md) 和 [ending-engineering.md](references/ending-engineering.md)，对用户指定且通过门禁的平台，直接从“内部底稿 + 广播任务总结 + 对应平台 reference”独立转写完整文章。任何平台稿都不得作为另一个平台稿的上游。
9. 调用 `$writing-style` 对每篇完整平台稿执行一次关系与声音检查、结构与语言去模板化，修复匿名说明书、机械结构、假洞察、清单堆叠、均匀节奏、伪口语和身份问题，不抹平平台差异。
10. 对全部平台稿执行跨平台一致性检查，核对事实、观点、边界、主要目标效果、作者身份和来源，没有平台临时补造内容。
11. 按 [orchestration.md](references/orchestration.md) 和 [cover-engineering.md](references/cover-engineering.md) 根据最终文章校准标题和封面，生成并渲染平台封面，在目标尺寸与缩略尺寸联合验收；正文视觉只在增加理解、记忆或调用价值时生成。
12. 读取 [platform-markdown-contract.md](references/platform-markdown-contract.md) 和 [platform-format-contract.md](references/platform-format-contract.md)，完成平台格式处理并运行当前系统的原生标题检查器。
13. 再调用 `$writing-style` 执行平台终检，只修正格式或视觉处理重新引入的语言、节奏、身份和人格漂移问题，不推翻内容主线。
14. 以 [communication-effects.md](references/communication-effects.md) 作为五道门禁问题、失败条件和通过状态的唯一权威源；[opening-engineering.md](references/opening-engineering.md)、[body-engineering.md](references/body-engineering.md) 和 [ending-engineering.md](references/ending-engineering.md) 只提供设计与失败修正方法，[reader-continuity.md](references/reader-continuity.md) 只补充概念和主线连续性证据。执行独立冷读与陌生场景迁移题，修正后复测并写入 `06-读者测试.md`。
15. 执行底稿、平台、跨平台、事实、深度、传播、风格、视觉和格式验收，写入 `05-验收报告.md`。
16. 交付任务总结、目标平台稿、素材、验收报告和读者测试。
17. 只有用户明确授权投递时，才按 [publishing.md](references/publishing.md) 调用目标平台专属 Playwright MCP；实例缺失时自动安装官方 MCP、注册独立持久化 Profile、重新发现并检查能力，再处理草稿。

## 使用广播任务总结

`00-广播任务总结.md` 只回答：这次对谁传播、读者需要跨越什么认知缺口、主要目标效果是什么、用什么主线和入口承诺完成传播、各平台怎样呈现、有哪些本次特别要求、需要什么视觉、允许交付到哪里。

它不是事实来源、知识账本、文章提纲或隐藏母稿。不得复制底稿章节、大段定义、事实清单和完整论证；通常保持一屏左右，每项尽量一两句话。完整模板和失败处理读取 [task-summary.md](references/task-summary.md)。

四个平台的共同输入固定为：

```text
权威内部底稿 + 00-广播任务总结.md
```

底稿决定“写什么、什么是真的”；任务总结决定“对谁写、要产生什么效果、从什么角度和入口进入、各平台怎样呈现”。

## 建立读者与传播主线

为每个平台建立完成当前文章所需的最小读者模型：

```text
读者是谁：
受众认知层级：
可用于识别主题的术语：
可直接参与理解的共同概念：
必须先解释或容易误解的概念：
最容易误解什么：
为什么愿意关注：
理解内容的动机与能力：
关键认知缺口：
主要目标效果：
完成迁移的内容主线：
作者说话位置：
读者关系与对话距离：
情绪温度与口语边界：
```

每个平台只保留一个主要目标效果和入口承诺，不要求所有文章都推动行动。受众认知层级必须明确为普通大众、主题半熟悉读者或专业读者，不能为了让术语稿通过而在写作后静默缩窄读者。普通大众先从共同现象或问题进入，不在标题、摘要和第一屏依赖成组术语；主题半熟悉读者可以识别主题术语，但术语参与推理前仍需解释；专业读者只直接使用该群体真正共享的准确术语。标题和封面可以点名目标读者能够识别、且正文准备解释的对象；入口承诺必须在不知道术语定义时仍然看得懂。标题还必须提供具体进入理由，通常组合可识别对象、未解决张力和读者损益中的至少两项；完整研究、候选和淘汰方法读取 [headline-engineering.md](references/headline-engineering.md)。摘要、提纲、开头、小标题、正文和图片不得依赖读者尚未建立的概念完成解释或推理。准确术语只在确有必要时保留，并按“熟悉现象或问题 → 通俗作用 → 准确名称 → 回到主线”进入。允许点名被解释的对象，不允许拿尚未解释的术语充当解释前提。例子、类比和故事只能解释底稿已有内容，不能成为新证据。

平台可以采用不同文章原型和阅读路径，但核心事实、观点强度、条件、例外和作者身份必须一致。完整连续性与冷读方法读取 [reader-continuity.md](references/reader-continuity.md)。

## 处理风格

按以下顺序选择一个主风格：

```text
用户本次明确指定
        ↓ 没有
用户默认个人档案
        ↓ 没有
广播通用默认风格
```

每次公开长文都使用 `$writing-style`，按其广播集成契约执行三个不同阶段：写作前关系与风格说明、完整平台稿关系与声音检查及去模板化、平台格式和视觉完成后的终检。不可用时使用通用默认风格，并由 `broadcast` 执行同等人工门禁。

可以吸收具体场景进入、现象到本质递进、观点与案例交替、偏离后扣回主线、长短段落调节和结尾回收等通用机制。不得复制其他作者的身份、经历、人格、标志性口癖、固定标题或签名结构。

第一人称只用于底稿和用户材料中真实存在的观察、判断过程、犹豫、取舍和复盘。公众号的作者关系最强，知乎次之，CSDN 和掘金更克制，但都不得用虚构经历制造“活人感”。

“人味”不通过口癖配额制造。没有真实经历时，可以让底稿已有的判断、取舍、疑问和边界成为说话位置，使用通用假设与可观察动作承载抽象概念；口语和网络用语只有在受众熟悉度、关系距离、平台和话题风险都适配时使用。完整方法读取 [relationship-engineering.md](references/relationship-engineering.md)。

## 生成平台稿

只生成用户指定的平台版本：

- 微信公众号标准文章：读取 [platform-wechat.md](references/platform-wechat.md)。
- 知乎独立文章：读取 [platform-zhihu.md](references/platform-zhihu.md)。
- CSDN 技术文章：先通过技术内容准入门禁，再读取 [platform-csdn.md](references/platform-csdn.md)。
- 掘金技术文章：先通过技术内容准入门禁，再读取 [platform-juejin.md](references/platform-juejin.md)。

CSDN 和掘金必须同时满足：

- 主题属于软件开发、系统架构、AI、数据、产品技术、工程管理或可复用的工程实践；
- 底稿能够支撑机制解释、问题复现、方案比较、实现过程或实践结论中的至少一种；
- 文章包含普通转载之外的解释、验证、分析或判断；
- 环境、版本、运行结果和适用边界能够按证据强度准确表达。

平台稿必须使用带 front matter 的 Markdown。`title` 是唯一发布标题，正文直接从导语开始，不得出现 H1；正文小标题从 `##` 开始。

公众号和知乎正文禁止围栏代码块、引用块、Markdown 表格、ASCII 排版、横向滚动结构、脚注、尾注和文末参考资料章节。CSDN 和掘金只保留技术论证必需且已经脱敏的受控代码块；未执行的代码不得声称已经验证。

平台层可以重构底稿中已有内容的标题、摘要、开头、段落、转场、解释深度、代码呈现、结尾、插图位置和排版。不得新增底稿中不存在的事实、案例、经历、核心观点、运行结果或第二条主线。

## 守住内容深度

大众化只降低理解门槛，不降低知识上限。每个核心部分至少让目标读者理解：

1. 结论是什么；
2. 它为什么成立；
3. 它不适用于哪里或最容易被误解成什么；
4. 它如何改变实践、选择或判断。

可以用底稿已有的证据、案例、流程、代码、对比或真实经验完成，不机械套用四段式。只给定义、只列清单、只写步骤、只换口语说法，或者用字数和术语数量冒充覆盖，均视为深度不足。

目标平台需要的事实或论证不在底稿时，缩小结论、删除对应段落，或者停止并请求补充底稿；不得从其他平台稿或常识中补造。

## 处理视觉

平台封面属于入口传播，正文视觉属于解释传播，两者分开处理：

- 写正文前先确定各平台封面的目标读者、信息任务、视觉方向和它与标题的分工；
- 完成正文后，根据最终标题和实际内容生成或校准封面；
- 平台封面按各自阅读入口独立设计，不因共享内容而复制同一封面；
- 先写清标题已经承担的信息，再让封面补充情绪、场景、人物、对象证据或账号风格；大众抽象长文默认不把封面做成缩小版正文；
- 实际渲染并在目标尺寸与代表性缩略尺寸检查标题互补度、主视觉焦点、情绪或对象识别、文字可读性和裁切；
- 封面不能制造正文不存在的事件、人物、结果、冲突和权威感。

完成各平台正文初稿后，再判断正文视觉是否增加理解、记忆或调用价值。

- 多个平台都需要解释、且直接来自底稿的同一关系，可以生成 `assets/shared/` 共享正文图。
- 只有一个平台需要的解释图、裁切或排版素材，进入对应平台目录。
- 没有正文视觉能够增加价值时，明确记录“无需共享正文插图”，不添加装饰图；这不取消平台封面的入口任务。

精确表达对比、流程、因果、层级、连续谱、框架、数据或中文文字时调用 `$frontend-design`；概念视觉、编辑插画或平台封面偏重气质与视觉隐喻时调用 `$canvas-design`。生成后必须保留可编辑源或设计说明，实际渲染并按目标阅读宽度查看。

图片只能压缩或澄清正文已经解释的内容，不能首次引入陌生核心概念，也不能反向修改底稿事实。

## 完成验收

### 底稿门禁

- 只有一篇明确的权威内部底稿；
- 底稿已经完整、收敛且适合公开转写；
- 任务总结没有复制底稿或演变成隐藏母稿。

### 平台门禁

- 每篇文章符合目标平台的读者、深度、结构、格式和风格；
- 受众认知层级已经明确，入口、术语密度和解释深度与该层级一致，没有为通过门禁临时缩窄读者；
- 关键表达能够由目标读者按预期解码；标题和封面只点名可识别的主题术语，正文中的专业术语没有替代通俗解释或提前成为推理前提；
- 标题、封面、开头、正文和结尾面向同一目标读者；前四者兑现同一入口承诺，结尾固化主要目标效果；
- 标题研究区分真实数据、平台热门与普通编辑样本，没有把知名账号标题冒充爆文证据；
- 标题和封面能够清楚表达相关性、张力与真实读者损益，不是只有主题分类，也不依靠夸大、偷换命题或虚构事件争取点击；
- 封面研究区分行为数据、平台热门、账号整体表现和普通编辑样本，没有把头部账号的普通封面冒充十万加证据；
- 封面完成标题难以承担的非语言传播，缩小后仍能感知情绪、场景、对象或风格；除实用型信息海报外，不用卡片、箭头、流程和多标签复述正文；
- 全文只有一条主线，并完成预定的理解、判断或行动效果；
- 核心部分形成结论、机制、边界和实践影响闭环；
- 已直接对照底稿检查该平台应保留的核心论点，没有因转写而静默丢失；
- 第一人称、案例、数据、代码和运行结果都能追溯到底稿；
- 作者说话位置和读者关系能够被感知，口语、网络用语和节奏符合平台、受众熟悉度与话题风险，没有匿名说明书或伪人类化；
- 已完成去模板化编辑和隔离冷读。

### 五道传播门禁

- 入口门：只看标题和封面时，目标读者能够识别主题、对象和真实阅读收益，并能指出为什么愿意现在点开；
- 第一屏门：开头不复述标题，立即增加新信息、建立继续阅读的缺口，并把读者交给正文；
- 推进门：每个核心内容单元都增加新的理解、判断或可用回报，并持续扣回同一主线；
- 最后一屏门：结尾留下可复述的判断、方法、情绪或身份确认，不用重复摘要和强制互动冒充收束；
- 效果门：隔离读者跨越关键认知缺口，形成预定理解、判断或行动，而不只是复述术语。

第一屏门、推进门和最后一屏门共同构成兑现链。入口强但兑现链失败、正文正确但入口无法吸引目标读者、读者能总结却没有完成心智迁移，均不得验收通过。完整测试输入、问题和降级记录读取 [communication-effects.md](references/communication-effects.md)。

没有由未参与写作的独立读者执行完整冷读和陌生场景迁移题时，不得把概念进入、读者理解、内容主线或传播效果标记为“独立验收通过”。隔离自检只能记录“设计自检完成，未独立验收”。缩略提纲只能验收明确覆盖的局部设计，不得代替完整文章验收。

### 跨平台门禁

- 每个平台都直接追溯到同一内部底稿和任务总结；
- 平台之间存在真实阅读任务差异，不是换标题复制；
- 没有事实漂移、观点冲突、身份变化和相互作为上游；
- 某个平台的压缩或省略没有被误报为底稿不存在；
- 重要压缩、省略和不适配已进入验收报告，不扩写任务总结；
- 共享视觉只表达底稿中多个平台共同需要的关系。

事实底线失败时停止交付。其他问题采用最小修改，不重写已经正确的部分。真实草稿视觉验收只在执行投递时进行；未投递不得报告“草稿排版已通过”。

## 交付发布包

始终交付：

```text
00-广播任务总结.md
05-验收报告.md
06-读者测试.md
```

按用户目标交付：

```text
01-公众号文章.md            # 用户要求公众号时
assets/wechat/
02-知乎文章.md              # 用户要求知乎时
assets/zhihu/
03-CSDN文章.md              # 用户要求 CSDN 且通过技术门禁时
assets/csdn/
04-掘金文章.md              # 用户要求掘金且通过技术门禁时
assets/juejin/
assets/shared/              # 至少两个平台需要同一正文图时
```

编号按平台固定，未选择或未通过门禁的平台保留缺号。`source` 指向权威内部底稿，不指向任务总结。历史发布包保持原样；用户要求重新广播时才迁移到新结构，不在 Skill 中长期维护两套生成流程。

## 处理发布

默认停止在本地发布包。

用户明确给出目标平台、账号、草稿边界并授权投递后，读取 [publishing.md](references/publishing.md) 和 [publishing-playwright.md](references/publishing-playwright.md)。按 front matter 的 `platform` 识别文章，不根据文件编号猜平台；只把验收通过的文章交给对应的 `publisher_wechat`、`publisher_zhihu`、`publisher_csdn` 或 `publisher_juejin` 实例。

四个平台必须使用独立且持久化的浏览器 Profile，不读取或复用用户日常浏览器 Profile。明确投递请求同时授权自动安装和注册来源可核验的官方 Playwright MCP；首次登录和公开发布仍不随之授权。

MCP 只提供浏览器操作能力，不自动代表平台草稿已经保存。每次投递必须读取当前页面结构，同一平台只保存一次，结果未知时先查草稿箱；不得把“已生成”“已填写”“已保存草稿”“草稿内容已确认”“草稿排版已通过”和“已公开发布”混为一谈。

安装、启动、Profile、登录或页面适配失败时保留完整本地发布包，降级为人工发布，不自动切回扩展、Token、CLI 或 WebSocket 桥接。

## 最终说明

报告：

- 权威内部底稿和广播任务总结；
- 目标平台版本、主要目标效果、认知缺口和入口承诺；
- 标题与封面样本来源、证据等级、最终传播机制和被淘汰方向；
- 标题、封面、开头、正文与结尾的任务分工、承诺一致性和目标效果；
- 风格、去模板化和跨平台一致性结论；
- 共享视觉与平台视觉处理结果；
- 各平台的关键压缩、展开和省略；
- 底稿、平台、跨平台、事实、深度、传播、风格、视觉和格式验收；
- 入口门、第一屏门、推进门、最后一屏门、效果门和隔离冷读发现的问题、修改动作及复测结论；
- 陌生场景迁移题、读者判断过程和是否真正完成应用迁移；
- 外部投递的准确状态；
- 所有未决、失败和降级项。
