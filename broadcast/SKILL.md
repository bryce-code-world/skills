# 广播

把已经想清楚的内容完成为大众愿意读、能够理解、值得传播的长图文。

## 遵守质量顺序

按以下顺序处理，后项不能破坏前项：

1. 事实和原意准确。
2. 普通读者能够理解。
3. 内容确实值得读。
4. 具备自然传播力。
5. 风格稳定且适合场景。
6. 符合公众号或知乎的长文语境。
7. 视觉与排版增强理解。

不得为标题、情绪、故事、节奏或平台感改变事实、观点强度、条件和适用边界。

## 维护版本与依赖

每次触发时读取 [dependencies.md](references/dependencies.md)，按其中的 24 小时规则执行非阻塞自身更新检查。

更新检查失败或发现新版本时继续当前内容任务，只在交付时报告。公开长文默认需要 `$writing-style` 执行风格说明和去模板化门禁；其他能力只在当前任务确实需要时检查对应依赖。

## 守住范围

正式支持：

- 平台中立的大众基础长文；
- 微信公众号标准文章；
- 知乎独立文章；
- 上述长文的共享正文插图、平台封面和带格式 Markdown；
- 已有公开长文的读者对象感、传播主线和平台节奏优化。

不处理公众号卡片、小绿书、知乎回答、小红书、短视频、音频、海报和其他非长文章形态。用户提出这些请求时说明当前边界，不用相邻能力勉强模拟。

默认只生成本地产物。没有明确投递授权时，不连接账号、不上传素材、不保存草稿、不公开发布。

## 判断输入能否转译

输入满足以下条件时直接开始：

- 主题、核心结论和重要事实清楚；
- 事实、观点、条件、未知和采用状态可以区分；
- 目标是公开传播，而不是继续整理内部材料。

输入仍然零散、冲突或结论未收敛时，使用 `$lightning` 整理。不可用时按 [dependencies.md](references/dependencies.md) 处理；事实仍不清楚时停止公开转译，不替用户选择事实版本。

内容短或材料有限时保持短而完整，不凭空补充案例、数据和经历。

## 建立事实与观点账本

写作前内部记录：

- 主题、核心结论和作者立场；
- 事实、数据、来源、归属和时间范围；
- 观点与事实的区别；
- 条件、例外、风险、未知和确认状态；
- 作者真实拥有的经历和观察；
- 可以压缩、解释或重排的内容；
- 不得改变的术语、名称和表达强度。

逐项记录“来源项 → 基础长文位置”。每项只能准确保留、移入可访问的附录或权威链接，或者明确标为未知、争议和待确认。不得静默省略，不得把推断写成事实，不得编造第一人称经历。

## 执行强制流程

1. 读取输入、目标读者、目的、目标平台和授权边界。
2. 判断是否需要先由 `$lightning` 收敛内容。
3. 建立事实与观点账本、最小读者模型和单一传播主线。
4. 调用 `$writing-style` 解析主风格和场景语气；不可用时使用通用默认风格并记录降级。
5. 读取 [base-article.md](references/base-article.md)，生成完整大众基础长文。
6. 调用 `$writing-style` 执行完整去模板化编辑；不可用时按同一门禁人工降级。未通过时不进入视觉和平台层。
7. 判断正文视觉是否真正增加理解；必要时按视觉任务调用 `$frontend-design` 或 `$canvas-design`，生成共享正文插图并嵌入基础长文。
8. 完成基础图文门禁。未通过时先修复共同上游，不生成平台稿。
9. 按用户指定的平台读取对应 reference，从同一基础长文重构带格式 Markdown。
10. 调用 `$writing-style` 执行平台稿语言终检，只修正平台改写重新引入的问题；不可用时人工降级。
11. 按封面的信息任务调用 `$canvas-design` 或 `$frontend-design`，生成平台封面和必要的裁切或清晰度版本。
12. 检查风格、事实覆盖、平台差异和移动端可读性。
13. 交付基础长文、目标平台稿、素材和验收报告。
14. 只有用户明确授权投递时，才按 [publishing-wechatsync.md](references/publishing-wechatsync.md) 处理草稿。

无论用户只要求一个平台还是多个平台，都必须保留大众基础长文这一正式产物。不得绕过它直接生成平台稿。

## 建立读者与传播主线

使用完成本次写作所需的最小读者模型：

```text
读者是谁：
已经知道什么：
最关心什么：
最容易误解什么：
读完应获得什么：
希望采取什么动作：
```

只保留一个主要传播承诺：

```text
读者为什么要点开：
为什么值得读完：
读完能复述什么：
愿意转给谁：
```

首次出现专业概念时，优先采用“通俗定义 → 为什么重要 → 准确名称”。例子、类比和故事只能解释已有内容，不能成为新的证据。

## 处理风格

按以下顺序选择主风格：

```text
用户本次明确指定
        ↓ 没有
用户默认个人档案
        ↓ 没有
广播通用默认风格
```

每次公开长文都使用 `$writing-style`，并按其广播集成契约执行写作前说明、基础长文去模板化和平台稿语言终检。没有个人档案时由它使用内置通用默认风格，不因此跳过。

不可用时使用通用默认风格，并由 `broadcast` 按同一问题类别执行最小编辑和内容内核检查，记录“writing-style 不可用”的降级。不得省略门禁。

可以吸收具体场景进入、现象到本质递进、观点与案例交替、偏离后扣回主线、长短段落调节和结尾回收等通用机制。不得复制其他作者的身份、人格、标志性口癖、固定标题或签名结构。

## 生成平台稿

只生成用户指定的平台版本：

- 公众号标准文章：读取 [platform-wechat.md](references/platform-wechat.md)。
- 知乎独立文章：读取 [platform-zhihu.md](references/platform-zhihu.md)。

平台版本必须是带结构的 `.md` 文件。Markdown 负责标题、摘要元数据、段落、标题层级、引用、列表、强调、链接、图片和图注；字体、字号、颜色、行距等最终视觉由下游渲染器或平台编辑器处理。

平台层只允许调整标题、摘要、开头入口、段落长短、转场、小标题、已有解释的压缩或展开、信息顺序、结尾语境、插图位置和平台包装。

不得在平台层新增事实、案例、核心观点或第二条传播主线。需要新增实质内容时，先修改基础长文并重新执行门禁，再同步目标平台版本。

## 处理视觉

先完成基础长文正文初稿，再判断视觉。正文视觉必须在基础长文阶段解决，平台层只处理封面、裁切、比例和排版。

`broadcast` 先锁定图片表达的事实和信息任务，再按场景选择视觉 Skill：

- 精确表达对比、流程、因果、层级、连续谱、框架、数据或中文文字时，调用 `$frontend-design`。应用其主题落地、反模板、字体、构图、标志性元素和两轮自我批评方法，生成可编辑 HTML/CSS 或 SVG，并渲染为 PNG；忽略不适用于静态图片的动效与交互要求。
- 生成平台封面、概念视觉、编辑插画或其他以气质、空间和视觉隐喻为主的静态画面时，调用 `$canvas-design`。先形成简短视觉哲学，再输出 PNG，并保留对应设计说明；文字保持稀少且准确。
- 封面需要精确承载框架、对比或较多中文时，可以改用 `$frontend-design`；正文需要纯概念性视觉时，可以改用 `$canvas-design`。不得仅根据“正文图”或“封面”机械路由。
- 需要照片、写实场景、复杂插画或纹理素材时，才在已选定的视觉方向下调用 `$imagegen` 或等价位图能力；它不替代信息结构和艺术指导。

不得把两个外部 Skill 的完整规则复制进 `broadcast`。调用细节、依赖来源和降级路径统一读取 [orchestration.md](references/orchestration.md) 与 [dependencies.md](references/dependencies.md)。

每张图至少承担一种任务：

- 解释结构、流程、因果或对比；
- 降低长段落理解成本；
- 帮助记忆核心框架；
- 为平台封面提供准确入口。

必要的共享正文插图必须实际生成、嵌入并验收，不能只留下“配图建议”。没有正文视觉能够增加理解价值时，明确记录“无需共享正文插图”，不为满足形式添加装饰图。

代码生成视觉必须同时保留可编辑源文件和最终 PNG。生成后实际渲染并检查：主题专属性、信息层级、中文字体、留白、对齐、裁切、目标阅读宽度下的字号，以及是否落入与主题无关的 AI 默认模板。至少完成一次基于截图的视觉批评和修正，不能只检查 HTML 或 CSS 代码正确。

需要调用视觉、风格、整理或发布能力时读取 [orchestration.md](references/orchestration.md)，只调用完成当前任务所需的最少能力。

## 完成验收

基础长文必须先通过 [base-article.md](references/base-article.md) 中的门禁，再执行：

### 事实验收

- 事实、数据、来源和归属准确；
- 核心观点、条件、例外、风险和未知没有漂移；
- 没有把推断写成事实；
- 没有虚构身份、经历、案例或引用；
- 账本中的来源项都有去向。

### 传播验收

- 标题兑现正文；
- 开头快速建立对象感和阅读收益；
- 全文只有一个传播主线；
- 每部分都推进理解、信任或行动；
- 有可复述、可收藏或可转发的真实价值；
- 没有噱头、煽动和虚假紧迫感。

### 风格验收

- 主风格前后一致；
- 严肃度与话题匹配；
- 平台差异没有变成人格变化；
- 没有模仿身份和标志性口癖；
- 没有影响阅读的模板化结构、空泛套话、机械节奏和重复总结；
- 没有通过错别字、粗口、刻意情绪或虚构经历制造“人味”；
- 去模板化修改有具体问题和位置记录，已经自然准确的部分保持不变；
- 语言调整没有改变内容内核。

### 平台验收

- 目标形态是公众号标准文章或知乎独立文章；
- 平台 Markdown、正文视觉和封面素材完整；
- 平台版本能追溯到同一基础长文；
- 多平台版本存在真实节奏差异，不是换标题复制；
- 没有依赖未经核对的易变平台限制；
- 发布包可以独立交付，不依赖发布工具才能阅读。

事实底线失败时停止交付成稿。其他问题采用最小修改，不重写已经正确的部分。

## 交付发布包

始终交付：

```text
01-大众基础长文.md
assets/shared/              # 存在共享正文插图时
```

按用户目标交付：

```text
02-公众号文章.md            # 用户要求公众号时
assets/wechat/
03-知乎文章.md              # 用户要求知乎时
assets/zhihu/
04-验收报告.md
```

平台 Markdown 至少包含推荐标题、必要摘要、完整正文、图片引用、来源与风险信息。多平台产物使用独立文件，避免误投。

## 处理发布

默认停止在本地发布包。

用户明确给出目标平台、账号、草稿边界并授权投递后，读取 [publishing-wechatsync.md](references/publishing-wechatsync.md)。只把验收通过的公众号标准文章或知乎独立文章交给当前可用的官方 Wechatsync 能力。

不得把“已生成发布包”“已提交”“已保存草稿”“草稿内容已确认”和“已公开发布”混为一谈。任何发布入口不可用时保留完整本地产物，降级为人工发布。

## 最终说明

报告：

- 基础长文和目标平台版本；
- 读者假设、传播主线和主风格；
- 去模板化编辑与平台稿终检结果；
- 共享视觉与平台视觉的处理结果；
- 关键压缩、展开和平台差异；
- 基础门禁和四重验收结论；
- 外部投递的准确状态；
- 所有未决、失败和降级项。
