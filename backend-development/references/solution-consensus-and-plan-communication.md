# 整体方案共识与计划沟通

S9 同时完成两件事：确认 S6、S7 构成的整体方案，并与项目负责人确认 S8 项目开发计划。

## 会前材料

- S6 前端与其他调用方范围及视角流程；
- S7 接口、RPC 与消息目的清单；
- S8 项目开发计划；
- 尚未关闭的产品交互疑问和已知风险。

## 参与方与议题

产品、项目、后端、前端或其他主要调用方、测试参加。

逐项确认调用方职责、端到端场景、交互目的、状态感知、联调边界、工作包、依赖、时间、里程碑和主要风险。

新发现的产品疑问由产品确认。无法当场确认且会改变整体方案时回到 S2，确认后更新 S6、S7、S8 并重新检查受影响结论。

使用 [solution-consensus-record.md](../assets/templates/solution-consensus-record.md)。

## 沟通边界

S9 形成多端共识基线，不逐字段冻结具体协议。S11 的普通字段和调用问题默认在线评审；只有范围较大、多端理解不一致、职责冲突或线上难以收敛时再开专项会议。

## 退出检查

- 各参与方对 S6、S7 的整体方案理解一致。
- 产品疑问已关闭或有明确阻塞状态。
- 项目负责人已确认 S8 计划阶段、时间和协作点；项目计划使用 `WP-XX` 时同时确认其边界。
- 结论已回填权威文档，沟通记录不替代权威设计。
