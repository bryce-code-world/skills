# 项目开发计划

S8 面向项目负责人，以 S5 整体流程为拆分骨架，并结合 S6 调用方范围和 S7 交互目的建立粗粒度后端开发计划。

## 先确认计划约束

生成计划前，从用户、项目材料和现有排期中确认：

- 计划第一读者；
- 开发人数和是否顺序开发；
- 时间上限、开始日期和工作日历；
- 需要的表格列和说明深度；
- 是否需要里程碑、风险、联调或负责人视图。

能够核实的内容直接使用。缺少的信息会改变排期时，只询问一个计划约束问题，不先生成企业级完整模板。

## 形成最小计划

默认只生成一张时间计划表，使用阶段、模块、主要产出、依赖、工期和项目确实需要的日期列。

按 S5 独立流程、稳定业务模块和真实依赖拆分阶段。压缩格式时仍保留企业创建、权益联动、企业生命周期、离职交接、消息通知、初始化和旧链路退出等独立业务边界。

单人开发默认使用顺序阶段。多人协作或项目负责人明确需要时，再增加负责人、并行关系、里程碑、联调点和风险。

`WP-XX` 是 S10 建立实现设计时可选的内部稳定标识，不强制出现在面向项目负责人的计划中。S8 使用阶段或模块名称也可以与 S10 一一对应。

计划颗粒度停留在阶段级或模块级。不在 S8 展开事务、RPC、缓存、代码文件或 AI 任务。

使用 [project-development-plan.md](../assets/templates/project-development-plan.md)。

## 调整规则

S10 发现阶段边界、依赖或颗粒度不成立时，回到 S8 更新计划。变化影响时间、参与方、里程碑或联调点时，重新与项目负责人完成必要沟通。

不因计划调整复制第二套计划。原计划差异由 Git 和沟通记录承接。

## 退出检查

- 计划阶段覆盖 S5 独立流程和 S6、S7 工作范围，没有因格式压缩丢失业务边界。
- 每个阶段有主要产出、依赖和可核对工期。
- 项目负责人可以据此安排时间；计划没有超出已确认的人员和期限约束。
- S10 可以按计划阶段或可选 `WP-XX` 建立一一对应的实现设计。
