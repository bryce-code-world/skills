# 项目开发计划

S8 面向项目负责人，以 S5 整体流程为拆分骨架，并结合 S6 调用方范围和 S7 交互目的建立粗粒度后端开发计划。

## 划分开发工作包

1. 按整体流程、稳定业务模块和真实技术依赖识别工作包。
2. 为每个工作包分配 `WP-XX` 和明确名称。
3. 写明目标、范围、前置工作包、涉及服务、协作方和主要交付物。
4. 排列有依赖的工作包；无直接依赖时按稳定业务模块推进。
5. 写明预计时间、里程碑、联调点、验收节点和主要风险。

计划颗粒度停留在模块级或工作包级。不在 S8 展开事务、RPC、缓存、代码文件或 AI 任务。

使用 [project-development-plan.md](../assets/templates/project-development-plan.md)。

## 调整规则

S10 发现工作包边界、依赖或颗粒度不成立时，回到 S8 更新计划。变化影响时间、参与方、里程碑或联调点时，重新与项目负责人完成必要沟通。

不因计划调整复制第二套计划。原计划差异由 Git 和沟通记录承接。

## 退出检查

- 工作包覆盖 S5 全部相关流程和 S6、S7 工作范围。
- 每个工作包有前置依赖、交付物、里程碑和验收节点。
- 项目负责人可以据此安排时间和协作方。
- S10 可以按 `WP-XX` 建立一一对应的实现设计。
