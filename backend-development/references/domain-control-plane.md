# 业务域研发控制面

业务域目录是人理解、操作和管理研发过程的控制面。代码、协议、测试、数据、日志和运行结果是事实面。

## 选择唯一入口

按以下顺序选择：

1. 复用承担导航职责的根 `README.md`。
2. 复用已有索引或阅读顺序文档。
3. 两者不能承载动态状态时，新建 `00-研发控制台.md`，并从根 README 链接。

入口一旦确定不得自行更换。移动、重命名或拆分必须由人确认。

## 必需信息

控制入口至少记录：

- 业务域定位、主服务、边界、上下游和核心对象；
- 主业务类型、可选辅助类型、规模、判断依据和目录策略；
- `P1`～`P6` 逻辑职责到实际业务化目录名的映射；
- `S1`～`S16` 的完整步骤词典、权威路径和当前状态；
- 迭代标识、目标、范围、非目标、状态和负责人；
- 当前 `P`、`S`、`WP-XX`、`TASK-XX` 及各自状态；
- 当前步骤材料状态和设计门禁状态；
- 当前步骤已满足条件、未满足条件和放行人；
- 每类结论的唯一权威路径；
- 开放事项编号、沟通类型、影响对象、决策人或风险接受人、所需事实和回退条件；
- 当前最小任务、验证证据和唯一下一步；
- 当前工作切片、已完成切片和剩余切片；
- 最近一次事实核对时间和更新原因。

使用 [domain-control.md](../assets/templates/domain-control.md) 初始化入口，使用 [business-domain-profile.md](../assets/templates/business-domain-profile.md) 记录画像。

## 状态

材料状态与研发状态分别记录。

材料状态使用 `NOT_LOCATED`、`LOCATED`、`MIGRATING`、`MIGRATED`、`MIGRATION_VERIFIED` 和 `REUSED`。

材料状态只表示来源、位置和迁移完整性。文档存在或迁移完成不能推导设计已经评审。

S1～S12 使用 `NOT_STARTED`、`IN_PROGRESS`、`BLOCKED`、`REVIEW_READY`、`FROZEN` 和 `CHANGE_PENDING`。

S13～S16、工作包和 AI 任务按实际进度使用 `NOT_STARTED`、`IN_PROGRESS`、`BLOCKED`、`REVIEW_READY`、`IMPLEMENTED`、`VERIFIED` 和 `DEPRECATED`。

研发大阶段状态由所含流程步骤推导。

- `FROZEN` 表示设计或协议已放行。
- `CHANGE_PENDING` 表示冻结结论受到新事实或新决策挑战，下游暂时不能继续依赖。
- `IMPLEMENTED` 只表示实现存在。
- `VERIFIED` 表示设计、实现和验证证据闭环。

冻结结论变化时，在控制入口记录开放问题、原冻结基线、影响对象和唯一下一步，并将最早受影响步骤标为 `CHANGE_PENDING`。

人的决定确认后，直接更新对应权威需求、模型或协议。完成受影响产物复核并重新放行后恢复 `FROZEN`，再从控制入口移除已关闭问题。过程由 Git、Agent 日志和对话承接。

## 恢复任务

续跑检查点只是恢复线索，不是永久权威事实。

恢复时先验证检查点中的路径、控制入口更新时间和实际 Git 状态。路径不存在、控制入口已更新或事实冲突时，立即废弃旧检查点，从当前控制入口重新恢复。

随后只读取控制入口、当前步骤权威文档、开放问题和实际工作区状态。依次回答：

1. 当前是哪一个迭代？
2. 当前 `P`、`S`、`WP-XX`、`TASK-XX` 是什么？
3. 哪些前置条件已满足，证据在哪里？
4. 是否存在未提交内容、冲突或外部阻塞？
5. 本轮允许完成的最小任务是什么？
6. 完成后的唯一下一步是什么？

存在未提交内容时，先核对控制入口中的开放问题和对话里已确认的决定。没有稳定决定时不得仅根据派生文档差异猜测业务结论。

控制入口与事实面冲突时报告差异，不自行选择一方，也不声称恢复完成。
