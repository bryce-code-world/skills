# 业务域根文档职责

业务域目录是人理解、操作和管理研发过程的控制面。代码、协议、测试、数据、日志和运行结果是事实面。

根目录固定使用两份核心文档：

- `README.md`：固化业务域信息，并提供最短导航；
- `Progress.md`：记录当前研发过程，并作为新会话续跑入口。

两份文档职责不同，不互相复制完整内容。

## README.md

`README.md` 只记录稳定的业务域框架：

- 一句话定位和业务边界；
- 业务线、核心模块、对象、角色、关系和生命周期；
- 服务、调用方和数据归属；
- 业务类型、规模及简短判断依据；
- P1～P6 实际路径与一句话职责；
- 业务模型、数据模型、流程、协议、实现、Review、验收和 Bug 的权威入口。

导航可以放在开头或结尾。当前迭代、阻塞和下一步不写入 `README.md`。

使用 [business-domain-profile.md](../assets/templates/business-domain-profile.md) 生成根目录 `README.md`。

## Progress.md

`Progress.md` 只记录当前推进所需的信息：

- 当前迭代、当前 P/S/状态；
- 当前工作对象，按需记录 `WP-XX` 或 `TASK-XX`；
- 当前最小任务、实际阻塞、唯一下一步和最近更新；
- 新会话需要读取的最小恢复范围；
- 有多个切片时的已完成切片和剩余切片；
- 接受风险、禁止事项和开放事项。

没有对应内容时，直接省略字段或小节。不得复制完整 S1～S16 状态词典、协议字段、历史讨论或完整人员时间表。

使用 [progress.md](../assets/templates/progress.md) 生成根目录 `Progress.md`。

## 最小状态

状态只回答当前对象做到哪里，不承担材料迁移、阻塞原因、变更原因或历史归档职责：

| 对象 | 允许状态 |
| --- | --- |
| S1～S10、S12 流程与设计 | `未开始`、`进行中`、`待确认`、`已确认` |
| S11 协议 | `未开始`、`进行中`、`待确认`、`已冻结` |
| S13～S16、TASK 与实现验证 | `未开始`、`进行中`、`已实现`、`已验证` |

P 不单独维护状态。WP 只在 S10 使用，并沿用 S10 的流程状态。

材料是否找到、复用、迁移或核验，直接写成事实，不创建材料状态枚举。

阻塞单独写“阻塞说明”，不增加“阻塞”状态。冻结结论发生变化时，在 `Progress.md` 记录原基线和影响范围，并把最早受影响步骤退回“待确认”。

协议或功能停止使用时记录“已废弃”结论、替代路径和兼容期限，不把它加入通用研发状态。

## 恢复任务

续跑检查点只是恢复线索，不是永久权威事实。

恢复时依次读取项目规则、`README.md`、`Progress.md`、当前步骤权威文档和必要事实：

1. 当前是哪一个迭代、P、S 和状态？
2. 当前工作对象、最小任务和唯一下一步是什么？
3. 权威入口、阻塞、开放事项和接受风险在哪里？
4. 检查点路径、`Progress.md` 更新时间和实际 Git 状态是否仍有效？

路径不存在、`Progress.md` 已更新或事实冲突时，废弃旧检查点，从当前 `Progress.md` 重新恢复。

存在未提交内容时，先核对 `Progress.md` 的开放事项和已经确认的决定。没有稳定决定时，不得仅根据派生文档差异猜测业务结论。

`README.md`、`Progress.md` 与事实面冲突时报告差异，不自行选择一方，也不声称恢复完成。
