# 整体流程与调用方适配

## S5：整体流程框架

按业务场景贯通需求到数据和外部效果：

1. 说明发起人、触发条件和输入。
2. 说明身份、权限和业务前置条件。
3. 说明后端服务、数据来源、计算和状态转换。
4. 说明事务、本地写入、RPC、消息和外部调用顺序。
5. 说明成功结果怎样被调用方感知。
6. 说明失败、超时、重试、补偿、并发和重复请求。
7. 说明数据生命周期和可观测证据。

整体流程必须覆盖前端操作和后端内部处理。只有关键子流程具有独立阅读任务时才拆文档。

使用 [end-to-end-flow.md](../assets/templates/end-to-end-flow.md)。

## S6：前端与其他调用方

先列出本次范围内全部调用方。前端通常是主要调用方，但还要识别移动端、后台管理端、内部服务、定时任务、异步 Worker、第三方和无前端场景。

对每个调用方说明工作范围、入口、流程节点、所需状态、刷新或推送规则、错误感知和联调场景。区分直接调用、后端异步履约和调用方刷新感知。

使用 [consumer-adaptation.md](../assets/templates/consumer-adaptation.md)。

## S7：交互目的清单

从 S6 场景盘点 HTTP、RPC、WS、MQ、IM 和第三方交互。每项记录调用方、触发场景、业务目的、责任服务、数据效果、成熟度和存量处理：新增、迭代、沿用或废弃。

S7 只固定目的和边界，不提前写完整字段协议。使用 [interaction-inventory.md](../assets/templates/interaction-inventory.md)。

## 退出检查

- 每条需求有端到端流程位置。
- 每个调用方知道负责什么、何时调用、如何感知结果。
- 每项交互可追溯到调用方场景和业务效果。
- S8 可以据此识别参与方、工作包、联调点和依赖。
