# 整体流程与调用方适配

## S5：业务拆解设计

S5 把已收敛的业务域需求拆成可独立负责、实现和验收的子业务，不提前完成 S10 的技术实现设计。

S5 的依赖方向只能向上游：默认依赖收敛后的 S1、已确认的 S2/S3 和已放行的 S4；不得引用 S6～S16、S10 实现设计、S11 协议或 S12 任务作为业务成立的前提。后续阶段只能引用 S5 的已确认结论。若当前材料只有接口路径、版本或字段信息，先转换为业务能力和结果描述，协议与实现细节留给 S10/S11。

每个子业务至少说明：

1. 业务范围、责任服务或模块、权威业务域和本期变更清单。
2. 发起人、触发条件、身份权限和业务前置条件。
3. 各责任方的逻辑动作、权威状态和状态转换。
4. 成功结果、失败业务结果和调用方感知。
5. 可执行的验收标准；复杂分支再补流程图。

每个子业务文档还应列出“上游依赖”小节，只列实际使用的 S1/S2/S3/S4 文档或已确认业务结论；不为凑齐追溯而复制需求编号，也不列不执行的事项。

事务边界、具体 RPC 调用、缓存实现、幂等、补偿载体和代码组织留到 S10；字段、错误码、消息编号以及共享或影响正确性的缓存契约留到 S11。

跨业务域场景只记录本业务域需要适配的输入、输出和责任交接，不接管关联业务域内部逻辑；只把已确认的业务写入正文。

S5 默认使用总览索引和子业务文档。总览只保留映射和导航，子业务文档承载自身范围、变更、流程和验收。

使用 [business-decomposition.md](../assets/templates/business-decomposition.md)；仅需要独立流程表时可复用 [end-to-end-flow.md](../assets/templates/end-to-end-flow.md)。

## S6：协议清单

S6 先把 S5 业务拆解中需要对外协作的接口、RPC、消息和错误语义整理成可供调用方识别的清单，但不冻结完整字段协议。

从 S5 子业务流程和 S4 协作数据模型盘点 HTTP、RPC、WS、MQ、IM 和第三方交互，分别整理新增、迭代、沿用和停止调用；同时标明用途、调用方或接收方、业务场景和替换关系。

S6 可以固定 Path、方法或消息名称、用途和废弃状态，但不提前写完整请求响应字段、Proto 字段号、错误码编号、事务、缓存或代码实现。完整接口、RPC、消息及按需缓存协议在 P4/S11 冻结。

使用 [interaction-inventory.md](../assets/templates/interaction-inventory.md)。

## S7：前端与其他调用方对接说明

S7 必须建立在已确认的 S5 多端协作流程、S4 协作数据模型和 S6 协议清单之上，面向前端及其他调用方说明本期业务范围、关键流程和可观察的协作方式。

先列出本次范围内全部调用方。前端通常是主要调用方，但还要识别移动端、后台管理端、内部服务、定时任务、异步 Worker、第三方和无前端场景。

开始写作前先在内部固定交付物契约：第一读者、阅读任务、文件集合、必须内容、明确排除内容和展示形式。能够从用户表达与现有目录确定时直接采用，只询问仍会改变产物的唯一问题。

对前端和其他外部调用方，只说明调用方可见的接口、消息、状态、错误、调用时机和失效条件。前端不需要知道 auth-native、责任服务或后端内部模块；除非产品已确认，页面提示、跳转、保留旧状态和交互降级不由后端替其决定。

区分直接调用、后端异步履约和调用方刷新感知。内部服务、定时任务和 Worker 只保留与调用方协作有关的责任，不在 S6 展开技术实现。

沟通内容较少且读者一致时优先在 P3 平铺，不为前端流程机械建立子目录。

调用方对接说明可以记录已确认的入口或菜单变化、页面或场景调整，但必须用调用方语言表达，不把后端内部实现名称当成前端协作前提。

前端流程图遵守：

- 一张图只表达一个场景，默认纵向；
- 使用 `START[流程主题]` 建立阅读起点；
- 调用节点写明前端实际使用的 Path；
- 节点只保留关键动作，完整清单放表格；
- 页面宽度无法清楚展示时主动拆图；
- 提交前执行项目可用的渲染或截图检查，无法渲染时明确保留人工视觉验收。

使用 [consumer-adaptation.md](../assets/templates/consumer-adaptation.md)。

使用 [interaction-inventory.md](../assets/templates/interaction-inventory.md)。

## 退出检查

- 每项交互能覆盖实际业务动作，并明确新增、迭代、沿用或停止调用。
- S6 已形成可供调用方识别的协议清单，但没有提前冻结字段级协议。
- S7 的每个调用方知道本期业务范围、可见入口、使用什么、何时调用和怎样感知业务结果。
- S7 没有混入 auth-native、责任服务、后端模块等调用方不需要的实现视角。
- S8 可以据此识别参与方、开发阶段、联调点和依赖。
