# 业务类型与规模识别

目录生成前先形成业务域画像。启动准备只形成初步画像；S1 业务模型收敛和 S5 业务拆解稳定后确认最终画像。

## 内置业务类型

| 主类型 | 识别特征 | 主要组织轴 |
| --- | --- | --- |
| 主数据型 | 维护多个业务域依赖的核心对象、关系和生命周期 | 对象、关系、生命周期 |
| 业务应用型 | 面向用户完成一组完整业务流程 | 稳定业务模块和主流程 |
| 基础能力型 | 向多个业务域提供通用能力 | 能力、调用方式、处理链路 |
| 规则治理型 | 对多个服务实施统一规则、准入或约束 | 规则模型、范围、检查机制、应用流程、依赖服务 |

选择一个主类型。确有必要时增加一个辅助类型；辅助类型不改变主组织轴。

无法稳定归类时标记 `待识别类型`，记录最接近类型和实际差异，由人决定是否扩展类型档案。

## 规模

| 规模 | 识别结果 | 默认深度 |
| --- | --- | --- |
| 小型 | 内容可作为一个整体理解和维护 | 大阶段内部平铺 |
| 中型 | 存在多个稳定模块、能力或独立维护职责 | 沿主组织轴拆一层 |
| 大型 | 存在多个能力域、聚合、复杂流程或跨服务协作边界 | 先按稳定能力域或模块拆分，必要时再按设计职责拆一层 |

综合业务模块、核心对象、流程状态、调用方、责任服务边界、协议种类、生命周期和存量复杂度判断。不得只按服务数、文件数或文档行数判断。

## 当前校准样本

| 业务域 | 类型与规模 | 校准重点 |
| --- | --- | --- |
| 消息推送 | 基础能力型、小型 | 能力集中，阶段内部保持最少文档 |
| 权益 | 规则治理型、大型 | 多模型、多流程、跨服务 RPC 和验收 |
| 权限 | 规则治理型、大型 | 企业级与应用级规则覆盖多个服务，存量实现碎片化 |
| 假勤 | 业务应用型、大型 | 考勤、假勤、审批、通知、统计和规则协同 |
| 绩效 | 业务应用型、大型 | 模板、活动、状态机、消息、缓存和多服务协议 |

样本只校准判断方法，不按名称直接套用结论。
