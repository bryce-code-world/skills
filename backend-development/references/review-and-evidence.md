# Review 与证据闭环

## 建立追溯矩阵

至少映射：需求点、业务模型、数据模型、S5 子业务与流程、调用方流程、交互清单或协议、实现位置、测试证据和 Review 状态。

不存在设计依据的实现、没有实现位置的协议、没有测试证据的高风险规则不能判为完成。

使用 [traceability-matrix.md](../assets/templates/traceability-matrix.md)。

## 执行 Review

按任务级、工作包级和整体级分别审查。每一级都执行项目规范、业务符合性、风险和证据四层检查，并明确未执行项。

使用 [review-report.md](../assets/templates/review-report.md)。报告包含目标、范围、基线、权威文档、实际检查对象、发现、证据、严重度、修复方向、未执行项和剩余风险。

Review 报告不复制现行设计。长期结论变化时更新权威设计并从报告链接。

## 发现状态

| 状态 | 含义 |
| --- | --- |
| 待处理 | 问题已确认，尚未处理 |
| 处理中 | 正在修复 |
| 已关闭 | 已修复并取得回归证据，或已记录接受风险、后续迭代或阻塞原因 |

阻塞原因、接受风险和技术后置分别写在说明中，不扩展 Review 状态枚举。

修复只处理 Review 已确认问题和 S5 本期变更清单允许范围。修复后重新执行目标回归，再由独立 Reviewer 复审。

## 完成门禁

- 单个 TASK 完成实现和自 Review 后先停在待人 Review；收到用户或项目指定 Reviewer 的明确通过后，才允许提交并进入下一任务。用户明确授权连续执行时，也不得合并多个 TASK 的 Review、提交或验收。
- 工作包级通过后才标记 `WP-XX` 完成。
- 整体级通过后才进入 S15。
- 阻塞问题和未处理的高风险问题未关闭时不得通过。
- 接受风险和技术后置必须有明确的人、边界、后续迭代或触发条件。

S15 使用 [delivery-acceptance.md](../assets/templates/delivery-acceptance.md) 固定联调、验收、上线和回滚证据。
