# 迭代生命周期

## 区分两类内容

长期有效设计保存当前需求事实、模型、流程和有效协议。确认发生长期变化时更新权威文档，通过 Git 保留历史差异。

迭代执行记录保存项目计划、沟通、AI 执行计划、任务记录、Review、联调和验收结果。每份记录带迭代标识，关闭后不覆盖为下一迭代内容。

`README.md` 只保留长期业务域信息。`Progress.md` 记录当前迭代的过程位置、阻塞和下一步。

## 确定迭代标识

优先使用项目已有版本号、需求号或项目编号。没有既有标识时，由人在 `Progress.md` 确认一个业务域内唯一的短标识。

不要根据目录名或日期自行替代项目已经采用的标识。

## 过程状态

迭代不另设规划中、执行中或验收中等全局状态。当前 `P/S` 和步骤状态已经表达过程位置。

迭代只记录两种终止结论：

- `已结束`：正常完成并保留执行记录；
- `已取消`：人终止迭代，并保留原因和影响范围。

## 并行迭代

通常一个 `Progress.md` 只维护一个当前迭代。

确有并行迭代时，在同一 `Progress.md` 中按迭代标识分开记录位置、阻塞和下一步；迭代专属路径必须包含迭代标识。

禁止多个迭代共同覆盖一份项目开发计划、AI 执行计划、任务记录、Review 报告或验收报告。

多个迭代修改同一长期权威文档时，先检查影响和冲突。无法确定采用顺序时交由人决定。

## 关闭迭代

1. 确认长期结论已回填权威需求、模型、流程和协议。
2. 固定计划、沟通、任务、Review、联调和验收记录。
3. 在 `Progress.md` 记录“已结束”或“已取消”、原因和影响范围。
4. 需要独立关闭记录时，使用 [iteration-closeout.md](../assets/templates/iteration-closeout.md)。
5. 在大阶段六的历史迭代索引链接原位置，不移动仍被引用的文件。
6. 把未完成项、接受风险和升级触发条件转入明确的后续迭代或观察清单。
