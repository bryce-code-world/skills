# 验收

## 一、硬性底线

任一项失败时不交付：

- 主要定义、步骤、公式、单位、边界或异常与来源冲突。
- 页面暗示了来源未支持的因果、时间、比例或物理机制。
- 演化页面把时间相邻当成因果，或把当前形态暗示为唯一、最优、必然结果。
- 最终产物不是单 HTML，或断网后 `file://` 无法使用。
- 存在外部资源、网络请求、动态代码执行、密钥或无关敏感信息。
- 主要操作无法用键盘完成，核心信息只能通过悬停或颜色理解。
- 第一屏存在多个竞争性的视觉主体、当前问题或强调级主动作，无法识别唯一学习起点。
- 完成主要学习路径后没有整体关系总览，或总览不能回看关键节点。
- 一个控件同时承担模式切换和重置等不同意图，或标签与实际行为不一致。
- 同一学习状态在进度、主对象、活动视图、当前解释或总览节点中显示不一致。
- JavaScript 正常时，静态降级内容形成第二条主线或允许绕过渐进揭示。
- 窄屏重排颠倒当前任务的语义顺序，或让辅助信息、未来状态先于当前问题和主动作出现。
- 静态结构在 JavaScript 失败时不包含学习目标、主要规则和边界。
- 静态校验、浏览器或认知测试没有实际执行，却声称已经通过。
- 未获授权时覆盖已有 HTML。

## 二、事实与模型

1. 建立不依赖 HTML 的事实基线。
2. 逐项核对定义、步骤、公式、符号、单位、范围和异常。
3. 对每个可操作参数选择正常值、边界值和异常值。
4. 在全部可操作范围内检查不变量。
5. 按最小状态表执行前进、后退、分支、回看、视图切换和重置，检查所有派生显示同步。
6. 检查重置后能否回到准确初始状态，普通视图切换是否保持当前学习状态。
7. 检查辅助视图是否引入了第二主线或新事实。

演化模型额外检查：

1. 阶段顺序、阶段状态和转变驱动是否有来源支持，并区分事实、因果推断和未知。
2. 每次转变是否明确标出继承、新增、改变和淘汰的结构。
3. 每次转变是否同时展示收益与新代价，而不是只展示“进步”。
4. 当前关键结构能否追溯到首次引入或最后改变的阶段。
5. 合理分支、适用条件和证据缺口是否可见。

## 三、离线与静态

1. 运行当前系统的原生 `validate_html` 适配器；不可用时按协议降级。
2. 确认 PowerShell 和 Shell 适配器没有调用 Python、Node.js 或其他额外运行时。
3. 断开网络或阻止请求后，使用 `file://` 打开。
4. 确认没有相邻资源依赖，重新打开后仍能从初始状态使用。
5. 分别在 JavaScript 正常和不可用时检查静态降级：正常时不竞争主线，不可用时仍能读取核心关系。
6. 检查中文、公式、图标和内联图形没有乱码或缺失。

## 四、浏览器与无障碍

1. 在当前可用的现代 Chromium 或 Edge 中实际打开。
2. 检查桌面宽度和窄屏宽度，确认无遮挡、截断、不可控溢出或认知顺序颠倒。
3. 逐个操作按钮、输入、滑块、拖拽、播放、暂停和重置，核对标签与行为只有一个明确意图。
4. 覆盖前进、后退、每条分支、总览回看、继续学习、再次进入总览、模式切换和重置的状态组合。
5. 只用键盘完成主要学习路径，检查焦点顺序和可见性。
6. 启用减少动画偏好，确认核心关系仍可观察。
7. 检查控制台错误、页面初始化失败和无效输入的可行动提示。

## 五、认知

先自检，再在误解后果高、结构新颖或自身把握不足时，请独立读者测试。

只提供主题文档和最终 HTML，不提供预期结论。请读者：

- 说出第一屏理解到的学习目标。
- 不接受提示，指出第一步应该操作什么；如果出现多个合理入口，认知验收失败。
- 完成主要操作并复述动作与反馈的关系。
- 完成后借助总览复述整体关系，并回看一个节点的局部解释。
- 从总览回看一个节点，继续或后退后再次进入总览，判断进度、解释和选中节点是否仍代表同一状态。
- 区分模式切换与重新开始；如果控件名称、结果或状态保留方式出乎预期，认知验收失败。
- 说出至少一个不变量和一个边界或异常。
- 对演化模型，说明一个当前结构为何存在，并判断当前结果是否被误解为必然或最优。
- 只报告误解、歧义、错误直觉、操作障碍和对应位置，不直接重写页面。

只根据可复现的理解问题执行最小修改。
