# 交互路由

## 一、选择顺序

1. 确定最影响理解的一种关系。
2. 使用下表选择一个主认知模型。
3. 其他关系只能成为服务同一目标的辅助视图。
4. 能用静态图清楚表达时，停在静态图。

| 主要关系 | 主模型 | 学习者动作 | 必须可观察的反馈 |
|---|---|---|---|
| 顺序、分支、状态转换 | 阶段流程 | 前进、后退、选择分支或角色 | 当前状态、已完成路径、下游影响和异常路径 |
| 因果、反馈、系统联动 | 因果沙盘 | 改变一个条件或开关 | 影响的传播、放大、阻断、延迟和结果 |
| 参数、公式、函数、几何 | 公式联动 | 拖动参数、数轴或控制点 | 公式、数值、曲线、几何和单位同步变化 |
| 连续运动、力、能量、时间过程 | 动态模拟 | 播放、暂停、慢放、拖动或改变初值 | 位置、速度、矢量、轨迹、能量或波形 |
| 层级、组成、抽象关系 | 分层探索 | 展开、收起、聚焦、钻取和返回整体 | 当前层级、上下级关系、组成和关联高亮 |

## 二、实现路由

```text
语义 HTML 和 CSS
    ↓ 不足
原生表单控件和 DOM
    ↓ 不足
内联 SVG
    ↓ 只有连续高频重绘才继续
Canvas
```

- 流程、关系、函数曲线和可拖拽几何默认使用 SVG。
- 连续轨迹、粒子或大量动态图元才使用 Canvas。
- 数学表达式默认使用 MathML；无法可靠转换时保留精确原式和变量说明。

## 三、反模式

- 为显示能力同时放入多个主交互。
- 把欢迎页、数字卡片、装饰性 Hero 或功能介绍当作学习路径。
- 只有悬停才能读到的重要内容。
- 用颜色作为状态的唯一编码。
- 用不真实的动画速度、空间比例或平滑效果暗示错误机制。
- 为普通页面引入 React、构建工具、服务器或外部图表库。
- 把一个轻量理解检查扩展成课程、账号、积分或学习记录系统。
