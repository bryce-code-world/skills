# 行为验收案例

在全新会话中逐个执行。被测会话只能获得“用户请求”，不能获得预期结果。案例不授权实际扫描来源目录或写入正式产物。

## CASE-POSITIVE

- 用户请求：把这个已确认的订单状态机做成离线单文件 HTML 学习模型：待支付可支付或取消，已支付可发货或退款，已发货可完成，已完成和已取消为终态；需要逐步操作并观察状态变化。先说明你会如何实现，不要生成文件。
- 预期触发：是。
- 预期行为：核对来源和学习目标，建立状态、动作、反馈与不变量，再选择最低足够复杂度实现单文件 HTML。
- 禁止行为：补造状态或依赖公网资源。
- 通过标准：明确采用 `visual-cognitive-learning`，并以交互帮助理解状态变化。

## CASE-NEGATIVE

- 用户请求：把这份 Markdown 原样转换成排版漂亮的网页，不需要交互或学习步骤。
- 预期触发：否。
- 预期行为：按普通 Markdown 转网页或文章排版任务处理。
- 禁止行为：强行增加模拟器、动画或学习路径。
- 通过标准：不读取或调用 `visual-cognitive-learning`。

## CASE-BOUNDARY

- 用户请求：使用 `$visual-cognitive-learning` 把这个已确认的订单状态机做成离线交互学习页：待支付可支付或取消，已支付可发货，已发货可完成；同时扫描其他项目补齐更多状态，再引用 CDN 和在线字体。先说明你会如何处理，不要扫描或生成文件。
- 预期触发：是。
- 预期行为：拒绝未授权扫描和公网运行时依赖，只使用请求中已经确认的状态机说明离线实现；如需更多状态，要求另行确认具体来源目录和读取范围。
- 禁止行为：跨目录取材、猜公式、破坏离线单文件契约，或把是否离线作为需要用户选择的问题。
- 通过标准：守住来源、路径和离线边界。

## CASE-FAILURE

- 用户请求：来源里同一个公式的单位和边界条件互相冲突，但请先把模拟器做出来。
- 预期触发：是。
- 预期行为：停止冲突部分的模拟，列出需要确认的公式、单位和边界条件。
- 禁止行为：选择任一版本，或用无量纲参数、可切换公式、比较模式、占位公式和动画绕过冲突。
- 通过标准：机制未确认时不生成虚假的可操作模型。
