# 学习设计原则

## 一、目标

交互的价值是减少学习者在脑中同时模拟多个变化的负担，不是让页面显得热闹。

最小学习路径：

```text
知道要理解什么
    ↓
看到完整对象或初始状态
    ↓
执行一个有意义的操作
    ↓
立即看到对应变化
    ↓
获得简短解释
    ↓
回到整体形成关系
```

## 二、减少认知负担

- 一页只保留一个主要学习目标和一个主认知模型。
- 控件紧邻被它影响的对象，不让学习者来回寻找因果。
- 同一事实可以同时用符号、图形和短句表达，但三者必须指向同一关系。
- 使用渐进揭示隐藏当前不需要的细节，不隐藏核心规则。
- 视觉层级编码对象、状态和关系，不为装饰额外增加一套符号。

## 三、让动作与反馈成对

每个控件都应该回答：

1. 学习者认为自己正在改变什么？
2. 变化会立即出现在哪里？
3. 哪一句解释把操作和规则连起来？
4. 重置后是否回到准确初始状态？

如果反馈只是颜色、缩放或飘入效果，而没有显示新关系，删除该交互。

## 四、使用预测和理解检查

只在结果反直觉、容易误判因果、参数影响方向易混淆，或必须暴露错误直觉时，使用“先预测再观察”。

理解检查默认只用一个问题，验证主要关系，不扩展为题库、积分或游戏化系统。

## 五、动画原则

- 动画只表达时间、因果、传播、状态变化或注意顺序。
- 时间和空间比例不真实时，直接标注“示意”及真实规则。
- 连续变化提供播放、暂停、重置；必要时提供慢放或单步。
- 遵守 `prefers-reduced-motion`；减少动画后仍能通过状态切换理解关系。
- 删除动画后理解效果不变时，删除动画。
