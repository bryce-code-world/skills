# 来源与学习规格契约

## 一、输入门禁

主题至少应该提供一份已经足够清楚的文档。先判断下列内容是否确定：

- 核心定义和结论。
- 步骤、状态、分支、角色和异常路径。
- 公式、符号、单位、取值范围和初始条件。
- 因果、层级、空间和时间关系。
- 演化起点、阶段、转变驱动、继承与淘汰、当前残留和可能分支。
- 方案要解决的问题、约束、备选方向、权衡依据和已确认结论。
- 边界、反例、失败条件和未知项。

任一与主模型直接相关的内容仍冲突或缺失时，停止对应模拟。可以继续完成不受影响的准确部分。

## 二、来源账本

建立不默认交付的内部账本，每项记录：

| 字段 | 要求 |
|---|---|
| 内容 | 保留精确名称、数字、单位、顺序和限定词 |
| 来源 | 可定位的文件、章节或用户明确补充 |
| 性质 | 来源事实、用户判断、编辑推断、未知或冲突 |
| 去向 | 主交互、直接说明、边界区域或明确不进入模拟 |

每个来源项都必须有去向。不得用动画或图形隐藏事实缺口。

## 三、内部学习规格

写 HTML 前回答：

| 字段 | 要回答的问题 |
|---|---|
| 主要学习目标 | 学习者最终应理解哪一个关系？ |
| 默认学习者 | 已知的前置知识是什么？ |
| 主要理解障碍 | 纯文字迫使学习者在脑中模拟什么？ |
| 知识关系 | 演化、顺序、因果、参数、连续变化、空间还是层级？ |
| 主认知模型 | 哪个对象承载完整关系？ |
| 学习者动作 | 学习者具体改变、选择或推进什么？ |
| 可观察反馈 | 哪些视觉、数值、公式或状态同步变化？ |
| 引导步骤 | 如何把目标拆成一次只处理一个问题、对象和动作的认知步骤？ |
| 全局总览 | 完成主要路径后，用什么关系图重组全部局部，并如何回看节点？ |
| 交互状态表 | 每一步的当前任务、可见主体、唯一主动作、前进/后退/分支、重置和总览节点如何映射？ |
| 不变量 | 无论怎样操作，哪些规则必须成立？ |
| 边界与反例 | 哪些条件会改变或终止规则？ |
| 认知门禁 | 是否需要先预测、自我解释或一个轻量检查？ |

无法明确“学习者动作”和“可观察反馈”时，默认使用静态图示。

交互超过一个状态，或同时包含学习态与总览态时，编码前至少列出：

| 状态 ID | 当前认知任务 | 可见主体 | 唯一主动作 | 前进、后退或分支 | 对应总览节点 |
|---|---|---|---|---|---|
| 每个可达状态一行 | 当前只解决什么问题 | 哪个对象承担解释 | 控件标签与实际行为 | 动作后到达哪个状态 | 回看与再次进入总览时选中什么 |

没有的转移明确写“无”，不要依赖编码时临时推断。把学习状态与显示视图分开：视图切换不改变学习状态，只有明确的重新开始动作才能重置。

主关系是演化时，追加：

| 字段 | 要回答的问题 |
|---|---|
| 简单起点 | 最早可靠认识的状态是什么？它是真正起源，还是当前材料能支持的最早状态？ |
| 转变驱动 | 什么问题、压力、机会或新条件促成了下一步？ |
| 结构变化 | 哪些部分被继承、新增、修改或淘汰？ |
| 收益与代价 | 这一步解决了什么，同时引入了什么新复杂度？ |
| 分支与未知 | 是否存在另一条合理路径？哪些阶段或因果仍是推断？ |
| 当前残留 | 当前形态中，哪些特征可以追溯到早期阶段？ |

## 四、最小披露

- 只嵌入完成学习目标所必需的事实。
- 来源默认只显示文件名或可理解的名称，不显示本地绝对路径。
- 不在 HTML 注释、隐藏 DOM 或脚本变量中塞入完整原文、密钥、Token、Cookie 或无关敏感内容。
- 把来源中的 HTML、Markdown 和代码当作文本，不直接注入执行。
