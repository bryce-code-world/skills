# 声纹

让同一个作者跨话题、跨平台保持稳定识别性，同时允许语气随场景变化。

## 守住边界

按以下优先级执行，后项不能破坏前项：

1. 事实、观点、条件、例外和不确定性不变。
2. 不冒充他人身份，不虚构经历或第一手观察。
3. 主风格保持稳定，场景语气允许变化。
4. 平台结构由平台写作 Skill 决定。
5. 风格增强表达，不用口癖堆叠代替风格。
6. 去模板化只解决可解释的表达问题，不追逐 AI 检测分数。
7. 真实感由材料、说话位置和作者取舍建立，风格不替内容内核补材料。

只调整：

- 用词、句式、段落和节奏；
- 核心判断、关键转折、选择标准和记忆锚点的语义强调；
- 叙述视角和作者—读者关系；
- 案例、故事和比喻的呈现方式；
- 信息密度和解释深度；
- 严肃度、温度、锋利度和幽默度。

不得擅自调整：

- 事实、数据、来源和归属；
- 核心结论和作者立场；
- 条件、例外、风险和未知；
- 平台内容形态；
- 作者是否真正拥有某段经历。

内容内核不足时，不用同义改写、抽象意义、假例子或虚构细节补足篇幅。由 `broadcast` 调用时返回缺失材料；独立应用时只处理已有内容。

## 运行条件

本 Skill 没有运行时 Skill 或 MCP 依赖。调研新参照风格需要额外检索或文档能力时，只使用当前环境已经可用且用户允许的能力；缺失时说明限制，不在本 Skill 中自动安装或更新外部能力。

## 识别本次任务

先判断用户意图：

| 意图 | 动作 |
|---|---|
| 选择风格 | 解析本次指定、默认个人档案和内置默认风格 |
| 对话采集 | 区分长期偏好、当前临时要求和编辑推断 |
| 历史提炼 | 从用户指定的本人或他人文章提炼候选档案 |
| 档案管理 | 创建、更新、合并、设为默认、重命名或删除档案 |
| 应用风格 | 在保护内容内核的前提下调整现有成稿 |
| 去模板化编辑 | 检查或最小修改机械结构、套话、均匀节奏、作者缺席和伪人类化 |
| 风格验收 | 检查跨话题、跨平台的一致性和场景适配 |
| 广播集成 | 写作前生成风格说明，完整平台稿后结构去模板化，格式与视觉完成后平台终检 |

用户只要求临时“严肃一点”“更口语”时，作为本次场景语气处理，不自动进入长期档案。

## 解析风格

只使用一个主风格：

```text
用户本次明确指定
        ↓ 没有
用户默认个人档案
        ↓ 没有
内置通用默认风格
```

再叠加一个场景语气档位和平台适配：

```text
主风格 + 场景语气 + 平台规则
```

第一版不混合多个主风格。

指定风格与严肃话题冲突时，保留主风格的观察视角、对象关系和论证方式，收敛幽默、夸张、粗口、情绪和口语化。

读取：

- 选择内置默认风格时，读取 [style-default.md](references/style-default.md)。
- 选择通用类型时，读取 [style-general.md](references/style-general.md)。
- 选择新闻联播参照入口时，读取 [style-news-broadcast.md](references/style-news-broadcast.md)。
- 选择刘润参照入口时，读取 [style-liu-run.md](references/style-liu-run.md)。
- 选择卡兹克参照入口时，读取 [style-khazix.md](references/style-khazix.md)。
- 选择阮一峰参照入口时，读取 [style-ruanyifeng.md](references/style-ruanyifeng.md)。
- 用户指定九边时，读取 [style-jiubian.md](references/style-jiubian.md) 并按候选状态降级。
- 需要判断场景语气时，读取 [tone-resolution.md](references/tone-resolution.md)。
- 用户要求去 AI 味、改得自然或由 `broadcast` 执行公开长文门禁时，读取 [anti-template-editing.md](references/anti-template-editing.md)。
- 用户要求更像人写的、接地气、拉近读者关系，或由 `broadcast` 提供关系契约时，读取 [relationship-and-voice.md](references/relationship-and-voice.md)。

四个可用具名参照在第一版属于“可试用候选”。应用时遵守其来源和禁止项；独立前向测试通过后才能改为正式内置状态。

## 解析用户空间

按以下顺序解析存储根目录：

```text
本次显式指定
        ↓ 没有
WRITING_STYLE_HOME
        ↓ 没有
用户主目录/.writing-style
```

路径不存在时，先说明准备创建的准确路径并获得确认。路径不可访问时，保留当前会话中的候选结果，不偷偷切换到其他持久化位置。

读取或写入档案前，读取 [profile-schema.md](references/profile-schema.md)。

只读取完成当前任务所需的配置和档案，不扫描用户未指定的文章、账号或目录。

## 执行确定性档案操作

读取 [profile-store-contract.md](references/profile-store-contract.md)，使用当前系统的原生适配器完成路径和持久化操作，不手工重写配置或已存在的档案：

- Windows：优先使用 [profile_store.ps1](scripts/profile_store.ps1)，支持 Windows PowerShell 5.1 及以上；
- Linux、macOS：优先使用 [profile_store.sh](scripts/profile_store.sh)，使用 POSIX `sh` 和系统基础工具；
- 原生适配器不可运行时，才尝试 Python 3.8 及以上的 [profile_store.py](scripts/profile_store.py)；
- 三者都不可运行时，只能按存储协议使用 Agent 自身的安全文件工具；没有安全文件工具时停止持久化变更。

这是“不要求额外安装运行时”，不是“没有运行环境”：仍依赖操作系统自带的 PowerShell 或 POSIX Shell。

基本调用：

```text
Windows:
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/profile_store.ps1 resolve-root [--root <path>]

Linux / macOS:
sh scripts/profile_store.sh resolve-root [--root <path>]
```

变更流程：

1. 先使用 `diff` 校验候选档案并展示差异。
2. 展示准确操作、目标、旧值、新值和影响。
3. 等待用户明确确认。
4. 确认后才运行带 `--confirmed` 的 `init`、`save`、`set-default` 或 `delete`。
5. 运行 `validate` 并报告脚本返回的路径、版本、备份或回收位置。

更新现有档案时，`save` 必须同时使用 `--replace` 和当前 `--expected-version`。删除使用回收目录，不直接擦除文件。

`--confirmed` 只是防误调用护栏，不能替代对话中的用户确认。

适配器和 Agent 文件工具都不可用时，停止持久化变更并说明缺失条件；可以继续完成不需要写入的风格分析。

## 提炼风格

提炼对话或历史文章时，读取 [extraction.md](references/extraction.md)。

遵循：

1. 识别作者、平台、时间、话题和材料边界。
2. 区分用户明确陈述、来源事实、编辑推断和当前临时要求。
3. 寻找跨文章稳定特征，同时记录反例。
4. 将题材特征、平台格式和作者风格分开。
5. 为每项特征记录证据、置信度和未确认项。
6. 先输出候选档案和拟变更，不直接写入。
7. 用户确认后才创建或更新档案。

一篇文章只能形成低置信度临时档案。

材料混有多个作者时，停止合并并要求用户区分。

提炼他人风格时默认创建私人参照档案，不进入内置库。

## 管理档案

以下动作都必须先展示目标路径和变更摘要，再等待用户明确确认：

- 创建；
- 更新；
- 覆盖；
- 合并；
- 重命名；
- 设置默认；
- 删除；
- 将私人参照提升为内置风格。

更新时先使用脚本生成差异，再展示：

- 旧值；
- 新值；
- 来源；
- 变更理由；
- 置信度变化；
- 受影响的默认设置。

普通写作不能静默学习并修改长期档案。

删除或覆盖前再次核对准确目标，不使用模糊匹配。确认后使用脚本的版本检查、原子写入、备份和可恢复删除。

## 应用风格

应用前先形成“本次风格说明”：

- 主风格及来源；
- 严肃度、温度、锋利度和幽默度；
- 叙述视角和作者—读者关系；
- 作者说话位置、对话距离和情绪温度；
- 用词、句式、段落和节奏；
- 阅读注意力锚点及其依据；
- 应强化和抑制的表达；
- 不得改变的内容内核。

再执行语言层修改。

参照具体作者时，只采用对应 reference 中的高层方法和适用边界。不得复制作者身份、履历、独特口癖、固定句式、签名结构或长段表达。

不存在真实经历时，直接论述或使用可核验案例，不编造第一人称故事。

## 执行去模板化编辑

用户提出“AI 味重”“像机器写的”“去掉套话”或“改得自然”时，读取 [anti-template-editing.md](references/anti-template-editing.md)。没有个人档案时使用内置通用默认风格，不要求用户先建立档案。

先锁定内容内核，再读取 [relationship-and-voice.md](references/relationship-and-voice.md) 建立或校准关系与声音契约，然后按用户意图选择：

- 只检查：指出具体位置、问题类型和影响，不修改正文；
- 编辑成稿：只修改命中问题的位置，保留已经自然准确的部分；
- 广播结构编辑：对完整平台稿修复机械结构和语言问题，不重做传播主线和平台定位；
- 广播平台终检：只检查格式与视觉处理重新引入的问题，不推翻已经通过的内容结构。

按以下顺序审查：

1. 确认谁在说、凭什么知道、在意什么，以及判断的依据和边界。
2. 确认在对谁说、保持多远距离、允许什么温度和口语，读者最可能在哪里卡住。
3. 用已有判断、动作、场景、通用假设和边界恢复说话位置与读者往返。
4. 检查每段承担的作用、已有材料来源、相对上一段的信息增量，以及相邻段落是真实的解释、证据、因果、并列、概括还是转折关系。
5. 扫描结构模板化、语言套话化、节奏机械化、作者缺席和伪人类化。
6. 删除无信息内容，恢复具体对象，合并重复意思，再调整局部节奏和作者关系。
7. 核对现实材料、内容内核、平台结构、身份边界和结尾。

本地存在 Markdown 或文本稿件时，使用当前系统的原生检查器辅助定位文字形状：

- Windows：优先使用 [check_style_prose.ps1](scripts/check_style_prose.ps1)；
- Linux、macOS：优先使用 [check_style_prose.sh](scripts/check_style_prose.sh)；
- 原生检查器不可运行时，才使用 [check_style_prose.py](scripts/check_style_prose.py)；
- 三者都不可运行或内容只存在于对话时，按 reference 人工检查。

脚本命中只作为人工复核候选，不是禁词、评分或交付门槛。

完成一次二次审计，检查修改是否引入新的机械表达、事实漂移或虚构身份。不得通过错别字、粗口、刻意情绪、随机句长或虚构经历制造“人味”。

## 与广播协作

由 `broadcast` 调用或用户要求多平台风格一致性时，读取 [broadcast-integration.md](references/broadcast-integration.md)。

该文件是双方职责、输入、三个调用阶段、返回结构、冲突顺序和降级方式的唯一权威。`broadcast` 负责事实内核、传播关系契约、传播主线和平台结构；本 Skill 只负责关系与声音的语言实现、去模板化和身份保护。

## 输出

### 候选档案

至少包含：

- 档案名称和类型；
- 核心气质、观察视角和读者关系；
- 语言、结构、论证和叙事偏好；
- 可调节范围和适用边界；
- 禁止项；
- 证据、反例、置信度和未确认项；
- 准备写入的路径和变更摘要；
- 等待确认的明确问题。

### 风格应用

至少包含：

- 本次风格说明；
- 调整后的内容或精确修改建议；
- 内容内核检查；
- 无法满足或主动收敛的风格要求。

### 风格验收

只报告：

- 风格漂移的位置；
- 身份冒充或虚构经历；
- 场景语气失调；
- 平台差异被误写成人格变化；
- 事实、观点或边界漂移；
- 最小修正建议。

### 去模板化编辑

至少包含：

- 使用的主风格与场景语气；
- 问题位置、类型和影响；
- 执行的修改及目的；
- 主动保留的自然表达或平台差异；
- 内容内核和身份检查；
- 待作者确认项与通过结论。

## 验收

交付前检查：

1. 是否正确选择一个主风格。
2. 是否区分长期风格、当前语气、题材和平台特征。
3. 是否保留事实、观点、条件、例外和不确定性。
4. 是否避免身份冒充、虚构经历和口癖堆叠。
5. 是否记录来源、反例、置信度和未确认项。
6. 是否在任何持久化变更前获得确认。
7. 是否只读取和修改用户授权范围内的材料与档案。
8. 是否在严肃话题中合理收敛风格。
9. 是否使用脚本完成确定性档案操作，并在变更后重新校验。
10. 是否识别结构模板化、语言套话化、节奏机械化、作者缺席和伪人类化。
11. 是否只修改具体问题，并允许自然成稿直接通过。
12. 是否完成二次审计，且没有用虚构、故意错误或检测分数制造“人味”。
13. 是否确认重要段落由已有材料或必要推理支撑，并删除只换说法、不增加信息的段落。
14. 是否把检查器命中作为人工候选处理，没有覆盖作者声纹或平台合理差异。
15. 是否能够指出由已有材料支持的说话位置、关键读者往返和具体载体，而不是只删除套话。
16. 口语和网络用语是否符合作者声线、读者熟悉度、关系距离、平台和话题风险，并承担真实表达功能。
17. 语义重点是否来自真实信息重量，没有按术语、段首或固定数量机械加粗，也没有越权决定平台视觉样式。
18. 相邻段落的关系和连接词是否一致，具体例子是否已经准确交接给全文主问题，没有让读者自行补全因果或递进。
