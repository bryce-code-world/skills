# 测试主题：从一个选题到一条视频

本文件仅用于**介绍 ai-multi-media-kit 本身**的样例任务，不是其他产品视频的默认定位，也不是通用主 Skill 的品牌背景。

## 观众与核心价值

观众是个人创作者和小型内容团队，而不是正在比较 Agent 安装方式的用户。

主要问题：AI 能写几段文字，但知识库、脚本、素材、配音、字幕、剪辑、质量检查之间仍需要人逐项组织、搬运和返工。

核心价值：把一个内容需求组织成可重复执行的视频生产流程。AI 负责创作与判断；成熟工具负责执行；脚本、配音、素材、成片和审核记录留下可追溯版本。不是一个“全程保证高质量/全平台必定发布”的承诺。

## 用一个任务展示价值

用用户提供的一段产品资料，展示它如何变成可观看、可修改的视频：

- 展示原始材料与**独立真实成片片段**，让观众看到输入、结果和少做的操作；禁止把本片前面几个镜头剪一份，再作为“生成效果”嵌回本片。
- 从脚本修改、素材选择、配音字幕或定点修订中选最能解释结果的过程。让变化前后的内容可见，不只展示“审核通过”字样。
- 用可编辑工程或一次实际修改说明成果能继续使用。审核分数、文件目录和波形属于辅助证据，不承担产品价值证明。

无需把每个内部工序拍成一页。可以做标注清楚的原创示意，但不能把伪造产品界面称为录屏，也不能把模板知识库称为已验证品牌数据。缺少真实结果时如实说明演示范围。

## 60 秒表达优先级

**本次介绍对象就是 `ai-multi-media-kit`，不是抽象的 AI 工作流。** 前 3～5 秒给真实痛点，**第 2 个镜头（前 12 秒内）用画面写出 `ai-multi-media-kit`，口播说出它的自然名称（如 AI Multi Media Kit）**，让观众立刻知道谁解决问题。中间解释这套 Skill 怎样把选题、分镜、音频、字幕、剪辑和检查衔接起来，并展示真实独立产物。结尾回到 `ai-multi-media-kit` 与用户可得到的结果，避免一直用“它”“这个 AI 工具”代替名字。

专业分镜设置 `video_purpose: product_intro`、`subject_name: ai-multi-media-kit` 和 `subject_spoken: AI Multi Media Kit`，这是 **Agent 内部参数，不要求普通用户写**。缺名称或没有在开头/结尾点名的分镜必须返工；只有字幕/封面里小字出现一次名称也不算真正介绍。

主体围绕任务推进和结果变化安排节奏，不规定过程占比。画面能表达的信息不再用旁白重复；完整流程和详细验收留在项目记录。

结尾收束为“少做流程搬运，把精力留给内容”。跨 Agent 兼容、共享环境和自有资产是辅助优势，最多最后一句补充；不要使用“换 Agent 就必然重装”作为主要问题。

## 不能混入观众版视频的测试细节

安装、路径、版本号、哈希、配音槽位表、工具命令、自评分数和回归测试数量留在工程报告。也不为把本片自己的最终截图或 PASS 结果拍进本片而额外渲染一轮；需要结果示例时使用已完成片段。

不虚构“全平台自动投稿”“隐私永不离开本机”“一键必出优质大片”“效率提高若干倍”等未验证结论；如果本条 MP4 仍是 `technical_only` 且未完成真正试听/事实审稿，不写“本片能直接发布”，只能说“生成了可检查、可编辑的 MP4”。未安装的引擎只在技术报告说明，不必为解释测试环境占用介绍视频的大段口播。

## 对应脚本策划字段

`editorial_intent.primary_value` 说明用户少做哪些操作、得到什么可见成果；`secondary_values` 可包括跨宿主复用、自有知识库和成果归属；`evidence_plan` 指出要展示的实际变化。审核 `focus_alignment` 要对照最终口播与镜头，不能仅凭流程占比、字段齐全或自评分数标 PASS。
