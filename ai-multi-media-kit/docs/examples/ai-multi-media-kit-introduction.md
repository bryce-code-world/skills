# 测试主题：从一个选题到一条视频

本文件仅用于**介绍 ai-multi-media-kit 本身**的样例任务，不是其他产品视频的默认定位，也不是通用主 Skill 的品牌背景。

## 观众与核心价值

观众是个人创作者和小型内容团队，而不是正在比较 Agent 安装方式的用户。

主要问题：AI 能写几段文字，但知识库、脚本、素材、配音、字幕、剪辑、质量检查之间仍需要人逐项组织、搬运和返工。

核心价值：把一个内容需求组织成可重复执行的视频生产流程。AI 负责创作与判断；成熟工具负责执行；脚本、配音、素材、成片和审核记录留下可追溯版本。不是一个“全程保证高质量/全平台必定发布”的承诺。

## 必须展示的生产机制

围绕一个具体任务展开，而不是朗读功能列表。例如“给小团队做一条产品功能介绍视频”：

- 从资料或知识库确定受众、核心价值和表达方式，形成选题与脚本。
- 按标准审核并修稿；区分事实、宣传主张与尚未验证的内容，不靠自评分数冒充质量。
- 选择与分镜对应且有授权的素材；将旁白做读音预检，按真实语音配时并校准字幕。
- 由 FFmpeg 或实际可用的视频工具合成 MP4；检查音轨、字幕、画面与节奏，存在问题自动返工。
- 输出视频、脚本、素材来源、审核记录；有条件时另生成平台适配包，生成包不等于已发布。

可视证据优先来自本次真实脚本变化、输入文本、剪辑时间轴、成片片段和审核发现。可以做标注清楚的原创示意，但不能把伪造产品界面称为录屏，也不能把模板知识库称为已验证品牌数据。

## 60 秒表达优先级

前 3～5 秒用“给出一个选题，后面的脚本、素材、配音、字幕和剪辑能不能接着做？”这样的真实痛点开场。

主体约四分之三时间用于展示上述生产过程与背后机制。选择其中关键过程讲清楚，不必把每个命令或工具名字念一遍。

结尾收束为“少做流程搬运，把精力留给内容”。跨 Agent 兼容、共享环境和自有资产是辅助优势，最多最后一句补充；不要使用“换 Agent 就必然重装”作为主要问题。

## 不能混入观众版视频的测试细节

安装成功、路径核对、版本号、哈希校验、回归测试数量是工程测试报告内容，不是观众必须观看的主线。目录里有几款 Agent 的作品，也不能替代产品价值证明。

不虚构“全平台自动投稿”“隐私永不离开本机”“一键必出优质大片”“效率提高若干倍”等未验证结论。未安装的引擎只在技术报告说明，不必为解释测试环境占用介绍视频的大段口播。

## 对应脚本策划字段

`editorial_intent.primary_value` 应围绕**视频自动化生产工作流与质量闭环**；`secondary_values` 可包括跨宿主复用、自有知识库和成果归属；`evidence_plan` 必须描述打算给观众看哪些真实过程/结果。审核 `focus_alignment` 要对照最终口播与镜头，而不是看到这些字段填写了就标 PASS。
