# 代表性任务测试提示词

按本次要验证的能力选一段，不要求日常创作逐个执行。将占位符换成用户提供的路径和资料；不同 Agent 使用各自项目与真实身份。技术检查和实际视听结果分开记录，不能把安装测试写成宣传片主线。

## 单条视频：默认入口

```text
使用 ai-multi-media-kit，根据 __产品资料__ 制作 45～55 秒的 9:16 中文产品宣传视频，面向手机观看。重点讲现有痛点、产品带来的改变和能够展示的证据，不讲安装步骤；不虚构功能、效率数字或使用效果。

先读 SKILL.md，按单条制作路线执行。只读发现并复用已有工具工作区；确认 workspace.json 的 output_root 为 __OUTPUT_ROOT__，不一致时报告冲突，不另建环境。只补齐本次需要且已获授权的依赖，不要求我配置多平台账号、额外文本模型或企业知识库模板。

使用内置模板和真实、获准使用的素材；先做代表镜头及自然语音短样本，再完成独立工程和真实 MP4。字幕按实际音频配时，检查手机可读性、遮挡、完整旁白与转场。没有配音或试听能力时如实列出未验证项，不伪造审核通过。

不公开发布、不覆盖历史作品、不修改 Skill 源码。交付 MP4、工程绝对路径、实际 Skill/工作区版本、已做的技术与视听检查。不要逐阶段等待我批准。
```

## 已有视频：定点修改

```text
使用 ai-multi-media-kit 修改 __视频工程路径__ 的第 23～26 秒：将指定文案改为 __新文案__，其余旁白、镜头顺序和总时长保持不变。

先定位当前工程和已接受成片，复用依赖与时间轴，不重新初始化或新跑 studio quick。保留可恢复版本，先检查受影响片段和相邻转场，再导出完整 MP4；确认范围外内容和音画时序没有意外变化。旧审核记录不能冒充新版本验收。交付完整成片位置与实际验证范围，不发布。
```

## 安装更新与完整生产：集成验证

仅在需要验证安装、升级或企业审核流程时使用；这不是单条制作的默认前置。

```text
请获取或安全更新 ai-multi-media-kit，然后用完整生产流程制作一条介绍本套件的视频，不要只给方案。
源码：https://github.com/bryce-code-world/skills/tree/main/ai-multi-media-kit
唯一成果根目录：__OUTPUT_ROOT__

核对当前仓库提交和 references/release.json，要求 0.12.0 或更新。分别验证源 Skill、宿主已安装入口和共享工具工作区的真实版本，保留未知修改。已有有效工作区直接复用；工作区核心落后时，用新源码的 upgrade_core.py 先预览再备份应用。本任务授权所需安全更新，不改变路径、不覆盖用户资料，不修改系统 PATH。

读取完整生产子 Skill、内容契约及 docs/examples/ai-multi-media-kit-introduction.md。用 studio new 创建 topic=amk-workflow-intro 的独立项目，记录真实宿主；模型无法核实则省略 --model。所有成果及简短 TEST-REPORT.md 写入该项目目录。

制作 45～60 秒、9:16、中文配音和字幕的 MP4，优先 1080×1920，最低 720×1280。面向创作者和小团队，围绕一个真实内容任务展示从需求到视频的过程；安装、路径复用只记在测试报告。示意画面须标明，不能冒充真实录屏。

使用实际获准、费用明确的 TTS；先 speech-plan，根据已知读音风险改写正式口播和字幕，重跑计划后审核稳定脚本，再使用导出的逐镜头文本生成音频。任何后续改稿都重新审核，不能沿用旧哈希。按内容契约完成实际渲染、字幕布局与音轨检查，从最终 MP4 查看各镜头，并正常速度核对声音、同步和节奏；没有试听能力就保留未验收状态，不伪造 PASS。

最多三轮自主返工。只做制作测试，不设置 publish-target，不登录或投稿，不修改上游源码。报告分别记录工程结果、内容主线、实际视听证据、失败和未验证项；最终给出视频与报告路径、项目 ID、真实版本及使用音色。
```
