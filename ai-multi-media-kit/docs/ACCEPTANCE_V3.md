| A31 | 新 Agent 发现有效环境 | 共享索引与工作区三目录只读核验通过，不再询问路径、运行初始化或重复下载安装；第二次调用不修改已有资产或配置 |
| A32 | 防止第二套默认环境 | 新 Agent 指定另一工具路径默认被拒绝，已有索引无效或三路径冲突也拒绝新建；仅用户显式 `--new-workspace` 才可创建第二套 |
| A33 | 缺失索引恢复 | 已知真实旧工具路径时 `inspect` 只读验证，`register` 可重新登记；不需要重新初始化工作区或下载安装依赖 |
| A34 | TTS 音频装配 | `studio voiceover` 用 FFmpeg 重采样；音频连同 0.15 秒偏移不能超过槽位，末段尾音不被裁剪 |
| A35 | MP4 独立质量门禁 | AI 自报 PASS 不能覆盖真实音轨有效发声比例、异常静音及分镜时长校验；坏视频不可打包/发布 |
| A36 | 体验验收 | 真正试听发音/自然度、核对字幕时序，并抽查各场景与末尾画面；内容有具体案例/看点而非只排列功能卡片 |

## 如何验证

- 默认运行 `python -X utf8 -m unittest discover -s tests`：隔离测试覆盖安装复用、目录保护、内容审核、素材、音轨和发布范围。
- 快速视频的真实渲染需显式设置 `AI_MEDIA_QUICK_REAL_RENDER=1`，再运行 `tests/test_quick_video.py` 对应测试；实际依赖和浏览器必须可用。
- 对修改过的画面抽帧检查；需要音频质量结论时必须实际试听。技术通过、结构检查与创作验收分别报告。
- `doctor` 只证明其检查范围内的环境状态，不证明宿主音频输入、第三方账号、在线素材、MPT 或真实平台投稿可用。只有实际运行的项目才写为已验证。

## 内容与项目契约

| 项 | 验收边界 |
|---|---|
| A37 成果归属 | 同 topic 的两个 Agent 自动得到独立内容目录；model 未知为 null；run 不冲突；list 可按主题查询；旧数据不迁移或猜作者。 |
| A38 接力来源 | parent 指向同主题源项目并记录现有文件哈希，新项目不修改源文件，不继承未授权的发布范围。 |
| A39 发音预检 | 已知风险词触发 REVISE，内部排版换行/Tab 拒绝；改稿更新计划和审核，原始 take 按文本与实际合成设置决定复用，不混用旧装配记录。 |
| A40 主次与试听 | 新项目缺 editorial_intent/focus_alignment 不通过脚本门禁；成片缺真实时间点的 actual_audio_review 声明不通过；CLI 不保证语义判断或验收声明真实性。 |
| A41 兼容与升级 | 旧 --id 接口保留 schema3 兼容；新 --topic/--agent 为 schema4，不通过使用旧入口绕开新约束；新安装和核心升级包含发音词典及版本元数据。 |
| A42 模型标签入目录 | 已确认模型经安全规范化出现在新内容目录且原始 model_id 不丢失；未知为 model-unknown；长模型有哈希区分，旧成果不移动。 |
| A43 字幕布局安全区 | 自绘渲染声明的 bbox 预检阻断正文与字幕重叠、字幕越界；最终 MP4 逐镜抽帧确认字幕未遮挡重要内容，不能用纯字幕文本检测冒充画面验收。 |

以上代码与离线样本验证不等于各个 Agent 在真实 TTS 上已达到可发布品质；最终声音和画面需按实际宿主能力验收。已知词典之外仍可能存在错读。
