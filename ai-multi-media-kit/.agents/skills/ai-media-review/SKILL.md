# 脚本 AI 审核

1. 读取真实任务、`brief.md`、当前脚本、企业审核规则及证据。品牌/受众资料仍是未填模板时，不能声称品牌适配已验证。
2. **先检查方向是否正确**：对照 `editorial_intent.primary_value`，看开场、主体与收尾是否真的服务该价值；次级卖点和本次测试任务有没有抢占主线。不能仅因语句通顺、提及功能或工程测试通过就判为好脚本。新项目 `review.json` 必须包含 `focus_alignment: {result: PASS/REVISE, reason: 具体口播和镜头依据}`。
3. 检查开场 3～5 秒的看点、至少一个可验证的过程/案例/对比、镜头是否可执行、素材许可、自然口语与 TTS 时间槽。连续功能卡片、反复渲染同一弱脚本不是有效改进。
4. 发音预检发现的词要由 Agent 在不改变原义的前提下处理，并同步旁白与字幕；音频合成后的真实读音另行验收。不能把词典无命中、波形正常或 ASR 文字正确视为发音已经正确。
5. 用 `studio hash` 取得真实脚本/规则哈希。只有所有检查有依据且 PASS、`facts_to_verify=[]`、`issues=[]`，才能写 `result=PASS`；最多三轮自动修稿。CLI 只核验记录结构和版本，不能独立判断语义对齐或证明 Agent 真的看过/听过，严禁虚构证据。

审核不是账号授权，不请求用户逐阶段批准。成片须另按 `video/review.json` 验收，详见 `docs/CONTENT_SCHEMA.md`。
