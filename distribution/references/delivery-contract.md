# 分发输入、授权与状态契约

## 输入门禁

开始外部操作前确认：

- 目标平台和目标账号唯一明确；
- 文章 front matter 或等价元数据包含非空平台和唯一标题；
- 正文从导语开始，不重复发布标题；
- 封面和正文必需素材存在；
- 内容验收没有阻塞投递的问题；
- 目标动作是检查、预填、保存草稿或公开发布之一；
- 用户本次授权覆盖该动作。

来自 Broadcast 时读取 `05-验收报告.md`。`06-读者测试.md` 只有设计自检而没有独立冷读，不当然阻塞用户明确要求的投递，但必须在分发报告中如实保留该验收边界。

## 动作授权

| 动作 | 允许条件 |
| --- | --- |
| 只读检查 | 用户要求检查或投递该平台 |
| 预填编辑器 | 用户明确要求预填或投递 |
| 保存草稿 | 用户明确要求保存草稿或投递到草稿箱 |
| 首次登录和账号选择 | 用户本人参与，并确认目标账号 |
| 覆盖、删除已有草稿 | 用户确认准确目标和动作 |
| 公开发布 | 用户明确要求公开发布；草稿授权不包含此动作 |
| 预约、重复或跨账号发布 | 分别核对时间、目标和授权 |

公开发布按钮可能同时提交审核、群发或通知订阅者时，以平台实际语义为准。语义不清时停止。

## 状态证据

| 状态 | 最低证据 |
| --- | --- |
| `preflight_passed` | 平台、账号、内容、素材、授权、工具和登录均已核对 |
| `filled` | 编辑器中标题、正文和必需字段已经回读，尚未证明保存 |
| `draft_saved` | 平台明确提示成功，或草稿箱出现可识别目标 |
| `draft_verified` | 重新打开草稿后，标题、正文关键位置、素材和真实渲染符合要求 |
| `published` | 平台明确反馈发布成功，但公开页面尚未完整核验 |
| `publish_verified` | 公开地址可访问，账号、标题、正文关键位置和时间一致 |
| `unknown` | 操作后反馈不明，无法证明成功或失败 |
| `failed` | 平台明确拒绝、校验失败或前置条件不满足 |

无法打开真实草稿时可以报告 `draft_saved`，不能报告 `draft_verified`。公开按钮点击成功不能单独证明 `published`。

## 分发报告

执行过外部动作时，在发布包根目录写入 `07-分发报告.md`：

```markdown
# 分发报告

- 平台：
- 账号标识：
- 文章：
- 素材：
- 目标动作：
- 最终状态：
- 状态证据：
- 草稿或公开地址：
- 执行时间：
- 内容处理：无 / 平台格式处理及准确说明
- 失败与安全重试条件：
- 未决与人工接管项：
```

多平台任务可以分别写报告，或在同一报告中为每个平台建立独立章节。不能用一个平台的成功状态代表其他平台。
