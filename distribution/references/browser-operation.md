# 浏览器操作与恢复

## 能力发现

自动投递只允许两类后端。优先使用项目已经配置并实际暴露的固定渠道适配器：

| 平台 | 适配器 |
| --- | --- |
| 微信公众号 | `publisher_wechat` |
| 知乎 | `publisher_zhihu` |
| CSDN | `publisher_csdn` |
| 掘金 | `publisher_juejin` |

每个适配器使用独立的持久化 Chrome 会话。调用适配器时自动打开浏览器；第一次由用户完成扫码、验证码或账号选择，后续只要登录态仍有效就直接复用。平台要求重新验证时仍由用户本人完成。

固定的是渠道、会话、内容准备和分发状态机，不硬编码易变的 DOM 选择器。开始前仍要读取真实工具 schema 和当前页面。固定适配器未暴露时，只发现已批准、用户允许且 schema 明确支持独立 `user-data-dir`/持久化 Context 的 Playwright MCP。

内置 Browser、Codex Chrome 扩展、普通远程浏览器以及未声明独立 Profile 能力的其他工具不能作为自动初始化或自动发布后端，只能用于人工接管。

当前渠道适配器直接控制平台官方后台，与 WechatSync、WechatSync CLI、浏览器扩展桥接和 9527/9528 端口无关，也不把这些能力作为隐式回退。

能力至少需要支持：

- 打开官方创作后台；
- 读取可见或可访问页面结构；
- 点击、输入、上传素材和导航；
- 在用户需要登录时保持交互页面；
- 打开草稿箱、内容列表或公开页面核验结果。

缺少任何完成当前动作所必需的能力时，进入首次能力预检与初始化协议：先区分适配器、浏览器运行时、隔离会话和页面能力的缺失。只有项目已有批准初始化入口且用户明确授权时，才引导执行对应初始化；没有入口、用户拒绝或初始化失败时停止自动投递，交付人工步骤。

## 首次初始化检查

首次调用某个平台适配器，或检测到能力状态变化时，按以下顺序执行只读检查：

1. 读取适配器 schema，确认当前动作所需的打开、读取、点击、输入、上传和核验能力；
2. 确认适配器声明的浏览器运行时可启动；
3. 确认该平台的隔离持久化会话可创建、可读写且没有锁冲突；若会话不存在，生成建议目录并进入 `session_path_pending_user`，不得在用户确认前创建或复用；
4. 打开官方后台并读取实时页面，确认工具能力不是只有连接成功而没有页面操作能力。

若需要初始化运行时或适配器，只调用项目明确记录的入口，不猜测命令、不下载未知依赖、不切换未知 MCP、扩展、CLI 或桥接。若只缺隔离会话，先向用户展示建议目录、用途和平台/账号隔离范围，允许用户修改或确认；确认目录可写、未被其他平台或账号复用且不是日常浏览器 Profile 后，才创建或复用会话。之后打开可见浏览器并等待用户本人完成扫码、验证码、二次验证或账号选择；完成后重新执行以上四项检查并核对页面可见账号。

项目批准的初始化入口至少要能表达三类结果：只读 `check`（缺失层与当前能力）、用户授权后的 `bootstrap`（安装、生成或启动所需组件，可等待用户交互）和完成后的 `verify`（重新检查能力并核对页面可见账号）。入口不得返回或要求 Skill 保存 Cookie、Token、密码或验证码。

Playwright MCP 是固定适配器缺失时唯一允许的自动投递回退；必须已经配置并暴露，且通过 schema 检查独立 Profile、可见交互页面和结果核验能力，不由本 Skill 安装。

## 会话与账号

- 使用用户确认的会话目录，或项目明确声明并经用户首次确认的隔离持久化会话；
- 平台和账号之间不共享登录态；
- 不读取用户日常 Chrome、Edge 或其他浏览器 Profile；
- 不复制 Cookie、Token、密码、二维码和验证码；
- 登录后从页面可见信息核对账号，无法区分账号时停止；
- 同一平台会话一次只允许一个任务使用；被占用时不强制解锁。

首次登录、验证码、双重验证、账号选择、协议确认和风险处理必须由用户本人完成。

## 页面操作

1. 从平台官方入口进入创作后台。
2. 读取当前页面，识别新建、草稿和内容管理入口。
3. 先识别标题、正文和目标动作控件，再识别封面、图片、图注、摘要、分类和标签。
4. 不操作含义不清、不可逆或超出授权的控件。
5. 填充后回读关键字段，不以输入动作成功代替页面内容确认。
6. 保存或发布后离开编辑器，从草稿箱、内容列表或公开页面重新核验。

平台变化时重新读取页面结构。渠道 reference 只记录稳定字段和确认节点，不保存易失效选择器。

投递前用 [payload-preparation.md](payload-preparation.md) 的原生脚本生成标准载荷。浏览器步骤只消费 `manifest.json`、`body.html` 或 `body.md`，按清单中的 `alt`、`caption` 和 `role` 核对图片语义，不得在任务现场重新编写 Markdown、DOCX 或 HTML 转换脚本。

## 幂等与恢复

- 新建前查询同账号下是否已有相同标题或用户指定目标；
- 同一动作只执行一次；
- 保存、跳转或发布结果不明时，先查询目标是否已经存在；
- 确认不存在后才允许在用户授权范围内重试；
- 修正现有草稿时覆盖同一目标，不创建副本；
- 发现重复候选且无法判断时停止，由用户选择。

不要结束未知浏览器进程、删除锁文件、清空会话、重置账号或删除草稿来恢复流程。

## 安全记录

只记录平台、非敏感账号标识、阶段、时间、状态、公开地址和可复核页面证据。截图包含二维码、个人信息或后台敏感数据时不写入发布包或通用日志。
