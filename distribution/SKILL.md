# 分发

把合格的平台发布包可靠送入目标渠道，并用证据区分每一个外部状态。

## 守住边界

本 Skill 只负责：

- 平台、账号、稿件、素材和授权预检；
- 编辑器填充与平台必需的格式映射，包括长文阅读提示的弱化呈现，以及图片、替代文字和可见图注的确定性绑定；
- 保存草稿、公开发布和结果核验；
- 失败恢复、重复投递防护和人工接管说明。
- 首次投递前的渠道能力预检，以及在项目批准入口存在时引导用户完成底层能力初始化和隔离登录会话建立。

本 Skill 不负责：

- 整理底稿、传播设计和平台转写；
- 改写标题、封面、开头、正文、结尾或作者声音；
- 未经用户明确授权，静默安装或生成 Skill、MCP、插件、浏览器运行时或渠道适配器；
- 在没有项目批准入口时发明安装命令、下载地址或未知桥接方案；
- 读取、保存或回显 Cookie、Token、密码和验证码；
- 绕过验证码、风控、平台审核或账号权限；
- 从保存草稿授权推导公开发布授权。

平台因格式限制要求改变文章语义时停止，返回内容上游修正。

## 识别任务

| 用户意图 | 动作 |
| --- | --- |
| 检查能否投递 | 只执行只读预检，不填充或保存 |
| 预填平台编辑器 | 填充后回读，不保存 |
| 保存草稿、投递到草稿箱 | 保存一次并从草稿箱核验 |
| 检查现有草稿 | 打开目标草稿，核对内容和真实渲染 |
| 公开发布 | 公开动作前再次核对平台、账号和明确授权 |
| 多平台分发 | 每个平台独立执行、独立记录，不共享状态 |

没有明确平台、账号或目标动作时，先停止外部写入并请求确认。

## 核对输入与授权

执行前读取 [delivery-contract.md](references/delivery-contract.md)，确认：

```text
目标平台：
目标账号或可核对标识：
平台文章路径：
封面与正文素材：
内容验收状态：
目标动作：检查 / 预填 / 保存草稿 / 公开发布
预约时间：无 / 已确认时间
本次外部操作授权：
```

来自 `$broadcast` 发布包时，以文章 front matter 的 `platform` 识别平台，不根据文件编号猜测；同时读取 `05-验收报告.md`。未验收、仍有阻塞问题、标题正文缺失或素材不完整时不得投递。

输入也可以来自其他流程，但必须提供等价的平台与内容验收依据。

覆盖、删除已有草稿，切换账号，首次登录，预约发布和公开发布分别需要对应授权。验证码和风险确认由用户本人完成。

## 选择渠道模块

一次只读取目标平台的模块：

- 微信公众号：[platform-wechat.md](references/platform-wechat.md)
- 知乎：[platform-zhihu.md](references/platform-zhihu.md)
- CSDN：[platform-csdn.md](references/platform-csdn.md)
- 掘金：[platform-juejin.md](references/platform-juejin.md)

未列出的平台不套用相似平台规则。先交付人工投递说明；需要长期支持时新增独立渠道模块。

每个渠道模块还必须声明该平台的能力预检要求、适配器/运行时边界，以及项目批准的初始化入口；若模块没有声明初始化入口，首次缺失能力时按无入口处理并直接进入 `bootstrap_blocked`，不猜测平台专用安装方式。

## 首次能力预检与初始化

真实投递前，必须先读取 [browser-operation.md](references/browser-operation.md) 并执行能力预检。预检至少确认：

1. 目标平台的 `publisher_<platform>` 适配器或已批准的等价浏览器能力已经暴露，且 schema 支持当前动作；
2. 适配器声明的浏览器运行时能够启动；
3. 目标平台的隔离持久化会话可创建、可读写且未被其他任务占用；若尚不存在，先生成适配器建议的会话目录并等待用户确认或修改，不在确认前创建或复用；
4. 能打开官方后台并读取实时页面结构。

初始化状态独立于投递状态记录：

| 状态 | 处理 |
| --- | --- |
| `capability_unchecked` | 只读预检尚未完成，不执行外部写入 |
| `bootstrap_required` | 适配器或运行时缺失，或需要调用批准初始化入口，进入初始化引导 |
| `session_path_pending_user` | 隔离会话目录缺失，已展示建议目录，等待用户确认或修改 |
| `bootstrap_waiting_user` | 已打开可见浏览器，等待用户登录、扫码、验证码、二次验证或账号选择 |
| `capability_ready` | 能力、会话和页面均已核验，进入投递流程 |
| `bootstrap_blocked` | 没有批准入口、用户拒绝、初始化失败或账号无法核对，停止自动投递 |

初始化引导规则：

- 缺少适配器或浏览器运行时，只能调用项目已有且明确记录的初始化入口；真正安装、生成或修改外部环境前，必须取得用户明确授权；
- 没有批准入口时，不猜命令、不下载未知包、不切换未知 MCP、扩展、CLI 或 WebSocket 桥接；
- 缺少隔离会话时，向用户展示适配器建议的会话目录、用途和隔离范围，允许用户修改或确认；确认后的目录必须可写、未被其他平台/账号复用且不是用户日常浏览器 Profile，之后才创建或复用，不自动移动或复制已有会话；
- 登录、验证码、二次验证和风险确认由用户本人完成；
- 初始化完成后必须重新执行完整预检，并从页面可见信息核对目标账号；
- 初始化被拒绝或失败时保留本地发布包，输出缺失层和人工接管步骤，不继续填充、保存或公开发布。

Playwright MCP 不是固定依赖。它只有在已由项目配置并向当前环境暴露、且满足实时页面操作要求时，才可作为等价浏览器能力参与预检。

## 发现浏览器能力

真实投递时读取 [browser-operation.md](references/browser-operation.md)。本节只负责能力路由；首次初始化遵守上一节协议。

优先使用当前项目已经配置的 `publisher_<platform>` 渠道适配器。每个平台绑定独立的持久化浏览器会话：首次登录由用户扫码或验证，登录态仍有效时后续任务直接复用。已配置适配器不存在时，才发现当前环境已经暴露、用户允许且能够读取实时页面的其他浏览器控制能力。

当前流程不调用 WechatSync，也不把 CLI、扩展或 WebSocket 桥接作为隐式回退。能力缺失且没有批准初始化入口时，保留完整本地发布包并返回人工操作边界。

平台和账号使用用户指定或项目明确声明的隔离持久化会话。不得读取用户日常浏览器 Profile；发现会话被其他任务占用时停止，不结束进程或删除锁文件。

## 执行单平台分发

1. 核对平台、账号、文章、素材、验收结论、目标动作和授权。
2. 加载唯一目标平台渠道模块。
3. 读取 [payload-preparation.md](references/payload-preparation.md)，用当前系统原生脚本验证图片语义、识别标准长文阅读提示并生成平台化投递载荷；禁止为单次投递另写转换脚本。
4. 执行“首次能力预检与初始化”；只有 `capability_ready` 才能继续，初始化未就绪时停止外部写入。
5. 打开官方创作后台并读取实时页面结构。
6. 检查登录和账号。需要扫码、验证码、账号选择或风险确认时等待用户本人完成。
7. 查询草稿箱或内容列表，检查同一标题和目标内容是否已经存在。
8. 打开新建入口或用户指定的既有草稿，识别当前页面字段后再填充。
9. 回读标题、正文开头、封面、图片、图注及平台必需字段，记录未识别项。
10. 只执行已授权动作：预填不保存；草稿只保存一次；公开发布前再次核对授权。
11. 从草稿箱、草稿详情或公开页面重新打开目标，核验真实状态和渲染。
12. 按 [delivery-contract.md](references/delivery-contract.md) 写入 `07-分发报告.md`，同时记录初始化状态。
13. 按 [tracking-contract.md](references/tracking-contract.md) 在发布包根目录更新 `08-渠道追踪.md`；草稿只登记安全定位信息，公开发布必须登记规范公开链接。

页面变化时重新读取当前页面。字段含义不明、出现多个同名账号或进入风控时停止，不靠猜测点击。

## 处理结果与恢复

只报告已经取得证据的最高状态：

```text
preflight_passed
filled
draft_saved
draft_verified
published
publish_verified
unknown
failed
```

调用成功、页面打开、字段已填或按钮已点击都不能证明平台已经保存或发布。

超时、断连或跳转异常后先查询草稿箱、内容列表或公开页面。结果仍不明确时标记 `unknown` 并停止；不得为了获得确定结果再次创建相同草稿或重复发布。

真实草稿排版不合格时保留现有草稿，把内容或渲染问题返回上游；获得覆盖授权后只修改同一草稿。

## 输出

没有执行外部写入时，直接报告预检结果、缺失条件和人工接管步骤。

执行过预填、草稿或发布动作时，在发布包根目录生成或更新两类文件：

- `07-分发报告.md` 记录本次投递过程、状态证据、异常和人工接管项；
- `08-渠道追踪.md` 记录这篇文章在各平台形成的当前渠道对象，作为后续数据采集入口。

分发报告记录：

- 平台和非敏感账号标识；
- 文章、素材和目标动作；
- 初始化状态：`capability_ready` / `bootstrap_blocked` / 不适用；
- 最终状态及其证据；
- 草稿或公开地址；
- 内容是否发生平台格式处理；
- 失败阶段、是否可能已写入和安全重试条件；
- 未决与人工接管项。

渠道追踪表遵守 [tracking-contract.md](references/tracking-contract.md)。草稿没有公开文章链接，不得把后台编辑地址写成公开链接；后台地址包含登录态、Token 或临时参数时不得保存。取得 `publish_verified` 状态时，规范公开链接是必填证据。

报告不得包含凭据、验证码、二维码、浏览器 Profile 路径或完整个人账号信息。

## 验收

交付前检查：

1. 平台、账号、稿件和动作是否唯一明确。
2. 内容和素材是否已经完成平台验收。
3. 是否只读取了一个目标平台模块。
4. 是否先完成能力预检；适配器、运行时、隔离会话和页面能力是否按实时状态核对。
5. 是否没有读取日常浏览器资料或记录凭据。
6. 是否没有改写文章语义、传播结构和作者声音。
7. 保存草稿是否只执行一次，且没有触发公开动作。
8. 公开发布是否存在本次明确授权和公开页面证据。
9. 结果未知时是否先查询而没有盲目重试。
10. 报告状态是否与可见证据一致。
11. 是否使用原生内容准备脚本，且没有遗留本轮临时转换脚本或载荷。
12. 是否在实际发布包目录更新渠道追踪表，并正确区分草稿定位信息和公开链接。
13. `publish_verified` 是否存在可公开访问且不含敏感参数的规范链接。
14. 每张信息图的替代文字和图注是否分别保留，图注是否只出现一次、紧邻对应图片且没有降级成普通正文。
15. 标准长文阅读提示是否只出现一次，并按目标平台弱化呈现；样式被编辑器剥离时是否仍保留提示语义并记录降级。
16. 初始化失败、被拒绝或没有批准入口时，是否停止外部写入并给出人工接管步骤。
17. 首次使用是否展示建议会话目录并等待用户修改或确认，且未将会话路径写入分发报告。

## 行为验收

发布后在全新会话中使用 [behavior-cases.md](references/behavior-cases.md) 验证触发、非触发、权限边界和失败处理。案例只定义预期，不授权登录、保存草稿或公开发布。
